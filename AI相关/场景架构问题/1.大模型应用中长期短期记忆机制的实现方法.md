## 大模型应用中长期短期记忆机制的实现方法

### 1. 为什么大模型应用需要记忆

LLM 本身是无状态的——每次调用只看本次输入的上下文。真实应用要"记住"用户偏好、历史事实、过往交互，必须在外部构建记忆机制。

| 记忆类型 | 时间跨度 | 存储位置 | 作用 |
| --- | --- | --- | --- |
| 短期记忆 | 当前会话内 | 上下文窗口 / 会话缓存 | 维持多轮对话连贯 |
| 长期记忆 | 跨会话、持久 | 外部存储（向量库/DB/图） | 积累用户偏好、事实、经验 |

> 深入的差异与存储检索方式，见 agent 目录的《22.Agent系统中短期记忆与长期记忆的差异及存储检索方式》与《12.LLM Agent长期记忆能力的实现方法》。

### 2. 短期记忆实现

短期记忆 = 把当前会话的历史消息留在上下文窗口内。

| 实现方式 | 说明 | 适用 |
| --- | --- | --- |
| 全量拼接 | 把所有历史消息原样拼进 Prompt | 会话短、token 充裕 |
| 滑动窗口 | 只保留最近 N 轮 | 通用默认 |
| 摘要压缩 | 旧消息摘要 + 近期原文 | 长会话 |
| Token 预算裁剪 | 按 token 预算动态裁剪 | 精确控制成本 |

```
当前上下文 = System Prompt + [历史摘要] + [最近 N 轮原文] + 用户当前输入
```

要点：短期的瓶颈是上下文窗口，超限必须裁剪/压缩（见 [[7.超长模型上下文窗口限制的工程解决方案]]）。

### 3. 长期记忆实现

长期记忆 = 把需要跨会话保留的信息外置存储，按需检索注入。

| 存储方式 | 检索方式 | 适合记忆类型 |
| --- | --- | --- |
| 向量库 | 语义相似度检索 | 事件、对话片段、经验 |
| 键值数据库 | 精确 key 查询 | 用户偏好、固定事实 |
| 图数据库 | 关系/多跳检索 | 实体关系、知识图谱 |
| 关系数据库 | 结构化查询 | 订单、工单等业务数据 |

#### 记忆类型

| 类型 | 内容 | 示例 |
| --- | --- | --- |
| 事件记忆 | 发生过的交互 | "用户上周问过退货政策" |
| 事实记忆 | 持久事实 | "用户姓名/地址" |
| 偏好记忆 | 用户习惯 | "用户偏好简洁回答" |
| 经验记忆 | 总结的规律 | "此类问题应走某流程" |

### 4. 记忆机制全流程

```
① 写入：从对话中抽取值得记的内容 → 编码（embedding/结构化）→ 存入对应存储
② 存储：按类型分库（向量/键值/图）
③ 检索：新 query 时，按语义/精确/关系检索相关记忆
④ 注入：把检索到的记忆拼进当前上下文
⑤ 管理：遗忘（过期删除）/压缩（摘要合并）/去重/重要性衰减
```

| 环节 | 关键决策 |
| --- | --- |
| 写入 | 记什么、不记什么（避免噪声） |
| 检索 | 召回多少、如何排序 |
| 注入 | 占多少 token 预算、放在上下文哪个位置 |
| 管理 | 何时遗忘/压缩，避免记忆库膨胀 |

### 5. 工程实现要点

| 要点 | 说明 |
| --- | --- |
| 记忆抽取 | 用 LLM 从对话抽取结构化记忆，而非全量存 |
| 重要性评分 | 给记忆打分，低分遗忘，高分保留 |
| 检索精度 | 召回不准会注入噪声，需 Rerank |
| 隐私合规 | 敏感信息脱敏/加密存储，遵守数据合规 |
| 记忆隔离 | 多用户记忆按 user_id 隔离，防串 |
| Token 预算 | 记忆注入不挤占当前任务上下文 |

### 6. 一句话总结

大模型记忆 = **短期靠上下文窗口内拼接/滑动/摘要维持会话连贯，长期靠外部存储（向量库/键值/图）+ 检索注入积累跨会话信息**，核心是"写入-存储-检索-注入-管理"五步闭环，瓶颈分别在短期窗口上限和长期检索精度。
