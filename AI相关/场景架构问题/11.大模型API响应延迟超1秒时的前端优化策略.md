## 大模型 API 响应延迟超 1 秒时的前端优化策略

大模型推理天生慢——首 token 往往要 1~3 秒，完整回答可能 10 秒以上。前端若按传统"请求→等待→一次性渲染"处理，用户体验会非常差。核心对策是：**把"等"变成"看"，用感知性能对冲实际延迟**。长上下文带来的延迟问题见 [[7.超长模型上下文窗口限制的工程解决方案]]。

### 1. 延迟从哪来

| 来源 | 说明 | 典型耗时 |
| --- | --- | --- |
| 模型推理慢 | 自回归逐 token 生成，长输出累积慢 | 占大头 |
| 首 token 慢 | prefill 阶段处理长 prompt | 1~3s |
| 排队 | 高峰期请求排队等 GPU | 不定 |
| 网络往返 | 到模型服务器的 RTT + 首字节 | 0.2~1s |
| 上下文长 | prompt 越长，prefill/每步越慢 | 随长度增长 |

### 2. 前端优化策略

| 策略 | 做法 | 收益 |
| --- | --- | --- |
| 流式输出（SSE） | 用 Server-Sent Events 逐 token 推送，打字机效果 | 首字节即可见，感知延迟骤降 |
| 骨架屏/占位 | 等待时渲染消息气泡骨架 + 三个跳动点 | 缓解空白焦虑 |
| 乐观更新 | 用户提问后立即上屏，不等回复 | 交互即时感 |
| 分块渐进渲染 | 流式内容边到边渲染（支持 Markdown 增量解析） | 早看到早阅读 |
| 请求取消与重试 | AbortController 取消旧请求；指数退避重试 | 避免堆积、抗抖动 |
| 降级兜底 | 超时回退缓存答案/规则答案/提示重试 | 不白屏 |
| 缓存 | 本地缓存高频问答 + 语义缓存相似命中的复用 | 命中即返，0 延迟 |
| 进度指示与预期管理 | "正在思考…""已检索 N 篇资料…" 状态文案 | 让等待可预期 |
| 并发与预取 | 多路请求并行；预测下一步预取 | 缩短关键路径 |
| 超时熔断 | 设超时阈值，超时提示而非死等 | 保护体验底线 |

### 3. 用户体验策略：感知性能 > 实际性能

| 原则 | 落地 |
| --- | --- |
| 让首字节尽快可见 | 流式 + 骨架屏，把"首字节时间"当核心指标 |
| 让等待有信息 | 进度文案/检索状态，避免无反馈空等 |
| 让输出可中断 | 用户可随时停止生成，节省时间与成本 |
| 让重复零等待 | 缓存命中直接出结果 |
| 让失败不阻塞 | 降级 + 重试，永远不让用户对着空白 |

### 4. 代码示例：SSE 流式接收

```javascript
// 前端用 fetch + ReadableStream 接收 SSE 流式响应
async function streamChat(query, onToken, onDone) {
  const ctrl = new AbortController();
  const res = await fetch('/api/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ query, stream: true }),
    signal: ctrl.signal,
  });

  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    // 解析 SSE: data: {...}\n\n
    const lines = buffer.split('\n\n');
    buffer = lines.pop(); // 保留不完整段
    for (const line of lines) {
      if (!line.startsWith('data:')) continue;
      const json = JSON.parse(line.slice(5).trim());
      if (json.delta) onToken(json.delta);   // 逐 token 渲染
    }
  }
  onDone();
  return ctrl; // 返回 controller 供用户中断
}

// 使用：打字机渲染 + 可中断
const ctrl = streamChat(
  '解释一下 RAG',
  tok => appendToBubble(tok),          // 每个 token 追加渲染
  () => setBubbleStatus('done')
);
// 用户点"停止"
stopBtn.onclick = () => ctrl.abort();
```

### 5. 一句话总结

大模型 API 延迟高时，前端的核心是**用流式输出（SSE）把"等完整结果"变成"看逐字生成"**，配合骨架屏、进度文案、缓存、降级与可中断，用感知性能对冲实际延迟——首字节越早可见，体验越好。
