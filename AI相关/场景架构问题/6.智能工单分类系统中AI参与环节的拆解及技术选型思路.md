## 智能工单分类系统中 AI 参与环节的拆解及技术选型思路

### 1. 场景与痛点

工单分类：把用户提交的工单（咨询/投诉/故障/报修）自动归到正确类目，再路由给对应处理团队。痛点决定了为什么必须上 AI：

| 痛点 | 说明 |
| --- | --- |
| 类目多 | 几百上千个类目，人工记不全、易错分 |
| 长尾严重 | 大量低频类目样本少，传统分类器覆盖差 |
| 人工慢 | 7x24 人工分拣成本高、时效差 |
| 表述杂 | 同一意图多种说法，规则难穷举 |
| 类目变动 | 业务调整类目频繁增删，模型需快速跟上 |

### 2. AI 参与环节拆解（端到端链路）

```
工单接入 → 文本预处理 → 分类 → 置信度评估与兜底 → 路由派单 → 反馈学习闭环
                                                              ↑（人工修正回流）
```

| 环节 | 动作 | 关键技术 |
| --- | --- | --- |
| 工单接入 | 多渠道（客服/APP/邮件/工单系统）汇聚成统一格式 | 接入层、会话归并 |
| 文本预处理 | 清洗/纠错/抽关键实体/补元数据（来源/时间/用户画像） | NLP 预处理、实体抽取 |
| 分类 | 判定主类目 + 子类目 + 优先级 | LLM few-shot / 微调小模型 / 规则 |
| 置信度评估与兜底 | 给分类结果打置信度，低置信转人工 | 阈值过滤、人工兜底 |
| 路由派单 | 按类目+优先级+技能组+负载派单 | 规则引擎、调度 |
| 反馈学习闭环 | 人工修正结果回流，定期重训/补示例 | 数据飞轮、评测 |

### 3. 技术选型思路：分类方案对比

| 方案 | 准确率 | 成本 | 延迟 | 可维护性 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| 传统规则（关键词/正则） | 覆盖内高、覆盖外低 | 低 | 极低 | 规则膨胀后差 | 类目少且稳定 |
| 微调小模型（BERT/TextCNN） | 高（样本足时） | 中（训练+部署） | 低 | 需重训 | 样本足、类目固定 |
| LLM 零样本 | 中 | 高（token） | 高 | 高（改 prompt） | 冷启动/类目频繁变动 |
| LLM few-shot | 高 | 高 | 高 | 高 | 类目多、有示例 |
| 向量检索辅助 | — | 低 | 低 | 中 | 长尾/历史相似工单复用 |

**选型建议——分层组合**：

| 层 | 方案 | 处理对象 |
| --- | --- | --- |
| 第一层 | 规则 | 确定性场景（含特定关键词/工单号格式） |
| 第二层 | 微调小模型 | 高频类目（样本足、要快） |
| 第三层 | LLM few-shot | 长尾/新类目（泛化、冷启动） |
| 辅助 | 向量检索 | 召回历史相似工单作示例或复用其分类 |
| 兜底 | 人工 | 低置信/高敏感 |

> 不要单一押注：高频走小模型求快准，长尾走 LLM 求泛化，规则兜底确定性，向量检索补长尾——各取所长。

### 4. 向量检索辅助历史相似工单

把历史已分类工单向量化入向量库；新工单先检索 top-k 相似历史工单：
- **作为 LLM few-shot 示例**：把相似工单+其类目塞进 prompt，提升分类一致性（动态示例比固定示例更准）。
- **直接复用**：高度相似且同类的，直接继承历史分类，跳过模型调用。

### 5. 反馈学习闭环（关键）

分类系统不是一次建成，靠闭环持续优化：

```
模型分类 → 人工复核修正 → 修正结果入库 → 定期重训小模型 / 补充 LLM 示例库 / 挖掘新长尾类目
```

| 闭环动作 | 价值 |
| --- | --- |
| 人工修正回流 | 持续标注数据，喂小模型重训 |
| 错分聚类分析 | 发现易混类目，补规则/prompt 示例 |
| 未命中收集 | 沉淀新长尾类目 |

### 6. 一句话总结

智能工单分类 = **"接入→预处理→分层分类（规则+小模型+LLM few-shot+向量检索）→置信度兜底→路由派单→反馈闭环"**；选型不押单点，高频走小模型求快准、长尾走 LLM 求泛化、规则兜底、向量检索补长尾、人工兜底兜敏感，靠反馈闭环持续进化。长尾知识库构建见 [[10.智能客服系统中知识库构建解决长尾问题的具体实现步骤]]。
