## LangChain 中多路召回结果动态权重分配的实现方法

混合检索时，向量、BM25、多 query 各路召回强弱随问题类型变化——固定权重难以适配所有 query。动态权重分配就是**根据当前 query 的特征，自适应调整各路召回的融合权重**，让"该信向量的信向量、该信关键词的信关键词"。

### 1. 多路召回场景与固定权重的局限

| 召回路 | 擅长 | 弱项 |
| --- | --- | --- |
| 向量检索 | 语义相似、同义改写 | 精确词/数字/专有名词 |
| BM25 关键词 | 精确词命中、代码/型号 | 不懂同义 |
| 多 query 召回 | 多角度覆盖 | 开销大、可能跑偏 |

| 固定权重的局限 | 说明 |
| --- | --- |
| 一刀切难适配 | 精确查询该重 BM25，语义查询该重向量，固定值两头不讨好 |
| 忽略置信度 | 某路这次召回质量差，固定权重仍给它高分 |
| query 类型未区分 | 问"代码 bug"和问"大模型概念"最优权重完全不同 |

> 混合检索的基础定义与融合策略见 rag 目录的《03.混合检索的定义及在大模型应用中的核心作用》，LangChain 落地见《52.RAG混合检索的定义及向量检索与关键词检索的结合实现》，查询扩展见《06.查询扩展的定义及在RAG中的应用价值》。

### 2. 动态权重分配思路

| 思路 | 做法 | 适用 |
| --- | --- | --- |
| 按 query 类型路由权重 | 先分类 query（精确型/语义型/代码型），每类预设权重 | 简单有效，工程首选 |
| 按各路置信度自适应 | 用各路召回分数分布/Top1 分数衡量该路置信度，高置信路加权 | 无需分类器 |
| 学习排序（LTR） | 用标注数据训练一个打分模型，融合多路特征 | 精度最高，需标注 |
| RRF 自适应 | RRF 本身隐式按排名融合，可对不同路用不同 k | 免归一化 |
| LLM 打分 | 让 LLM 对各路结果打相关性分再融合 | 零样本，贵且慢 |

### 3. LangChain 实现方法

核心组合：**query 分类前置路由 + EnsembleRetriever 动态 weights + 检索后 Rerank 精排**。

| 环节 | LangChain 组件/做法 |
| --- | --- |
| query 分类 | LLM 或规则分类器，输出 query 类型 |
| 动态权重 | 按类型查表得到 weights，传给 EnsembleRetriever |
| 多路召回 | EnsembleRetriever 组合向量 + BM25（+多 query） |
| 精排兜底 | 检索后接 Reranker（bge-reranker 等）统一排序，修正权重偏差 |

```python
from langchain.retrievers import EnsembleRetriever

# 按 query 类型决定各路权重
WEIGHTS_BY_TYPE = {
    "exact":    [0.3, 0.7],   # 精确型：BM25 主导
    "semantic": [0.8, 0.2],   # 语义型：向量主导
    "code":     [0.2, 0.8],   # 代码型：BM25 主导（标识符精确匹配）
    "default":  [0.6, 0.4],   # 默认：向量略重
}

def classify_query(q: str) -> str:
    # 简单规则示例；生产用 LLM 分类器
    if any(c in q for c in ["代码", "函数", "报错", "API"]) or "/" in q:
        return "code"
    if any(c in q for c in ["价格", "编号", "型号"]) or q.replace(" ", "").isdigit():
        return "exact"
    return "semantic"

def dynamic_hybrid_retrieve(q, vector_retriever, bm25_retriever, k=8):
    qtype = classify_query(q)
    weights = WEIGHTS_BY_TYPE[qtype]
    hybrid = EnsembleRetriever(
        retrievers=[vector_retriever, bm25_retriever],
        weights=weights,
    )
    docs = hybrid.invoke(q)[:k]
    # 可选：接 Reranker 精排，进一步修正权重偏差
    return docs, qtype, weights
```

### 4. 进阶：按置信度自适应

不分类，直接看各路召回质量动态调权：

| 信号 | 用法 |
| --- | --- |
| 各路 Top1 相似度分数 | 分数高的一路加权 |
| 各路分数方差 | 方差大（区分度强）的一路更可信 |
| 召回重合度 | 多路都命中的文档更可能相关，加权 |

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| Rerank 兜底 | 动态权重仍可能偏，检索后用 Cross-Encoder Rerank 统一精排最稳 |
| 评测驱动 | 用 recall@k/MRR 在标注集上调各类权重，别拍脑袋 |
| 分类器要轻 | query 分类前置会增加延迟，用规则或小模型，别用大模型 |
| 兜底默认权重 | 分类不确定时回落默认权重，避免极端 |

### 6. 一句话总结

LangChain 多路召回动态权重 = **先按 query 类型（精确/语义/代码）路由出权重 → 传给 EnsembleRetriever 动态融合向量与 BM25 → 再用 Reranker 精排兜底**，让"精确查询信关键词、语义查询信向量"，比固定权重更能适配多变的查询。
