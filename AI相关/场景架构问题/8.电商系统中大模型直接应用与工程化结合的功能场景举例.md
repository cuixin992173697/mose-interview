## 电商系统中大模型直接应用与工程化结合的功能场景举例

### 1. 直接应用 vs 工程化结合的边界

| 维度 | 直接应用（开箱用 LLM） | 工程化结合（LLM+系统+数据） |
| --- | --- | --- |
| 依赖 | 仅调 LLM API | LLM + 检索/数据库/业务系统/审核流 |
| 数据 | 无/少量 prompt | 接入商品/订单/用户/知识库 |
| 准确性要求 | 容忍泛化 | 要求精准、可溯源、可控 |
| 典型 | 文案生成、摘要 | 导购、推荐解释、风控 |

> 简单说：**直接应用是"LLM 单兵"，工程化结合是"LLM 进系统当大脑"**。高价值高风险场景必须工程化。

### 2. 直接应用场景

| 场景 | 怎么用 | 要点 |
| --- | --- | --- |
| 商品文案生成 | 输入商品属性→生成标题/详情/卖点 | few-shot 控风格，人工抽审 |
| 评论摘要 | 批量评论→摘要+情感 | 长文本压缩 |
| 客服问答 | LLM 直接答常见问题 | 简单 FAQ，复杂转 RAG |
| 智能搜索改写 | 用户口语 query→改写/扩词 | 提升搜索召回 |

### 3. 工程化结合场景

| 场景 | 架构 | 技术要点 |
| --- | --- | --- |
| 个性化推荐解释 | 推荐系统出结果→LLM 生成自然语言解释 | 推荐理由可解释，提升信任 |
| 导购对话 | RAG（商品库检索）+ LLM + 对话记忆 | 多轮意图理解、商品属性问答，见 rag 目录《04.详解RAG的完整工作流程》 |
| 商品图谱 | LLM 抽实体关系建图谱→辅助搜索/推荐 | 知识图谱构建 |
| 风险审核 | LLM 判别违禁/欺诈文案+规则+人工 | 幻觉敏感，需兜底 |
| 智能营销 | LLM 生成千人千面素材+AB 测试 | 生成+投放闭环 |
| AI 选品/补货 | LLM 分析趋势+销量数据→建议 | 结合 BI 数据 |

### 4. 场景对照（直接 vs 工程化）

| 场景 | 类型 | 为什么 |
| --- | --- | --- |
| 商品文案 | 直接 | 容忍泛化、要创意 |
| 导购对话 | 工程化 | 必须基于真实商品库，不能编 |
| 风险审核 | 工程化 | 高风险需确定性+可追溯 |
| 评论摘要 | 直接 | 信息压缩，容错高 |
| 推荐解释 | 工程化 | 要对接推荐系统数据 |

### 5. 工程化结合的通用架构

```
用户输入 → 意图识别/路由
        → RAG 检索商品/知识库（精准供给）
        → LLM 推理（结合业务数据）
        → 后处理校验（幻觉/合规/库存校验）
        → 业务系统联动（下单/推荐/派单）
        → 审核与监控闭环
```

### 6. 一句话总结

电商大模型应用分两档：**直接应用（文案/摘要/搜索改写，LLM 单兵）适合容错高的生成场景；工程化结合（导购/推荐解释/风控/选品，LLM+检索+业务系统+审核）适合需精准可控的高价值场景**——判断标准是"容不容幻觉、要不要对接真实数据"。
