## LangChain 中 Agent 的定义及与 Chain 的差异

> 本篇聚焦"Agent 定义 + 与 Chain 的差异对比"。Chain 与 Agent 的定义和应用场景举例见 [[46.LangChain中Chain与Agent的定义及应用场景举例]]，Agent 执行流程见 [[48.LangChain的Agent执行流程解析]]。

### 1. Agent 的定义

Agent = 以 **LLM 为决策核心** + 工具 + 循环推理的执行单元。它不预设执行路径，而是由 LLM 在每一轮根据"当前状态 + 历史 Observation"动态决定下一步：调用哪个工具、传什么参数、还是直接给出最终答案。

```
输入
 → LLM 推理：该做什么？（Thought）
 → 选择工具 + 生成参数（Action）
 → 执行工具，拿到结果（Observation）
 → 回填上下文，再推理……
 → 信息足够，输出 Final Answer
```

核心三要素：

| 要素 | 作用 |
| --- | --- |
| LLM（大脑） | 推理决策，决定下一步 |
| Tools（工具） | 感知与行动的执行入口 |
| 循环（Thought-Action-Observation） | 多步推进直到完成 |

### 2. 与 Chain 的差异

| 维度 | Chain | Agent |
| --- | --- | --- |
| 决策主体 | 预定义代码逻辑（无自主决策） | LLM（自主推理决策） |
| 流程 | 固定序列，写代码时确定 | 动态，LLM 实时决定 |
| 确定性 | 确定性（同输入同路径） | 非确定性（同输入可能不同路径） |
| 可控性 | 高（路径可预测） | 低（靠 max_steps/终止条件兜底） |
| 灵活性 | 低（改流程要改代码） | 高（适配新任务/新工具） |
| 步数 | 固定 | 可变（循环直到完成） |
| 成本/延迟 | 低且稳定 | 高且波动（多轮 LLM 调用） |
| 错误处理 | 需显式编码 | LLM 可见错误后自主重试 |
| 适用任务 | 固定、可枚举的流程 | 开放、需动态决策的任务 |

一句话：**Chain 是"我告诉你怎么走"，Agent 是"你自己看着走"。**

### 3. 何时用 Agent，何时用 Chain

| 判断条件 | 选择 |
| --- | --- |
| 步骤写代码时就能全部确定 | Chain |
| 需要根据中间结果改变后续路径 | Agent |
| 流程固定、只需在某步调用 LLM | Chain |
| 需要多工具组合、且用哪个由情况定 | Agent |
| 对延迟/成本/稳定性要求高 | Chain |
| 任务开放、目标不可枚举 | Agent |
| 既要稳定又要局部灵活 | Chain 为主，关键节点嵌 Agent |

> 经验：**先用 Chain，Chain 表达不了的复杂度再上 Agent**。Agent 的灵活性是用成本、延迟和不确定性换来的，不要为不需要自主性的任务上 Agent。

### 4. 演进关系

LangChain 中二者并非割裂：

| 阶段 | 说明 |
| --- | --- |
| 早期 Chain | 固定管道，LLM 只在节点内被调用 |
| Agent（AgentExecutor） | 引入 LLM 决策循环，但与 Chain 是两套机制 |
| LangGraph | 用**图（状态机）**统一表达：Chain 是确定的图，Agent 是含 LLM 决策节点的图，二者在同一框架下融合 |

即 LangGraph 之后，"Chain vs Agent"更多是**图里节点是否含 LLM 自主决策**的区别，而非两套独立体系。

### 5. 一句话总结

Agent = **LLM 为决策核心 + 工具 + Thought-Action-Observation 循环**，与 Chain 的本质差异是"动态决策 vs 固定序列、非确定 vs 确定、灵活高成本 vs 稳定低成本"；判断标准是"路径能否事先确定"——能确定用 Chain，需 LLM 边走边看用 Agent。Agent 定义与作用见 [[4.LangChain Agent的定义及核心作用]]，场景举例见 [[46.LangChain中Chain与Agent的定义及应用场景举例]]，执行流程见 [[48.LangChain的Agent执行流程解析]]。
