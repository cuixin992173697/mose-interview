## LLM Agent 长期记忆能力的实现方法

### 1. 为什么需要长期记忆

LLM 上下文窗口有限，单靠上下文记不住所有事：

| 痛点 | 说明 |
| --- | --- |
| 上下文窗口有限 | 长对话/大量工具结果塞不下 |
| 跨会话失忆 | 新会话开始，上次经验全丢 |
| 重复劳动 | 同类问题反复推理，不复用经验 |
| 个性化缺失 | 记不住用户偏好 |

长期记忆 = 把"超出窗口的"和"跨会话的"信息外置存储，按需检索注入上下文。

### 2. 记忆类型

| 类型 | 内容 | 示例 |
| --- | --- | --- |
| 事件记忆（Episodic） | 具体发生过的事 | "上次用户问了X，我答了Y" |
| 语义记忆（Semantic） | 事实/知识 | "用户的公司是A，用B技术栈" |
| 程序记忆（Procedural） | 技能/经验规则 | "处理PDF表格要先结构化" |
| 偏好记忆 | 用户习惯 | "用户喜欢简洁回答" |

### 3. 存储后端选型

| 存储 | 适合 | 检索方式 |
| --- | --- | --- |
| 向量库 | 事件/语义记忆，模糊语义检索 | 向量相似度 |
| 键值库（KV/Redis） | 用户偏好、明确 key 的状态 | 精确 key 查 |
| 图数据库 | 关系型记忆（实体-关系） | 图遍历 |
| 关系数据库 | 结构化历史记录 | SQL |

### 4. 写入与检索注入流程

```
对话进行中
  → 提取值得记住的信息（事件/偏好/经验）
  → 向量化 + 元数据（时间/类型/重要性）写入记忆库
  → （后续轮次）当前 query 向量化
  → 检索相关记忆 top-k
  → 注入上下文 → LLM 据此生成
```

### 5. 检索方式

| 方式 | 说明 |
| --- | --- |
| 向量相似 | query 向量与记忆向量比相似度，最常用 |
| 时间衰减 | 越近的记忆权重越高 |
| 重要性评分 | 给记忆打重要性分，重要的优先召回（如 Generative Agents） |
| 混合 | 向量 + 时间 + 重要性综合打分 |

### 6. 记忆管理

记忆无限增长会爆，需管理：

| 操作 | 说明 |
| --- | --- |
| 遗忘 | 低重要性/久未访问的记忆降权或删除 |
| 压缩 | 多条相似记忆合并/摘要 |
| 更新 | 旧信息被新信息覆盖 |
| 分层 | 热记忆（近期）/冷记忆（归档） |

### 7. 短期 vs 长期

| 维度 | 短期记忆 | 长期记忆 |
| --- | --- | --- |
| 存储 | LLM 上下文窗口 | 外部存储 |
| 时长 | 单次会话 | 跨会话持久 |
| 内容 | 当前对话/最近结果 | 历史/经验/偏好 |

差异与存储检索详见 [[22.Agent系统中短期记忆与长期记忆的差异及存储检索方式]]。

### 8. 一句话总结

Agent 长期记忆 = **外部存储（向量库/KV/图）+ 记忆分类（事件/语义/程序/偏好）+ 写入检索注入流程 + 检索打分（相似/时间/重要性）+ 管理策略（遗忘/压缩/更新）**，让 Agent 突破上下文窗口、跨会话积累经验并个性化。
