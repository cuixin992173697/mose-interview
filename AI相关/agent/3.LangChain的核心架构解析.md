## LangChain 的核心架构解析

### 1. 架构演进总览

LangChain 编排骨架经历四代演进：

| 代际 | 形态 | 特点 |
| --- | --- | --- |
| ① Chain（旧） | 继承式类组合（LLMChain 等） | 封装死、难定制、难流式 |
| ② LCEL | 声明式管道，`|` 管道符 | 可组合、原生流式 / 异步 / 批处理 |
| ③ Runnable 协议 | 统一接口 | 所有组件实现 invoke / stream / batch |
| ④ LangGraph | 图编排 + 状态机 | 支持循环、分支、多 Agent |

演进主线：从"固定类"走向"声明式可组合"，再走向"图状态机"以支撑复杂 Agent。

### 2. Runnable 协议（统一底座）

所有 LCEL 组件都实现 Runnable 协议，统一四类调用：

| 方法 | 说明 |
| --- | --- |
| invoke | 单次同步调用 |
| stream | 流式逐 token 返回 |
| batch | 批量并行调用 |
| ainvoke / astream / abatch | 异步版本 |

这意味着 `prompt | model | parser` 任意组件都自动支持流式 / 异步 / 批量，无需额外编码。

### 3. LCEL（LangChain Expression Language）

用 `|` 把 Runnable 串成管道，类似 Unix 管道：

```python
chain = prompt | model | StrOutputParser()
chain.invoke({"topic": "RAG"})
```

#### RunnableSequence / RunnableParallel

- 顺序：`a | b | c` → RunnableSequence
- 并行：`RunnableParallel({"a": branch1, "b": branch2})` → 同时跑多路再合并

```python
from langchain_core.runnables import RunnableParallel, RunnablePassthrough
chain = RunnableParallel({"ctx": retriever, "q": RunnablePassthrough()}) | prompt | model
```

### 4. LCEL vs 传统 Chain

| 维度 | 传统 Chain（LLMChain） | LCEL |
| --- | --- | --- |
| 写法 | 类实例化 + 固定参数 | `|` 管道声明 |
| 流式 | 不原生支持 | 原生 stream |
| 异步 / 批量 | 需手写 | 自动支持 |
| 可组合性 | 受限 | 自由组合 / 并行 |
| 定制 | 要继承改类 | 任意拼接 |
| 现状 | 逐步弃用 | 推荐方式 |

### 5. LangGraph：图编排与状态机

LCEL 是线性管道，难表达"循环、条件跳转、多 Agent 协作"。LangGraph 把流程建模为有向图：

| 概念 | 说明 |
| --- | --- |
| State | 跨节点共享的状态对象 |
| Node | 节点，对 state 做变换 |
| Edge | 边，可条件跳转 / 循环 |
| Graph | StateGraph 组装，编译后可 invoke / stream |

```python
from langgraph.graph import StateGraph, END
graph = StateGraph(dict)
graph.add_node("retrieve", retrieve_fn)
graph.add_node("generate", generate_fn)
graph.set_entry_point("retrieve")
graph.add_conditional_edges("generate", should_end, {True: END, False: "retrieve"})
app = graph.compile()
```

### 6. 何时用 LangGraph

| 场景 | 用 LCEL | 用 LangGraph |
| --- | --- | --- |
| 线性 RAG | ✅ | 过重 |
| 单轮简单链 | ✅ | 过重 |
| Agent 循环（ReAct） | 难表达 | ✅ |
| 多 Agent 协作 | ❌ | ✅ |
| 复杂分支 / 回溯 | ❌ | ✅ |

> LangGraph 正取代旧 AgentExecutor 成为构建 Agent 的主流方式，见 [[4.LangChain Agent的定义及核心作用]]。

### 7. 一句话总结

LangChain 架构从"传统 Chain（固定类）"演进到"LCEL 声明式管道（`|` 管道符 + Runnable 统一接口，原生流式 / 异步 / 批量）"，再到"LangGraph 图状态机（支持循环 / 分支 / 多 Agent）"——简单线性流程用 LCEL，Agent 循环与多智能体协作用 LangGraph。
