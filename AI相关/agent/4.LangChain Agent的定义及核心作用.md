## LangChain Agent 的定义及核心作用

### 1. Agent 是什么

Agent = 以 LLM 为大脑、能**自主决策调用工具、多步推理**直到完成任务的智能实体。

- 区别于固定 Chain：Chain 是写死的流程，Agent 由 LLM 动态决定下一步干什么。
- 核心：LLM 依据"当前状态 + 工具列表"产出 Thought + Action（调哪个工具、传什么参），见 Observation 后循环，直到 Final Answer。

### 2. 核心作用

| 作用 | 说明 |
| --- | --- |
| 自主规划 | 把任务拆成子步骤，动态决定顺序 |
| 工具使用 | 按需调用搜索 / 计算 / 数据库 / API 等工具 |
| 多步推理 | 跨多轮 Thought-Action-Observation 推进 |
| 错误恢复 | 工具失败作为 Observation 回填，自主修正重试 |
| 终止判断 | 信息够了输出 Final Answer，否则继续 |

> 完整 ReAct 循环机制见 [[1.ReAct循环的完整过程]]。

### 3. LangChain Agent 类型

| 类型 | 决策方式 | 说明 |
| --- | --- | --- |
| ReAct | 文本解析 Thought / Action | 经典，提示工程驱动，易出错 |
| OpenAI Functions / Tool Calling | 原生 function calling 结构化字段 | 现代主流，解析可靠 |
| Structured Tool Chat | 结构化工具消息 | 兼容部分模型 |

现代实现普遍用 Tool Calling（function calling），不再用正则解析文本。

### 4. AgentExecutor 循环

AgentExecutor 是旧版执行器，封装"Agent 决策 → 工具执行 → Observation 回填 → 再决策"的循环：

```python
from langchain.agents import create_tool_calling_agent, AgentExecutor
agent = create_tool_calling_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, max_iterations=10, verbose=True)
executor.invoke({"input": "查北京今天天气并总结"})
```

| AgentExecutor 关键参数 | 作用 |
| --- | --- |
| max_iterations | 最大步数，防死循环 |
| early_stopping_method | 超步数处理（generate / force） |
| handle_parsing_errors | 解析失败兜底 |
| return_intermediate_steps | 是否返回中间步骤 |

### 5. LangGraph 取代 AgentExecutor 的趋势

| 维度 | AgentExecutor（旧） | LangGraph（新） |
| --- | --- | --- |
| 模型 | 固定循环封装 | 图状态机，显式可控 |
| 定制 | 难改循环逻辑 | 节点 / 边自由定义 |
| 多 Agent | 不支持 | 原生支持 |
| 状态 / 记忆 | 弱 | State 显式管理 |
| 可观测 | 回调 | 节点级追踪 |
| 现状 | 维护但逐步弃用 | 官方推荐 |

LangChain 官方已推荐用 LangGraph 构建 Agent（见 [[3.LangChain的核心架构解析]]），AgentExecutor 仍可用但不再是首选。

### 6. 一句话总结

LangChain Agent 是以 LLM 为大脑、自主规划 + 调用工具 + 多步推理的智能实体，类型从 ReAct 文本解析演进到 Tool Calling 结构化调用；执行器正从封装式的 AgentExecutor 迁移到图状态机式的 LangGraph，以支撑更复杂的循环、状态与多 Agent 协作。
