## 不同 LLM Provider 对 Tool Schema 支持差异的处理及 OpenClaw 的适配方法

### 1. 问题：Tool Calling 没有"普通话"

Function Calling / Tool Calling 是让 LLM 调用外部工具的事实标准，但**它没有统一国际规范**，各家 Provider 各自实现，同一份工具定义换个 Provider 可能就调不通：

| 差异维度 | 说明 |
| --- | --- |
| Schema 字段命名 | OpenAI 用 `tools[].function.parameters`，Anthropic 用 `tools[].input_schema`，Gemini 用 `functionDeclarations[]` |
| JSON Schema 子集 | 支持的类型/关键字不同（`$ref`/`oneOf`/`anyOf`/`format` 支持参差） |
| 嵌套对象 | 有的支持任意嵌套，有的只支持扁平结构 |
| required 字段 | 多数支持 `required` 数组，个别 Provider 处理宽松 |
| 多工具并行 | OpenAI 有 `parallel_tool_calls`，部分 Provider 一轮只能调一个或行为不同 |
| 枚举/约束 | `enum`/`minimum`/`pattern` 等约束支持不一 |

### 2. 主流 Provider 差异对比

| Provider | 工具描述入口 | 嵌套 | required | 多工具并行 | 备注 |
| --- | --- | --- | --- | --- | --- |
| OpenAI | `tools[].function.parameters` | 支持 | 支持 | 支持（`parallel_tool_calls`） | 事实标杆，多数框架兼容 |
| Anthropic | `tools[].input_schema` | 支持 | 支持 | 一轮可多个 `tool_use` | 用完整 JSON Schema |
| Gemini | `functionDeclarations[]` | 弱 | 支持 | 受限 | 参数偏扁平，复杂结构需拍平 |
| Qwen / 通义 | 兼容 OpenAI 风格 | 支持 | 支持 | 支持 | 部分细节与 OpenAI 有出入 |

### 3. 通用处理方法

| 方法 | 思路 |
| --- | --- |
| 抽象统一工具描述层 | 内部用一套与 Provider 无关的 Tool Schema（标准 JSON Schema），不直接暴露 Provider 私有格式 |
| Provider 适配器 | 每个 Provider 一个适配器，把统一描述转换成该 Provider 要求的格式 |
| 特性探测与降级 | 运行时探测 Provider 能力，不支持的特性降级（嵌套拍平、并行改串行、枚举转文字提示） |

### 4. OpenClaw 的适配方法

OpenClaw 这类 Agent 框架的典型设计，用一层 **Provider 适配层**屏蔽差异：

```
统一 Tool Schema（标准 JSON Schema）
        │
   Provider 适配层 ──┬─→ OpenAI 适配器 ───→ tools[].function.parameters
                    ├─→ Anthropic 适配器 → tools[].input_schema
                    ├─→ Gemini 适配器 ───→ functionDeclarations[]
                    └─→ Qwen 适配器 ─────→ OpenAI 兼容格式
        │
   特性探测与降级（运行时按 Provider 能力裁剪 Schema）
```

| 适配动作 | 说明 |
| --- | --- |
| 统一抽象 | 框架内工具一律用标准 JSON Schema 描述，含 name/description/parameters |
| 格式转换 | 适配器把统一描述映射到各 Provider 的字段命名与结构 |
| 能力探测 | 启动时/运行时探测 Provider 支持的 Schema 子集（嵌套深度/并行/枚举） |
| 降级策略 | 嵌套→拍平为多字段；并行→串行循环调用；枚举→转成 description 文字约束 |
| 结果归一 | 把各 Provider 返回的 tool_call 结构归一成统一调用对象，供 Agent Runner 执行 |

> 工具调用完整链路见 [[19.Tool Calling工具调用的完整链路解析]]，动态 API 调用见 [[13.LLM Agent动态API调用的实现方式]]。

### 5. 一句话总结

不同 LLM Provider 的 Tool Schema 格式与能力各异，OpenClaw 这类框架用**统一 Tool Schema 抽象 + Provider 适配器转换 + 运行时特性探测与降级**三层屏蔽差异，让同一套工具定义跨 Provider 复用，上层 Agent 逻辑无需感知底层差异。
