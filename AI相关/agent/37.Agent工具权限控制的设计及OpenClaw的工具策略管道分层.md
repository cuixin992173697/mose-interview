## Agent 工具权限控制的设计及 OpenClaw 的工具策略管道分层

### 1. 工具权限控制需求

Agent 能调用工具是把双刃剑，权限失控会出大事：

| 风险 | 场景 |
| --- | --- |
| 误操作 | Agent 误删文件、误发邮件、误改生产数据 |
| 越权 | 低权限用户借 Agent 调用高权限工具 |
| 数据泄露 | Agent 把敏感数据外发到第三方工具 |
| 恶意指令注入 | 用户 Prompt 注入诱导 Agent 调危险工具 |

因此工具调用前必须有权限控制层。

### 2. 通用设计

OpenClaw 这类框架的工具权限控制通常包含：

| 设计项 | 说明 |
| --- | --- |
| 工具分级 | 按风险分只读 / 可逆 / 危险三级 |
| 权限矩阵 | 角色 × 工具 的允许/拒绝/需审批矩阵 |
| 审批流 | 危险工具调用前需人工确认 |
| 沙箱执行 | 工具在受限环境运行，限制文件/网络/资源访问 |
| 审计日志 | 记录每次工具调用的调用者/参数/结果，可追溯 |

#### 工具风险分级

| 级别 | 举例 | 默认策略 |
| --- | --- | --- |
| 只读 | 查询、搜索、读文件 | 自动放行 |
| 可逆 | 发消息、建草稿、可撤销操作 | 角色有权限即放行 |
| 危险 | 删文件、转账、改生产配置、外发数据 | 必须人工确认 |

### 3. OpenClaw 工具策略管道分层

工具调用前依次过一条策略管道，**每层可拦截**，全部通过才执行：

```
Agent 决定调用工具
        │
        ▼
① 身份与权限校验（调用者角色是否有该工具权限）——无权限→拒绝
        │
        ▼
② 风险评级（工具定级：只读/可逆/危险）
        │
        ▼
③ 审批/人工确认（危险级→暂停等人工批准）——不批准→取消
        │
        ▼
④ 沙箱/受限执行（限制文件/网络/资源，防越界）
        │
        ▼
⑤ 审计日志（记录调用者/工具/参数/结果）
        │
        ▼
    执行工具，返回结果
```

| 管道层 | 拦截对象 | 失败动作 |
| --- | --- | --- |
| ① 身份权限校验 | 无权限调用 | 直接拒绝 |
| ② 风险评级 | — | 决定后续是否需审批 |
| ③ 审批/人工确认 | 危险级操作 | 暂停等确认，超时/拒绝则取消 |
| ④ 沙箱执行 | 越界访问 | 运行时拦截 |
| ⑤ 审计日志 | — | 不拦截，只记录可追溯 |

### 4. 管道分层价值

| 价值 | 说明 |
| --- | --- |
| 分层拦截 | 权限/风险/审批/沙箱各管一段，单一职责 |
| 快速短路 | ① 权限不通过直接拒，不浪费后续算力 |
| 危险可控 | 危险级必经人工确认，防误操作 |
| 纵深防御 | 即使一层漏了，下一层兜底（如沙箱拦运行时越界） |
| 可审计 | 全链路日志，事后可追溯 |

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 权限随会话隔离键 | 权限绑定 (角色, 隔离键)，多租户下不串权限（见 [[36.多渠道下Agent会话隔离粒度的设计及OpenClaw的实现]]） |
| 审批异步化 | 危险工具暂停后，人工审批结果异步回调继续执行，不阻塞 Agent 主循环 |
| 注入防护 | 校验工具参数是否被 Prompt 注入篡改，危险参数额外校验 |
| 工具白名单 | Agent 只能调用注册的白名单工具，防动态加载未授权工具 |
| 默认拒绝 | 未明确授权的工具默认拒绝，符合最小权限原则 |

### 6. 一句话总结

工具权限控制 = **工具分级（只读/可逆/危险）+ 权限矩阵 + 审批流 + 沙箱 + 审计**；OpenClaw 用策略管道分层（身份权限校验 → 风险评级 → 审批确认 → 沙箱执行 → 审计日志）逐层拦截，危险级必经人工确认，纵深防御防误操作与越权。工具调用链路见 [[19.Tool Calling工具调用的完整链路解析]]，运行阶段见 [[26.OpenClaw的Agent Runner工作原理及运行阶段]]。
