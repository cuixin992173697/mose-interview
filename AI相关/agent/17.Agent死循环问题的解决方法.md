## Agent 死循环问题的解决方法

### 1. 什么是 Agent 死循环

Agent 在执行中**反复执行相同或等价的动作、无法推进到终止**，消耗大量 token 与时间却产不出结果。这是自主 Agent（如 AutoGPT，见 [[16.AutoGPT自主决策的实现原理]]）最典型的故障。

### 2. 死循环的成因

| 成因 | 表现 |
| --- | --- |
| 目标不清 | 目标模糊，模型反复"重新理解目标"却定不下具体动作 |
| 工具反复失败 | 同一工具同一参数反复调用、反复报错、反复重试 |
| 状态不更新 | 每轮上下文几乎一样，模型得不到新信息，输出相同动作 |
| 无终止条件 | 没有最大步数/资源限制，理论上能无限循环 |
| 反思失效 | 模型"反思"后仍得出相同错误结论 |
| 上下文丢失关键信息 | 记忆被截断，模型忘了"已经试过"，重复尝试 |

### 3. 解决方法

| 方法 | 说明 |
| --- | --- |
| 最大步数限制 | 硬性 max_iterations，到顶强制结束，防无限循环 |
| 明确终止条件 | 任务完成判定 + 显式 Finish/Final Answer，让模型知道何时停 |
| 状态去重 | 检测连续相同/相似动作，触发干预 |
| 失败计数与熔断 | 同一工具连续失败 N 次即放弃该路径，换方案或报错 |
| 反思修正 | 失败后强制要求模型"分析原因并换一种方法"，而非原样重试 |
| 资源限制 | token/时间/调用次数预算，耗尽即停 |
| 人工干预兜底 | 触发阈值后暂停并转人工，而非无限自旋 |

### 4. 防循环的设计要点

| 要点 | 做法 |
| --- | --- |
| 把"已尝试"写进上下文 | 明确告诉模型"你刚才试过 X 失败了，别再试"，避免重复 |
| 强制状态推进 | 每轮要求"必须有新进展"，否则判定卡死 |
| 多样性约束 | 限制连续相同动作，鼓励换工具/换参数 |
| 监控与告警 | 实时检测循环特征，及时介入 |

### 5. 一句话总结

Agent 死循环根因是**目标不清、工具反复失败、状态不更新、无终止条件、反思失效**；解决靠**最大步数+明确终止+状态去重+失败熔断+强制反思换法+资源限制+人工兜底**的多层防御，核心思想是"不让 Agent 在同一状态上无限自旋"，工作流程基础见 [[11.Agent智能体的核心工作流程]]。
