## AI Agent 中 Skills 的定义及作用

### 1. Skill 的定义

Skill（技能）= **封装好的、可复用的 Agent 能力单元**，通常由"一组工具调用 + 执行流程 + 提示模板"打包而成，类似给 Agent 装的"技能包"。

```
Skill = 工具组合 + 执行流程 + 提示模板 + 输入输出规范
```

一个 Skill 可以包含多个原子工具的编排，对外暴露一个高阶能力。

### 2. Skill vs 单个 Tool

这是理解 Skill 的关键——Skill 不是 Tool 的同义词，而是**更高阶的封装**：

| 维度 | Tool（工具） | Skill（技能） |
| --- | --- | --- |
| 粒度 | 原子操作 | 高阶能力（可含多步工具） |
| 复杂度 | 单一动作 | 多步编排 + 流程 + 提示 |
| 抽象层级 | 底层 | 上层 |
| 例子 | `search()`、`run_code()` | "写一篇技术博客"（搜索+写作+校对） |
| 决策负担 | Agent 自己决定怎么编排多工具 | Skill 内部已编排好，Agent 只管调用 |

> 类比：Tool 是"螺丝刀/锤子"，Skill 是"组装一个书架"的完整技能包——后者内部用了多个工具并定义了流程。

### 3. Skill 的作用

| 作用 | 说明 |
| --- | --- |
| 能力复用 | 一次封装，多 Agent/多场景复用，避免重复造轮子 |
| 降低决策复杂度 | Agent 不用从零编排多工具，调用一个 Skill 即可 |
| 模块化 | 能力解耦，独立开发/测试/升级 |
| 标准化 | 统一接口规范，Skill 可跨 Agent 共享 |
| 提升可靠性 | 内部流程固化，比让 Agent 自由编排更稳定 |

### 4. 何时用 Skill 而非裸 Tool

| 场景 | 选择 |
| --- | --- |
| 单步原子操作 | 用 Tool |
| 多步固定流程（每次都类似） | 封装成 Skill |
| 跨 Agent 复用的高阶能力 | 封装成 Skill |
| 探索性、流程不固定的任务 | 让 Agent 用 Tool 自由编排 |

### 5. 一句话总结

Skill 是封装了"多工具 + 流程 + 提示"的可复用高阶能力包，比原子 Tool 抽象层级更高；作用是**能力复用、降低 Agent 决策复杂度、模块化、标准化**。与 MCP 的区别见 [[33.MCP与Skills的差异及适用场景]]，体系设计与管理见 [[34.AIAgent的Skills体系设计、管理及实际项目挑战]]。
