## 多 Agent 间的通信协调方式及 OpenClaw 中 Gateway 的作用

### 1. 为什么多 Agent 需要通信协调

单个 Agent 难以胜任复杂任务，常拆成多个职责各异的 Agent 协作（规划 Agent + 执行 Agent + 审查 Agent）。多 Agent 要协作，先要解决"怎么把消息/任务在 Agent 之间传起来"——这就是通信协调。

### 2. 多 Agent 通信方式

| 通信方式 | 机制 | 特点 | 适用 |
| --- | --- | --- | --- |
| 直接调用 | A 直接调 B 的接口，同步拿结果 | 简单、强耦合、同步阻塞 | 父子 Agent 分工、流水线 |
| 消息总线 | Agent 往总线发消息，订阅者收 | 解耦、支持多对多 | 多 Agent 松散协作 |
| 共享黑板（Blackboard） | 共享一块状态区，各 Agent 读写 | 状态共享、需并发控制 | 复杂任务共享上下文 |
| 事件流 | Agent 发事件，其他 Agent 响应 | 异步、可扩、最终一致 | 异步协作、流水触发 |

### 3. 协调方式

| 协调方式 | 说明 |
| --- | --- |
| 同步 | A 调 B 等结果，链式推进，易理解但阻塞 |
| 异步 | A 发消息不等待，B 处理完回调/发事件，吞吐高 |
| 发布订阅 | 发布者不关心谁消费，解耦最彻底 |
| 编排（Orchestrator） | 一个中心（如父 Agent/Gateway）统一调度各子 Agent |

### 4. 通信的共性难题

直接让 Agent 之间点对点通信会很快失控：

| 难题 | 表现 |
| --- | --- |
| 入口分散 | 每个 Agent 各自暴露，调用方要记住一堆地址 |
| 鉴权重复 | 每个 Agent 各做一套鉴权 |
| 缺少路由 | 调用方要自己决定找哪个 Agent |
| 无限流/熔断 | 某 Agent 过载拖垮全局 |
| 协议不一 | 不同 Agent 协议/格式各异 |
| 幂等缺失 | 重试导致重复副作用 |

这些正是引入 **Gateway（网关）** 要解决的问题。

### 5. OpenClaw 中 Gateway 的作用

OpenClaw 这类 Agent 框架的典型设计，在多 Agent 之上设一个 **Gateway（网关）** 作为统一出入口，把"通信协调"的公共职责收敛到一处：

```
        用户 / 外部调用
              │
        ┌─────▼─────┐
        │  Gateway  │  统一入口 / 鉴权 / 路由 / 限流 / 协议转换 / 幂等
        └─────┬─────┘
     ┌────────┼────────┬────────┐
  Agent A   Agent B   Agent C   ...
```

| Gateway 职责 | 说明 |
| --- | --- |
| 统一入口 | 所有请求经 Gateway 进，调用方只需认识一个入口 |
| 路由分发 | 按 [[35.多Agent系统中消息路由的设计及OpenClaw的路由匹配优先级]] 把请求路由到目标 Agent |
| 鉴权 | 统一做身份/权限校验，Agent 不必各做一套 |
| 限流/熔断 | 防止某 Agent 过载扩散 |
| 协议转换 | 对外统一协议，对内适配各 Agent 协议 |
| 消息转发 | 多 Agent 间消息经 Gateway 转发，留痕可审计 |
| 幂等控制 | 重复请求在 Gateway 去重（见 [[44.Agent系统幂等性的必要性及OpenClaw的Gateway幂等性处理方案]]） |

### 6. Gateway vs 直接点对点

| 维度 | 点对点直连 | Gateway 统一入口 |
| --- | --- | --- |
| 耦合度 | 高（互相认识） | 低（只认识 Gateway） |
| 鉴权 | 各做各的 | 统一一次 |
| 路由 | 调用方自决 | Gateway 集中路由 |
| 可观测 | 分散 | 集中留痕 |
| 扩展 Agent | 改调用方 | 只注册到 Gateway |
| 单点风险 | 无 | Gateway 需高可用 |

> Gateway 是单点，工程上需做高可用（多实例 + 负载均衡）来对冲。

### 7. 一句话总结

多 Agent 协作的通信方式有直接调用/消息总线/共享黑板/事件流，协调分同步/异步/发布订阅/编排；OpenClaw 这类框架在多 Agent 之上设 **Gateway** 统一承担入口、路由、鉴权、限流、协议转换、转发与幂等，把公共通信职责收敛一处、解耦 Agent 间直连。路由细节见 [[35.多Agent系统中消息路由的设计及OpenClaw的路由匹配优先级]]，子 Agent 协作见 [[40.多Agent协作的适用场景及OpenClaw对子Agent的支持方式]]，幂等见 [[44.Agent系统幂等性的必要性及OpenClaw的Gateway幂等性处理方案]]。
