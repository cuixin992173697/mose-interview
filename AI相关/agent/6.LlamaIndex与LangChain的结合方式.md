## LlamaIndex 与 LangChain 的结合方式

### 1. 各自定位

| 框架 | 强项 | 弱项 |
| --- | --- | --- |
| LlamaIndex | 数据接入 / 索引 / 检索（RAG 数据层强）、丰富的 index / query engine | 编排 / Agent / 链相对弱 |
| LangChain | 编排 / Agent / 链 / 工具生态（控制流强） | 索引 / 检索抽象不如 LlamaIndex 细 |

互补关系：LlamaIndex 管"数据 → 索引 → 检索"，LangChain 管"编排 → Agent → 工具"。

### 2. 结合方式

#### 方式一：LlamaIndex 检索器接入 LangChain 链

把 LlamaIndex 的检索器包装成 LangChain Runnable，作为 RAG 链的检索源：

```python
from llama_index.core import VectorStoreIndex
from langchain_core.runnables import RunnableLambda

index = VectorStoreIndex.from_documents(llama_docs)
retriever = index.as_retriever(similarity_top_k=4)

def retrieve(q):
    return [n.node.text for n in retriever.retrieve(q)]

rag = RunnableLambda(retrieve) | prompt | llm | StrOutputParser()
```

#### 方式二：LlamaIndex 复用 LangChain 组件

LlamaIndex 提供适配器，可直接用 LangChain 的 LLM / Embedding / VectorStore：

```python
from llama_index.llms.langchain import LangChainLLM
from langchain_openai import ChatOpenAI

lc_llm = ChatOpenAI(...)
llama_llm = LangChainLLM(llm=lc_llm)   # 在 LlamaIndex 里用 LangChain 模型
```

#### 方式三：混合架构（推荐）

LlamaIndex 建索引 + 检索，LangChain 做 Agent 编排：

```
数据 → [LlamaIndex: 解析→索引→检索] → 检索结果 → [LangChain: Agent/Chain 推理+工具] → 答案
```

充分发挥两者长处：检索精度交给 LlamaIndex，多步推理与工具调用交给 LangChain Agent（见 [[2.LangChain的核心组件详解]] [[3.LangChain的核心架构解析]]）。

### 3. 互补关系表

| 维度 | LlamaIndex | LangChain | 结合建议 |
| --- | --- | --- | --- |
| 数据加载 | 强（多格式 / Reader 丰富） | 一般 | LlamaIndex |
| 索引 / 检索 | 强（多种 index 类型） | 一般 | LlamaIndex |
| 编排 / 链 | 一般 | 强（LCEL） | LangChain |
| Agent | 一般 | 强 | LangChain |
| 工具生态 | 一般 | 强 | LangChain |
| 评测 | 较强（ragas 集成） | 一般 | LlamaIndex |

### 4. 选型建议

- 纯 RAG 且重检索质量 → LlamaIndex 为主
- Agent / 多工具 / 复杂编排 → LangChain 为主
- 既要强检索又要强编排 → 混合（方式三）
- 复杂 RAG 工程可参考 rag 目录的《41.RAG的定义及基于LangChain的RAG应用实现》

### 5. 一句话总结

LlamaIndex 强在"数据 / 索引 / 检索"，LangChain 强在"编排 / Agent / 工具"，二者通过"LlamaIndex 检索器接入 LangChain 链 / LlamaIndex 复用 LangChain 组件 / 混合架构（LlamaIndex 建索引 + LangChain 做 Agent）"结合，混合架构能同时拿到检索精度与编排灵活性。
