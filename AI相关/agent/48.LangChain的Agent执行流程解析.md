## LangChain 的 Agent 执行流程解析

### 1. 执行流程总览

LangChain Agent 的执行是一个 **"决策 → 执行 → 观察"** 的循环，直到满足终止条件输出最终答案：

```
用户输入
  │
  ▼
┌─────────────────────────────┐
│ 1. 组装上下文                │  System Prompt + 工具描述 + 历史 + 用户输入
│    (Agent Scratchpad)        │
└──────────────┬──────────────┘
               ▼
┌─────────────────────────────┐
│ 2. LLM 推理决策              │  生成 Thought + Action（工具名+参数）
│    （是否调用工具？）         │     或直接 Final Answer
└──────────────┬──────────────┘
               ▼
        ┌──────┴──────┐
   调用工具           不调用（信息足够）
        │                  │
        ▼                  ▼
┌──────────────┐    ┌──────────────┐
│ 3. Action 解析│    │ 输出 Final    │
│    校验       │    │  Answer       │
└──────┬───────┘    └──────────────┘
       ▼
┌──────────────┐
│ 4. 工具执行   │
└──────┬───────┘
       ▼
┌──────────────────────────┐
│ 5. Observation 回填上下文 │  结果追加进 Scratchpad
└──────┬───────────────────┘
       ▼
   回到第 2 步（循环）
```

### 2. 各阶段详解

| 阶段 | 动作 | 说明 |
| --- | --- | --- |
| ① 上下文组装 | 拼接 System Prompt + 工具描述(JSON Schema) + 历史 + 用户输入 + Scratchpad | Scratchpad 记录已发生的 Thought/Action/Observation |
| ② LLM 推理决策 | LLM 输出 Thought + Action（或 Final Answer） | 决定调哪个工具、传什么参数；或判定信息足够直接答 |
| ③ Action 解析校验 | 从 LLM 输出解析出工具名+参数，校验工具存在/参数合法 | 经典 ReAct 用正则，现代用 Function Calling 结构化字段 |
| ④ 工具执行 | 调用对应工具 | 失败/超时也产生一条错误 Observation |
| ⑤ Observation 回填 | 把执行结果追加进上下文 Scratchpad | 成为下一轮推理输入；错误也是有效 Observation |
| ⑥ 终止判定 | 判断是否结束 | Final Answer / max_iterations / 超时 / 用户中断 |

### 3. AgentExecutor 循环机制

`AgentExecutor` 是 LangChain 经典的 Agent 执行器，核心控制参数：

| 参数 | 作用 |
| --- | --- |
| `max_iterations` | 最大循环步数，防止死循环 |
| `max_execution_time` | 最大执行时长 |
| `return_intermediate_steps` | 是否返回中间的 Thought/Action/Observation |
| `early_stopping_method` | 达到上限时的兜底策略（`force` 直接让 LLM 给最终答案 / `generate` 再调一次 LLM 总结） |
| `handle_parsing_errors` | Action 解析失败时的处理（回填错误信息让 LLM 修正） |

循环逻辑（伪代码）：

```python
iterations = 0
while iterations < max_iterations:
    # 1. LLM 决策
    output = agent.plan(input, intermediate_steps)
    # 2. 判断是否结束
    if output.is_final_answer():
        return output
    # 3. 执行工具
    observation = tool.run(output.action)
    # 4. 回填
    intermediate_steps.append((output.action, observation))
    iterations += 1
# 5. 兜底
return early_stopping_method兜底
```

### 4. 与 ReAct、OpenClaw Agent Runner 的对应

| 概念 | LangChain Agent | 经典 ReAct | OpenClaw Agent Runner |
| --- | --- | --- | --- |
| 循环 | Thought→Action→Observation | 同 | 同源执行循环 |
| 决策 | LLM + 工具描述 | LLM + 文本标签 | LLM + 工具策略管道 |
| Action 表达 | Function Calling / ReAct 文本 | `Action: tool` + `Action Input:` | 结构化工具调用 |
| 终止 | max_iterations/Final Answer | Final Answer/max_steps | max_steps/超时 |
| 错误恢复 | handle_parsing_errors | 错误作 Observation | 工具失败回填重试 |

ReAct 循环的完整过程见 [[1.ReAct循环的完整过程]]，OpenClaw 的执行引擎见 [[26.OpenClaw的Agent Runner工作原理及运行阶段]]，Tool Calling 完整链路见 [[19.Tool Calling工具调用的完整链路解析]]。

### 5. 代码示例

#### 经典 AgentExecutor（旧版）

```python
from langchain.agents import create_openai_tools_agent, AgentExecutor
from langchain_openai import ChatOpenAI
from langchain.tools import tool

@tool
def search(query: str) -> str:
    """搜索网络"""
    return "..."

llm = ChatOpenAI()
tools = [search]
agent = create_openai_tools_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools,
                         max_iterations=10,
                         return_intermediate_steps=True,
                         handle_parsing_errors=True)
result = executor.invoke({"input": "今天北京天气如何？"})
```

#### LangGraph（新版，推荐）

```python
from langgraph.prebuilt import create_react_agent

agent = create_react_agent(ChatOpenAI(), tools=[search])
result = agent.invoke({"messages": [("user", "今天北京天气如何？")]})
```

### 6. LangGraph 取代 AgentExecutor 的趋势

| 维度 | AgentExecutor（旧） | LangGraph（新） |
| --- | --- | --- |
| 模型 | 固定循环 | 图/状态机，可自定义节点与边 |
| 灵活性 | 低（循环逻辑内置） | 高（可插入中间步骤/条件分支/人工介入） |
| 状态管理 | Scratchpad | 显式 State（可持久化/检查点/回放） |
| 多 Agent | 弱 | 原生支持多节点协作 |
| 官方态度 | 进入维护/弃用 | 主推 |

LangChain 官方已推荐用 LangGraph 构建 Agent，`AgentExecutor` 逐步退出主推路线，但其"决策-执行-观察-回填"循环仍是理解 Agent 执行的本质。

### 7. 一句话总结

LangChain Agent 执行 = **组装上下文 → LLM 决策(Thought/Action) → 解析校验 → 工具执行 → Observation 回填 → 循环 → 终止输出**，由 `AgentExecutor`（旧）或 LangGraph（新，主推）驱动；循环本质与 ReAct、OpenClaw Agent Runner 同源，区别在表达与可控性。ReAct 详见 [[1.ReAct循环的完整过程]]，Agent Runner 详见 [[26.OpenClaw的Agent Runner工作原理及运行阶段]]，Agent 定义见 [[4.LangChain Agent的定义及核心作用]]。
