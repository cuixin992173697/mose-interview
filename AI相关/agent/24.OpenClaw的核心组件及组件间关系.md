## OpenClaw 的核心组件及组件间关系

### 1. 核心组件清单

OpenClaw 由六个核心组件构成，各司其职、可插拔替换：

| 组件 | 职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| Channel Plugin | 多渠道接入抽象，统一异构渠道的消息格式与会话模型 | 渠道原始消息 | 标准化消息 + 会话键 |
| Router | 消息路由，决定交给哪个 Agent 处理 | 标准化消息 | 目标 Agent |
| Agent Runner | 执行引擎，驱动 Thought→Action→Observation 循环 | Agent 配置 + 消息 | 回复 / 工具调用 |
| Context Engine | 上下文管理，组装 / 裁剪 / 压缩上下文 | 会话历史 + 记忆 + 工具结果 | 给 LLM 的上下文 |
| Tool Pipeline | 工具策略管道，校验 / 权限 / 审计 / 执行工具 | 工具调用请求 | 工具结果 |
| Memory | 短期 / 长期记忆存储 | 交互事件 | 记忆检索结果 |

### 2. 组件间关系（数据流）

```
用户消息
   │
   ▼
┌──────────────┐
│Channel Plugin│ ── 标准化消息 + 会话键
└──────┬───────┘
       ▼
┌──────────────┐
│   Router     │ ── 路由到目标 Agent
└──────┬───────┘
       ▼
┌──────────────┐    ┌────────────────┐
│ Agent Runner │◄──►│ Context Engine │ ── 组装上下文
└──────┬───────┘    └───────┬────────┘
       │  推理 / 工具调用      │ 读写
       ▼                    ▼
┌──────────────┐    ┌────────────────┐
│ Tool Pipeline│ ──►│    Memory      │
└──────┬───────┘    └────────────────┘
       │ 工具结果回填 → 回到 Agent Runner 循环
       ▼
   生成回复 → Channel Plugin → 用户
```

读法：消息从 Channel 进入，经 Router 路由到 Agent Runner；Agent Runner 与 Context Engine 双向交互（取上下文 / 写回事件），需要工具时经 Tool Pipeline 执行，结果回填继续循环，最终回复经 Channel 返回用户。Memory 被 Context Engine 读写。

### 3. 各组件定位详解

#### Channel Plugin（多渠道接入层）
把 Web / IM（钉钉 / 企微 / Slack）/ 语音 / API 等异构渠道统一成标准消息格式 + 会话标识，屏蔽渠道差异。详见 [[31.Agent系统多渠道接入的抽象层设计及OpenClaw的Channel Plugin接口]]。

#### Router（消息路由层）
按规则把消息分发到合适的 Agent（单 Agent 直连；多 Agent 按意图 / 职责路由）。详见 [[35.多Agent系统中消息路由的设计及OpenClaw的路由匹配优先级]]。

#### Agent Runner（执行引擎）
驱动单个 Agent 的 Thought→Action→Observation 循环，管理多步执行与终止。详见 [[26.OpenClaw的Agent Runner工作原理及运行阶段]]。

#### Context Engine（上下文管理）
可插拔的上下文抽象，负责组装 System Prompt + 记忆 + 历史 + 工具结果，并在超限时裁剪 / 压缩（Compaction）。详见 [[30.OpenClaw中Context管理抽象为可插拔Context Engine的原因及支持策略]]。

#### Tool Pipeline（工具策略管道）
工具调用前过一层策略管道：校验参数 → 权限检查 → 审计 →（危险操作人工确认）→ 执行。详见 [[37.Agent工具权限控制的设计及OpenClaw的工具策略管道分层]]。

#### Memory（记忆）
短期记忆（当前会话上下文）+ 长期记忆（跨会话外部存储），供 Context Engine 检索注入。概念见 [[22.Agent系统中短期记忆与长期记忆的差异及存储检索方式]] [[12.LLM Agent长期记忆能力的实现方法]]。

### 4. 可插拔设计

| 组件 | 插件化点 | 可替换示例 |
| --- | --- | --- |
| Channel Plugin | 接入协议适配 | 新增钉钉 / 企微 / Slack 渠道 |
| Context Engine | 上下文管理策略 | 滑动窗口 / 摘要压缩 / 检索式 |
| Tool Pipeline | 策略节点 | 加审计 / 限流 / 人工确认节点 |
| Router | 路由规则 | 关键词 / 嵌入相似 / LLM 意图 |
| Memory | 存储后端 | 内存 / 向量库 / 数据库 |
| Agent Runner | 执行模型 | ReAct / Plan-Execute / 图编排 |

可插拔使 OpenClaw 能按场景组合：本地开发用轻量 Memory，生产换向量库；高安全场景加厚 Tool Pipeline；多渠道部署启用多个 Channel Plugin。

### 5. 一句话总结

OpenClaw 六大核心组件 = **Channel Plugin（接入）→ Router（路由）→ Agent Runner（执行）↔ Context Engine（上下文）→ Tool Pipeline（工具）+ Memory（记忆）**，以可插拔方式串联成"消息进 → 路由 → 执行 → 上下文管理 → 工具调用 → 回复出"的完整数据流。单条消息的完整链路见 [[25.OpenClaw中用户消息从输入到回复的完整链路]]。
