## OpenClaw 插件系统的设计要点及插件 API 设计

### 1. 为什么要插件系统

Agent 框架核心不可能预知所有业务需求。插件系统的意义：

| 意义 | 说明 |
| --- | --- |
| 扩展性 | 不改核心代码即可加新能力 |
| 生态 | 第三方可贡献插件，形成生态 |
| 解耦 | 核心只管骨架，能力由插件按需挂载 |
| 定制 | 不同部署装不同插件，按需启用 |

一句话：**核心稳定、能力可插**。

### 2. 插件系统设计要点

| 设计要点 | 说明 |
| --- | --- |
| 插件接口规范 | 统一的插件契约（元数据+入口+回调），保证可加载可替换 |
| 生命周期 | 加载（load）→ 初始化（init）→ 运行（serve）→ 卸载（unload），各阶段有钩子 |
| 依赖管理 | 声明插件依赖，按拓扑序加载，处理冲突 |
| 隔离 | 插件故障不拖垮核心（异常捕获/沙箱/资源限制） |
| 权限 | 插件能访问哪些资源/注册点，最小授权 |
| 版本兼容 | 插件声明兼容的核心版本，加载时校验 |
| 配置 | 插件自带配置声明，框架统一注入 |

### 3. 插件 API 设计

OpenClaw 这类 Agent 框架的典型设计，插件通过"注册点"把自身能力挂到框架各扩展位：

| 注册点 | 插件提供什么 | 举例 |
| --- | --- | --- |
| Hook | 横切拦截（前置/后置处理） | 日志、审计、改写上下文 |
| Channel | 一个新接入渠道 | IM 渠道、语音渠道 |
| Tool | 一个新工具 | 数据库查询工具 |
| Skill | 一个高阶能力 | "生成周报"技能包 |
| Provider | 一个 LLM/Embedding 提供方 | 接入新模型供应商 |

插件 API 通常包含：

| API 组成 | 说明 |
| --- | --- |
| 元数据声明 | 插件名/版本/依赖/权限/配置 schema |
| 生命周期回调 | onLoad / onInit / onEnable / onDisable / onUnload |
| 注册点挂载 | 注册 Hook/Channel/Tool/Skill/Provider |
| 上下文访问 | 拿到框架上下文（Logger/配置/Memory/Gateway 等），受限访问 |
| 错误契约 | 抛出约定异常，框架统一处理 |

伪代码示意：

```python
class MyPlugin(Plugin):
    name = "audit-log"
    version = "1.0.0"
    hooks = ["pre_tool_call", "post_tool_call"]

    def on_init(self, ctx):
        self.logger = ctx.logger

    def pre_tool_call(self, event):
        self.logger.info(f"call tool: {event.tool_name}")
        # 可改写/拦截
```

### 4. 插件 vs Skills 的区别

二者都"加能力"，但层次不同：

| 维度 | Plugin（插件） | Skill（技能） |
| --- | --- | --- |
| 本质 | 框架扩展点 | Agent 能力封装 |
| 关注 | 扩展框架本身（接入/钩子/工具） | 封装可复用的高阶能力给 Agent 调用 |
| 粒度 | 框架级 | 任务级 |
| 典型 | 接一个新渠道、加一个 Hook | "生成周报""订机票"技能包 |

> 详见 [[32.AIAgent中Skills的定义及作用]]。一个插件可以注册并提供若干 Skill。

### 5. 设计陷阱

| 陷阱 | 说明 |
| --- | --- |
| 注册点过少 | 扩展位不够，插件做不了事 |
| 上下文泄漏 | 给插件过多框架内部访问，破坏隔离 |
| 无版本约束 | 核心升级后插件失效 |
| 无故障隔离 | 一个插件异常拖垮整个 Agent |
| 配置混乱 | 插件配置散落，难统一管理 |

### 6. 一句话总结

插件系统让 Agent 框架"核心稳定、能力可插"，设计要点是接口规范/生命周期/依赖/隔离/权限/版本/配置；OpenClaw 这类框架的插件 API 通过 Hook/Channel/Tool/Skill/Provider 等注册点挂载能力，配生命周期回调与受限上下文访问；插件是框架扩展点，Skill 是 Agent 能力封装，二者层次不同。Channel 插件见 [[31.Agent系统多渠道接入的抽象层设计及OpenClaw的Channel Plugin接口]]，Hook 系统见 [[39.Agent系统中Hook中间件的作用、典型场景及OpenClaw的Hook系统设计]]，Skills 见 [[32.AIAgent中Skills的定义及作用]]。
