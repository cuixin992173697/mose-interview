## Agent 系统中短期记忆与长期记忆的差异及存储检索方式

### 1. 为什么要区分短期与长期记忆

Agent 的上下文窗口有限（见 [[21.Agent的Context Window定义及核心约束作用]]），不可能把所有历史都塞进去。借鉴人类认知，把记忆分成**短期（工作记忆）**和**长期**两层，各司其职。

### 2. 短期记忆 vs 长期记忆

| 维度 | 短期记忆 | 长期记忆 |
| --- | --- | --- |
| 类比 | 工作记忆/大脑缓存 | 笔记本/知识库 |
| 存储位置 | LLM 上下文窗口内 | 外部存储（向量库/KV/图） |
| 持久性 | 易失，随会话/截断消失 | 持久，跨会话保留 |
| 作用范围 | 当前会话、当前任务 | 跨会话、跨任务 |
| 容量 | 受 Context Window 限制 | 几乎无上限 |
| 获取方式 | 直接拼接在 Prompt 里 | 需检索召回再注入 |
| 内容 | 最近对话/当前工具结果/任务状态 | 历史偏好/事实/经验/用户画像 |
| 速度 | 快（已在上下文） | 慢（需检索） |

### 3. 短期记忆的存储与检索

短期记忆本质上就是**当前上下文窗口里的内容**：

| 方面 | 方式 |
| --- | --- |
| 存储 | 会话上下文（消息列表）+ 临时缓存（当前任务状态/中间变量） |
| "检索" | 无需检索，直接按顺序拼进 Prompt |
| 管理 | 窗口快满时触发摘要/截断，把旧的压缩或转存长期记忆 |

### 4. 长期记忆的存储与检索

长期记忆存在外部，需要主动存储和检索：

#### 存储方式

| 存储 | 适合存 | 代表 |
| --- | --- | --- |
| 向量库 | 语义化文本记忆（对话片段/事实） | Chroma/Milvus/pgvector |
| 键值库 | 结构化键值（用户偏好/配置） | Redis/DB |
| 图数据库 | 关系型记忆（实体-关系） | Neo4j |
| 文档库 | 完整历史记录 | 对象存储/日志 |

#### 检索方式

| 检索 | 说明 |
| --- | --- |
| 相似度检索 | 按 query 向量召回语义相近记忆（最常用） |
| 时间检索 | 按时间近因/远因召回 |
| 重要性检索 | 按记忆重要度评分召回 |
| 混合检索 | 语义 + 时间 + 重要性加权 |

> 典型实现（如 Generative Agents/MemGPT）：每轮把值得记的内容写入向量库，下一轮按当前 query 检索 top-k 相关记忆注入上下文。

### 5. 协同：短期↔长期的流转

```
短期记忆（上下文窗口）
  ├─ 窗口快满 → 摘要/提取重要内容 → 写入长期记忆
  └─ 需要历史信息 → 从长期记忆检索 → 注入短期记忆
```

| 流转 | 触发 | 动作 |
| --- | --- | --- |
| 短→长 | 窗口压力/重要信息出现 | 摘要/抽取后存入外部 |
| 长→短 | 当前任务需要历史 | 检索 top-k 注入上下文 |

### 6. 一句话总结

Agent 记忆分两层：**短期记忆=上下文窗口内的工作记忆（易失、直接拼接、受窗口限制），长期记忆=外部持久存储（向量库/KV/图，跨会话、需检索召回）**；二者通过"短期满则摘要转存长期、需要时检索注入短期"协同。长期记忆实现细节见 [[12.LLM Agent长期记忆能力的实现方法]]，架构定位见 [[9.LLM Agent的基本架构组成]]，窗口约束见 [[21.Agent的Context Window定义及核心约束作用]]。
