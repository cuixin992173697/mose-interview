## OpenClaw 的定义、核心问题及核心能力

### 1. 定义

OpenClaw 是一个 **LLM Agent 编排框架**：在 LLM 之上，提供上下文管理、执行循环、多渠道接入、多 Agent 路由、工具权限控制等工程能力，使 LLM 能在真实部署环境中持续、安全、多渠道地自主执行任务。

一句话：**LLM 提供"智能"，OpenClaw 提供"工程骨架"。** 原理总览见 [[0.OpenClaw的核心原理解析]]。

### 2. 解决的核心问题

脱离工程框架，直接拿 LLM 做 Agent 会撞上六类问题，OpenClaw 逐一对应：

| # | 核心问题 | 痛点 | 典型场景 |
| --- | --- | --- | --- |
| ① | 上下文窗口受限下的长对话 | 历史累积超窗口，早期信息丢失 | 多轮客服 / 长任务 |
| ② | 工具结果膨胀撑爆上下文 | 一次工具调用返回超大结果（日志 / 检索） | 检索 / 代码执行 / 日志查询 |
| ③ | 多渠道接入异构 | Web / IM / 语音 / API 协议、格式、会话模型各异 | 全渠道部署 |
| ④ | 多 Agent 消息路由 | 多个 Agent 该由谁处理、如何分发 | 多角色协作 |
| ⑤ | 工具权限与安全 | 危险工具（删数据 / 外发）需管控 | 生产环境 |
| ⑥ | 多会话隔离 | 并发多用户 / 多会话不能串扰 | 多租户 |

### 3. 核心能力

针对上述问题，OpenClaw 提供六大核心能力：

| 能力 | 作用 | 对应问题 |
| --- | --- | --- |
| Context Engine | 可插拔上下文管理（组装 / 裁剪 / 压缩） | ①② |
| Agent Runner | 驱动 Thought→Action→Observation 执行循环 | 执行 |
| Channel Plugin | 多渠道统一接入抽象 | ③ |
| Router | 多 Agent 消息路由与分发 | ④ |
| Compaction | 上下文压缩策略（裁剪无效时的兜底） | ① |
| Tool Pipeline | 工具策略管道分层管控 | ⑤ |

会话隔离（⑥）由会话键 + Channel + Memory 协同实现，见 [[36.多渠道下Agent会话隔离粒度的设计及OpenClaw的实现]]。

### 5. 一句话总结

OpenClaw = **LLM Agent 编排框架**，核心价值是把"长对话上下文、工具结果膨胀、多渠道接入、多 Agent 路由、工具权限、多会话隔离"六大工程难题，映射为 Context Engine / Agent Runner / Channel Plugin / Router / Compaction / Tool Pipeline 六大可插拔能力。组件关系见 [[24.OpenClaw的核心组件及组件间关系]]。
