## Agent 系统中 Hook 中间件的作用、典型场景及 OpenClaw 的 Hook 系统设计

### 1. 什么是 Hook / 中间件

Hook（钩子）/ 中间件 = 在 Agent 执行链路的关键节点**插入回调函数**，对流转的数据做拦截、改写或观察，而**不侵入主执行逻辑**。

类比：Web 框架的中间件、LangChain 的 Callbacks、数据库触发器——都是"在固定点位挂自定义逻辑"。

### 2. 作用

| 作用 | 说明 |
| --- | --- |
| 解耦横切关注点 | 把日志、监控、审计等与业务无关的逻辑从主链路剥离 |
| 可插拔扩展 | 加功能不改主代码，注册即生效，卸载即移除 |
| 统一拦截点 | 在固定点位做安全/限流/改写，避免散落各处 |

### 3. 典型场景

| 场景 | Hook 做什么 |
| --- | --- |
| 日志记录 | 记录每步输入输出，便于调试与追踪 |
| 监控指标 | 采集延迟、token 消耗、工具调用次数 |
| 审计 | 留存谁在何时调了什么工具，合规留痕 |
| 限流 | 对 LLM/工具调用频率与并发做限制 |
| 输入输出改写 | 注入额外上下文、脱敏、过滤敏感词 |
| 安全过滤 | 拦截危险工具调用、Prompt 注入检测 |
| 缓存 | 命中缓存直接返回，跳过 LLM 调用 |

### 4. OpenClaw 的 Hook 系统设计

OpenClaw 这类 Agent 框架的典型设计，在 Agent Runner 执行链路上预设一批 Hook 点：

| Hook 点 | 触发时机 | 典型用途 |
| --- | --- | --- |
| on_message_in | 消息接入前 | 输入校验、脱敏、限流 |
| on_llm_before | LLM 调用前 | 注入上下文、改写 Prompt、预算检查 |
| on_llm_after | LLM 调用后 | 记录 token、缓存、结果预处理 |
| on_tool_before | 工具调用前 | 权限校验、风险评级、审批（见 [[37.Agent工具权限控制的设计及OpenClaw的工具策略管道分层]]） |
| on_tool_after | 工具调用后 | 结果改写、超大结果压缩 |
| on_reply_before | 回复前 | 输出过滤、引用校验、审计落库 |

```
消息接入 →[on_message_in]→ LLM调用 →[on_llm_before][on_llm_after]→ 工具调用 →[on_tool_before][on_tool_after]→ 回复 →[on_reply_before]→ 返回
```

| 设计要点 | 说明 |
| --- | --- |
| 注册机制 | 按 Hook 点注册回调，声明优先级 |
| 执行顺序 | 同一 Hook 点多个回调按优先级链式执行 |
| 可中断/短路 | 回调可返回"终止"信号，短路跳出主链路（如限流拦截、审批拒绝） |
| 上下文透传 | 回调可读取/修改流转数据（消息、Prompt、工具结果） |

### 5. 与 LangChain Callbacks 的对应

| 维度 | OpenClaw Hook | LangChain Callbacks |
| --- | --- | --- |
| 形态 | 中间件式，可中断 | 事件监听式，以观察为主 |
| 拦截能力 | 强（可短路） | 弱（主要观察记录） |
| 注册 | 按 Hook 点 | 实现 CallbackHandler 接口 |
| 典型方法 | on_tool_before 等 | on_tool_start/on_tool_end |

> Agent Runner 执行阶段见 [[26.OpenClaw的Agent Runner工作原理及运行阶段]]。

### 6. 一句话总结

Hook 中间件在 Agent 执行链路的固定点位插入可插拔回调，用来解耦日志/监控/审计/限流/安全等横切关注点；OpenClaw 这类框架在消息接入、LLM 调用前后、工具调用前后、回复前预设 Hook 点，支持链式执行与短路中断，是 Agent 系统可扩展性与安全控制的关键基础设施。
