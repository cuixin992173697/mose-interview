## Tool Calling 工具调用的完整链路解析

> 原题标注"OpenClow 前置"为教学标记，本篇讲通用 Tool Calling 链路。

### 1. 什么是 Tool Calling

Tool Calling（工具调用 / Function Calling）= LLM 根据用户意图，**自主决定调用哪个工具、传什么参数**，编排层执行后把结果回填，模型继续推理。它是 Agent 与外界交互的核心机制。

### 2. 完整链路

```
① 用户 query
   ↓
② 模型决策：是否需要工具？调哪个？
   ↓
③ 生成结构化工具调用（工具名 + 参数 JSON）
   ↓
④ 编排层解析 & 校验（工具存在？参数合法？权限？）
   ↓
⑤ 执行工具（调 API / 跑代码 / 查库）
   ↓
⑥ 结果回填上下文（tool_result）
   ↓
⑦ 模型继续推理：还要调工具？还是输出最终答案？
```

| 步骤 | 关键点 |
| --- | --- |
| ② 决策 | 模型依据工具描述+参数 Schema 判断是否调用 |
| ③ 生成 | 原生 Function Calling 返回结构化字段，非文本解析 |
| ④ 校验 | 工具不存在/参数错/无权限→生成错误 Observation 反馈 |
| ⑤ 执行 | 同步或异步，可能成功/失败/超时 |
| ⑥ 回填 | 结果（含错误）作为新上下文 |
| ⑦ 继续 | 模型基于结果决定下一步或收尾 |

### 3. Function Calling vs ReAct 文本解析

| 维度 | Function Calling（现代） | ReAct 文本解析（经典） |
| --- | --- | --- |
| 表达 | API 原生结构化字段 | 文本标签 `Action: / Action Input:` |
| 解析 | 直接读结构，可靠 | 正则提取，易错 |
| 工具描述 | JSON Schema | 自然语言描述 |
| 并行 | 支持一轮调多工具 | 通常串行 |

二者核心循环一致（Thought→Action→Observation），区别在表达与解析方式，详见 [[1.ReAct循环的完整过程]]。

### 4. 错误处理与重试

| 错误类型 | 处理 |
| --- | --- |
| 工具不存在 | 反馈错误，让模型换工具 |
| 参数不合法 | 反馈具体错误信息，模型修正参数重试 |
| 执行失败/超时 | 错误作为 Observation 回填，模型自主修正 |
| 反复失败 | 失败计数熔断，避免死循环（见 [[17.Agent死循环问题的解决方法]]） |

> 错误也是一种 Observation——模型看到"调用失败：参数缺失"后会修正重试，而非卡死。

### 5. 工具描述的重要性

模型选工具全靠工具描述 + 参数 Schema。**描述写得好坏直接决定调用准确率**：

- 描述要讲清"这个工具干什么、何时该用、何时不用"。
- 参数 Schema 要明确类型、必填、含义、取值范围。
- 工具多时，描述质量是命中率的决定因素。

### 6. 一句话总结

Tool Calling 完整链路 = **query → 模型决策调工具 → 生成结构化调用 → 编排层解析校验 → 执行 → 结果回填 → 模型继续推理或收尾**；现代用原生 Function Calling 替代文本解析，错误作为 Observation 驱动自主修正，工具描述质量决定调用准确率。动态调用 API 见 [[13.LLM Agent动态API调用的实现方式]]。
