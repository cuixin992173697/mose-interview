## System Prompt 在 Agent 系统中的职责及过长处理方法

### 1. System Prompt 的职责

System Prompt 是 Agent 系统的"操作系统级指令"，定义了 Agent 是谁、能干什么、怎么干、不能干什么。它贯穿每一次 LLM 调用，是 Agent 行为的总开关。

| 职责 | 说明 | 示例 |
| --- | --- | --- |
| 角色定义 | Agent 的身份、人设、专业领域 | "你是一个资深前端面试官" |
| 能力边界 | Agent 能做什么、不能做什么 | "只能回答前端相关问题" |
| 行为约束 | 工作流程、决策规则、何时调工具 | "信息不足时先检索再回答" |
| 输出格式 | 结构化输出规范 | "用表格对比，结尾一句话总结" |
| 工具说明 | 可用工具的名称、用途、调用时机 | "搜索工具用于查实时信息" |
| 安全规则 | 红线、权限、防注入 | "不执行删除操作除非用户确认" |

> System Prompt 决定 Agent 行为下限——写得越明确，Agent 越可控；写得含糊，Agent 行为就发散。

### 2. System Prompt 过长的问题

工业级 Agent 的 System Prompt 常膨胀到数千甚至上万 token（角色+规则+工具 schema+示例+安全策略全塞进去），带来一系列问题：

| 问题 | 表现 | 影响 |
| --- | --- | --- |
| Token 占用 | 每轮调用都带超长 System Prompt | 成本飙升、上下文预算被挤占 |
| 注意力稀释 | 关键指令被海量文本淹没 | 模型抓不住重点，指令遵循率下降 |
| 指令冲突 | 多条规则相互矛盾 | Agent 行为不稳定、随机选边 |
| Lost-in-the-middle | 中间位置的信息被忽略 | 重要规则放中间会被无视 |
| 维护困难 | 单文件巨型 Prompt 难迭代 | 改一条怕影响全局 |

### 3. 过长的处理方法

#### 方法一：分层结构化

把 System Prompt 按职责分层组织，而非堆砌：

```text
# 角色
你是一个前端面试助手...

# 能力边界
- 只回答前端问题
- ...

# 工具
## search_web: 搜索实时信息
## code_run: 执行代码

# 输出规范
- 用 Markdown
- ...

# 安全
- 危险操作需确认
```

分层让模型按区块理解，也便于维护。

#### 方法二：压缩精简

- 去冗余：删重复表述、合并同类规则。
- 用短句：每条规则一行，避免长段落。
- 删低频：很少触发的规则移到按需注入。

#### 方法三：动态按需注入

不把所有规则一次性全塞，而是根据当前任务/状态**动态拼接**相关部分：

| 策略 | 说明 |
| --- | --- |
| 按任务类型 | 不同任务加载不同规则子集 |
| 按工具集 | 只注入本轮可用工具的说明 |
| 按状态 | 根据对话阶段注入相应流程规则 |

#### 方法四：检索式 Prompt（RAG for Prompt）

把规则库建索引，每轮根据用户 query 检索最相关的几条规则注入，而非全量加载。适合规则极多的场景。

#### 方法五：拆分多文件按场景加载

把 System Prompt 拆成多个模块文件（角色.md / 工具.md / 安全.md / 示例.md），由编排层按场景组合加载：

```python
def build_system_prompt(scene):
    parts = ["base/role.md", "base/safety.md"]
    if scene == "coding":
        parts += ["tools/code_run.md", "rules/coding.md"]
    elif scene == "search":
        parts += ["tools/search.md", "rules/search.md"]
    return "\n".join(load(p) for p in parts)
```

### 4. 方法选型

| 场景 | 推荐方法 |
| --- | --- |
| Prompt 几百 token | 无需处理，直接用 |
| 数千 token，规则多 | 分层结构化 + 压缩精简 |
| 规则随任务变化大 | 动态按需注入 + 拆分多文件 |
| 规则极多（上万字） | 检索式 Prompt |

### 5. 一句话总结

System Prompt 是 Agent 行为的总开关，职责涵盖角色/边界/流程/格式/工具/安全；过长会带来 token 浪费、注意力稀释、指令冲突，解法是**分层结构化 + 压缩精简 + 动态按需注入 + 检索式/多文件加载**。相关上下文约束见 [[21.Agent的Context Window定义及核心约束作用]]，自主决策场景的 Prompt 设计见 [[16.AutoGPT自主决策的实现原理]]。
