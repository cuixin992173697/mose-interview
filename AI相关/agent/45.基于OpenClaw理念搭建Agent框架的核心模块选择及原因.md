## 基于 OpenClaw 理念搭建 Agent 框架的核心模块选择及原因

### 1. 从 OpenClaw 理念出发

OpenClaw 这类 Agent 框架的核心设计理念是：**可插拔、上下文优先、多渠道、安全可控、编排统一**。照此理念自己搭建一个 Agent 框架，应选哪些核心模块、为什么选——本篇给出选型清单与理由。

### 2. 核心模块清单与选型原因

| 核心模块 | 解决的核心问题 | 为什么必须 |
| --- | --- | --- |
| LLM 抽象层 | 屏蔽不同 Provider 差异（接口/Tool Schema/流式各异） | 换模型不改业务，见 [[38.不同LLM Provider对Tool Schema支持差异的处理及OpenClaw的适配方法]] |
| Context Engine | 管 LLM 上下文窗口，长对话不超限 | 上下文是 Agent 的生命线，见 [[30.OpenClaw中Context管理抽象为可插拔Context Engine的原因及支持策略]] |
| Agent Runner | 驱动 Thought→Action→Observation 执行循环 | Agent 的"发动机"，见 [[26.OpenClaw的Agent Runner工作原理及运行阶段]] |
| Tool Pipeline | 工具的权限校验/风险评级/审批/执行/审计 | 工具有副作用，必须安全可控，见 [[37.Agent工具权限控制的设计及OpenClaw的工具策略管道分层]] |
| Hook 系统 | 横切扩展（日志/审计/改写上下文）不侵入核心 | 可插拔扩展的关键，见 [[39.Agent系统中Hook中间件的作用、典型场景及OpenClaw的Hook系统设计]] |
| Channel | 多渠道（Web/IM/语音/API）统一接入 | 一次构建多渠道部署，见 [[31.Agent系统多渠道接入的抽象层设计及OpenClaw的Channel Plugin接口]] |
| Gateway | 统一入口/路由/鉴权/限流/幂等 | 多 Agent 协作的公共枢纽，见 [[42.多Agent间的通信协调方式及OpenClaw中Gateway的作用]] |
| Memory | 短期（上下文内）+ 长期（外置检索）记忆 | 跨轮/跨会话记忆，见 [[22.Agent系统中短期记忆与长期记忆的差异及存储检索方式]] |
| Router | 多 Agent 消息路由 | 决定消息给谁，见 [[35.多Agent系统中消息路由的设计及OpenClaw的路由匹配优先级]] |
| Plugin | 扩展生态（注册点挂载新能力） | 不改核心加能力，见 [[43.OpenClaw插件系统的设计要点及插件API设计]] |

### 3. 模块关系图

```
        Channel(多渠道接入)
              │
          Gateway(入口/路由/鉴权/幂等)
              │
          Router ──→ 子 Agent A / B / C
              │
        Agent Runner(执行循环)
         │    │    │
   Context  Tool  Hook(横切)
   Engine   Pipeline 系统
         │
       Memory(短期+长期)
   ── 所有能力可经 Plugin 扩展 ──
   ── LLM 抽象层贯穿 Runner/Context ──
```

### 4. 最小可用子集 vs 全量模块

并非一上来就要全量模块。按阶段选：

| 阶段 | 最小子集 | 可后加 |
| --- | --- | --- |
| 原型 / Demo | LLM 抽象层 + Agent Runner + Tool Pipeline | — |
| 单 Agent 上线 | + Context Engine + Memory | Hook、Channel |
| 多渠道生产 | + Channel + Gateway | Router、Plugin |
| 多 Agent 协作 | + Router + Gateway 幂等 | Plugin 生态 |

> 最小子集原则：先跑通"LLM 决策 + 工具执行 + 上下文管理"主链路，再按需叠加多渠道/多 Agent/扩展生态。

### 5. 选型的三条主线

| 主线 | 对应模块 | 理念 |
| --- | --- | --- |
| 跑起来 | LLM 抽象层 + Agent Runner + Tool Pipeline | 执行能力 |
| 跑得久 | Context Engine + Memory | 上下文优先 |
| 跑得广 | Channel + Gateway + Router + Hook + Plugin | 多渠道/多 Agent/可插拔 |

### 6. 一句话总结

基于 OpenClaw 理念搭建 Agent 框架，核心模块应选 LLM 抽象层/Context Engine/Agent Runner/Tool Pipeline/Hook/Channel/Gateway/Memory/Router/Plugin——分别解决模型差异、上下文、执行循环、工具安全、横切扩展、多渠道、统一入口、记忆、多 Agent 路由、生态扩展；先以"LLM+Runner+Tool"最小子集跑通主链路，再按阶段叠加多渠道与多 Agent 能力。OpenClaw 原理见 [[0.OpenClaw的核心原理解析]]，组件关系见 [[24.OpenClaw的核心组件及组件间关系]]，Context Engine 见 [[30.OpenClaw中Context管理抽象为可插拔Context Engine的原因及支持策略]]，Agent Runner 见 [[26.OpenClaw的Agent Runner工作原理及运行阶段]]。
