## MCP 与 Skills 的差异及适用场景

### 1. 各自定义

| 概念 | 定义 |
| --- | --- |
| MCP（Model Context Protocol） | 连接 LLM 与外部工具/数据源的**标准化协议/连接器**，解决"怎么把外部能力统一接入模型" |
| Skills | 封装好的、可复用的 Agent **能力/技能包**（多工具+流程+提示），解决"怎么把高阶能力复用" |

> 一句话：MCP 管"接入"，Skills 管"执行与复用"。

### 2. 核心差异

| 维度 | MCP | Skills |
| --- | --- | --- |
| 本质 | 协议/连接器 | 能力封装 |
| 关注点 | 标准化接入外部资源 | 复用高阶执行能力 |
| 粒度 | 单个工具/数据源 | 多工具编排的能力包 |
| 解决问题 | 工具接入碎片化、每家接口不同 | 高阶能力重复开发、Agent 编排复杂 |
| 类比 | USB 接口标准 | 应用程序 |
| 产出 | 一批可被模型调用的标准工具 | 一个可复用的完整能力 |

### 3. 适用场景

| 场景 | 推荐 | 原因 |
| --- | --- | --- |
| 接入数据库/API/文件系统等外部资源 | MCP | 标准化协议，一次接入多模型可用 |
| 让多个 Agent 共享同一个工具集 | MCP | 工具层解耦 |
| 复用一个多步骤的高阶能力（如"生成周报"） | Skills | 流程固化、复用 |
| 降低 Agent 对复杂多工具任务的编排难度 | Skills | Skill 内部已编排 |
| 团队沉淀通用业务能力 | Skills | 模块化资产 |

### 4. 二者协同

MCP 和 Skills 并非二选一，而是**分层协同**：

```
Skills（高阶能力，编排多个工具）
  └─ 调用 ─→ MCP 接入的标准化工具（底层资源访问）
```

- MCP 在底层提供标准化的工具/数据源接入。
- Skills 在上层把多个 MCP 工具（或本地工具）编排成高阶能力。
- Agent 只需选择并调用 Skill，Skill 内部用 MCP 工具完成执行。

### 5. 一句话总结

MCP 是标准化**接入外部资源的协议/连接器**（管"怎么连"），Skills 是封装复用的**高阶能力包**（管"怎么执行/复用"）；两者分层协同——Skills 在上编排，MCP 在下接入。Skill 定义见 [[32.AIAgent中Skills的定义及作用]]，体系管理见 [[34.AIAgent的Skills体系设计、管理及实际项目挑战]]，底层工具调用链路见 [[19.Tool Calling工具调用的完整链路解析]]。
