## OpenClaw 中用户消息从输入到回复的完整链路

> 原题 "OpenClow" 笔误统一为 OpenClaw。

### 1. 链路总览

一条用户消息从进入到回复返回，经过以下环节：

```
用户消息 → ①Channel 接入 → ②会话/隔离键解析 → ③Router 路由 → ④Agent Runner 启动
        → ⑤Context Engine 组装上下文 → ⑥LLM 推理（含工具循环）→ ⑦生成回复 → Channel 返回
```

### 2. 每步输入/输出/职责

| 步骤 | 输入 | 处理 | 输出 |
| --- | --- | --- | --- |
| ① Channel 接入 | 渠道原始消息 | 协议解析、格式标准化 | 标准消息对象 |
| ② 会话/隔离键解析 | 标准消息 | 提取会话 ID / 用户 ID / 渠道，确定隔离粒度 | 会话上下文键 |
| ③ Router 路由 | 消息 + 会话键 | 按规则匹配目标 Agent | 目标 Agent |
| ④ Agent Runner 启动 | Agent 配置 + 消息 | 加载工具 / Skills，进入执行循环 | 执行实例 |
| ⑤ Context Engine 组装 | 历史 + 记忆 + 工具定义 | 拼 System Prompt + 记忆 + 历史 + 工具说明，超限则裁剪 / 压缩 | LLM 上下文 |
| ⑥ LLM 推理 | 上下文 | LLM 决策：直接答 or 调工具 | 文本回复 or 工具调用 |
| ⑦ 工具循环（可选） | 工具调用 | Tool Pipeline 校验执行 → 结果回填 → 回到⑥ | 观察结果 |
| ⑧ 生成回复 | 最终推理 | 终止循环，格式化回复 | 标准回复 |
| ⑨ Channel 返回 | 标准回复 | 转渠道格式发回用户 | 用户可见回复 |

### 5. 一句话总结

OpenClaw 的消息链路 = **Channel 接入 → 会话键解析 → Router 路由 → Agent Runner 启动 → Context Engine 组装上下文 → LLM 推理（工具循环）→ 生成回复 → Channel 返回**，九步把一条用户消息变成有上下文、有工具、有权限管控的 Agent 回复。执行循环细节见 [[26.OpenClaw的Agent Runner工作原理及运行阶段]]，组件关系见 [[24.OpenClaw的核心组件及组件间关系]]。
