## Agent 智能体的核心工作流程

### 1. 核心循环

Agent 的工作本质是一个 **"感知→规划→行动→观察→反思"** 的循环，直到目标完成或终止：

```
用户目标/输入
     │
     ▼
┌─→ 感知（Perception）：接收输入与环境状态
│      │
│      ▼
│   规划（Plan）：推理下一步做什么、用什么工具
│      │
│      ▼
│   行动（Act）：调用工具/执行动作
│      │
│      ▼
│   观察（Observe）：获取工具/环境返回结果
│      │
│      ▼
│   反思（Reflect）：结果够不够？目标达成没？下一步？
│      │
└──── 终止判定 ──否──→ 回到感知
            │是
            ▼
        输出最终答案
```

### 2. 各阶段详解

| 阶段 | 做什么 | 产出 |
| --- | --- | --- |
| 感知 | 接收用户输入、工具结果、环境状态 | 当前状态描述 |
| 规划（Plan/Thought） | 推理"现在知道什么、还缺什么、下一步干嘛" | 行动决策 |
| 行动（Act） | 调用工具、执行代码、或直接回答 | 工具调用 |
| 观察（Observe） | 收集行动结果（成功输出/错误） | 结果回填上下文 |
| 反思（Reflect） | 评估进展、判断是否完成、修正方向 | 继续/终止/换方案 |

### 3. 与 ReAct 的关系

ReAct（Reasoning + Acting）是上述循环的经典实现，把"规划"和"反思"合并为 Thought：

```
Thought（思考）→ Action（行动）→ Observation（观察）→ Thought → ... → Final Answer
```

ReAct 的完整过程见 [[1.ReAct循环的完整过程]]。现代 Agent 框架在此基础上加了显式规划、反思、多 Agent 协作等增强。

### 4. 终止条件

循环必须有终止机制，否则死循环：

| 终止条件 | 说明 |
| --- | --- |
| 目标完成 | 模型判断信息足够，输出最终答案 |
| 最大步数 | max_iterations / max_steps 上限 |
| Token/超时 | 上下文耗尽或超时 |
| 用户中断 | 人工停止 |
| 不可恢复错误 | 致命错误退出 |

> 死循环的成因与解决见 [[17.Agent死循环问题的解决方法]]。

### 5. 一个完整示例

```
目标：查北京今天天气并决定是否带伞
1. 感知：用户问"今天北京下雨吗，要带伞吗"
2. 规划：需要先查天气 → 调天气工具
3. 行动：调用 get_weather("北京")
4. 观察：返回"小雨，18℃"
5. 反思：拿到天气了，可以回答了
6. 输出：北京今天小雨，建议带伞
```

### 6. 关键机制

| 机制 | 说明 |
| --- | --- |
| 推理指导行动 | 规划决定行动，行动结果反过来更新推理 |
| 错误即观察 | 工具失败作为 Observation 回填，模型自主修正 |
| 上下文累积 | 每轮追加内容，需上下文管理（压缩/摘要/记忆） |
| 终止保障 | 多重终止条件防止死循环 |

### 7. 一句话总结

Agent 核心工作流程 = **感知→规划→行动→观察→反思** 的循环，ReAct 是其经典实现（Thought→Action→Observation）；推理指导行动、行动反馈更新推理，靠多重终止条件收尾——本质是"边想边做边纠错"的自主推进过程。
