## 讲一下ReAct循环的完整过程，用户发一个任务到完成中间经过哪些处理

### 1. 输入预处理 & 上下文组装
在调用模型前，harness(编排层)，要拼出完整的上下文，通常包含：

| 组成 | 作用 |
| --- | --- |
| System Prompt | 角色定义、行为规则、输出格式约定 |
| Tool/Function 定义 | 可用工具的名字、描述、参数 JSON Schema——模型据此决定调用哪个 |
| 历史对话 / 记忆 | 之前轮次的 Thought/Action/Observation（多轮任务的关键） |
| 用户任务 | 本轮要解决的目标 |

这一步还要做上下文管理：检查 token 是否超限，超了就截断、摘要或检索（RAG）

### 2. LLM 推理生成（Reasoning + Acting）

模型收到上下文后输出两部分：

  - Thought（思考）：对当前状态的推理——"我现在知道什么、还缺什么、下一步该干什么、为什么"。
  - Action（行动）：具体的动作选择，即调用哪个工具、传什么参数。

  这一步是 ReAct 区别于"纯思维链"和"纯行动"的关键：推理指导行动，行动的结果又反过来更新推理。


### 3. Action 解析 & 校验

编排层把模型的输出解析成可执行的调用：

  - 经典 ReAct：用正则/解析从文本里抽出 Action: tool_name 和 Action Input: {...}。
  - 现代实现：直接用 API 的 function calling / tool_use 结构化字段，解析更可靠。

  然后做校验：工具是否存在？参数类型对不对？是否有权限？不通过则生成一条错误 Observation 反馈给模型。

### 4. Action 执行（Acting）

 在真实环境里执行工具调用：

  - 调外部 API（搜索、天气、数据库查询）
  - 执行代码（Python/Shell）
  - 读写文件、操作浏览器
  - 调用子 Agent

  执行可能是同步的，也可能是流式的；可能成功，也可能抛错或超时。

### 5. Observation 回填

把执行结果（成功输出 或 错误信息）格式化后追加进上下文，成为下一轮推理的新输入。

重点：错误也是一种 Observation——模型看到"工具调用失败：参数缺失"后，会在下一轮 Thought 里修正参数重试，而不是卡死。


### 6. 终止判定 & 最终回答

 循环每轮都要判断是否结束：

  - 正常结束：模型判断信息已足够，不再调用工具，直接输出最终答案（或显式调用 Finish/Final Answer）。
  - 强制结束：达到最大步数（max_iterations）、token 耗尽、用户中断、超时。

## 关键机制

  ┌──────────────┬─────────────────────────────────────────────────────────────────┐
  │     机制     │                              说明                               │
  ├──────────────┼─────────────────────────────────────────────────────────────────┤
  │ 循环终止条件 │ Final Answer / max_steps / 超时 / 用户中断——防止死循环          │
  ├──────────────┼─────────────────────────────────────────────────────────────────┤
  │ 错误恢复     │ 工具失败作为 Observation 回填，模型自主修正重试                 │
  ├──────────────┼─────────────────────────────────────────────────────────────────┤
  │ 上下文管理   │ 每轮都追加内容，token 会膨胀；需截断、摘要、或只保留最近 N 轮   │
  ├──────────────┼─────────────────────────────────────────────────────────────────┤
  │ 记忆与状态   │ 跨轮任务靠历史上下文；长任务用外部记忆/向量库检索               │
  ├──────────────┼─────────────────────────────────────────────────────────────────┤
  │ 工具选择     │ 模型依据工具描述 + 参数 Schema 决策，描述写得好坏直接影响准确率 │
  ├──────────────┼─────────────────────────────────────────────────────────────────┤
  │ 权限与安全   │ 危险操作（删文件、外发请求）通常需要人工确认                    │
  └──────────────┴─────────────────────────────────────────────────────────────────┘

## 经典 ReAct vs 现代实现

  ┌─────────────────────┬────────────────────────────────────┬─────────────────────────────────────────────┐
  │        维度         │      经典 ReAct（2022 论文）       │   现代 Agent（如 Claude Code、各类框架）    │
  ├─────────────────────┼────────────────────────────────────┼─────────────────────────────────────────────┤
  │ Thought/Action 表达 │ 纯文本标签 Thought: / Action:      │ 原生 function calling / tool_use 结构化字段 │
  ├─────────────────────┼────────────────────────────────────┼─────────────────────────────────────────────┤
  │ 解析方式            │ 正则提取，易出错                   │ API 直接返回结构，可靠                      │
  ├─────────────────────┼────────────────────────────────────┼─────────────────────────────────────────────┤
  │ Observation 格式    │ 文本拼接                           │ 结构化 tool_result 消息                     │
  ├─────────────────────┼────────────────────────────────────┼─────────────────────────────────────────────┤
  │ 多工具并行          │ 通常串行                           │ 支持一轮内并行调用多个工具                  │
  ├─────────────────────┼────────────────────────────────────┼─────────────────────────────────────────────┤
  │ 核心循环            │ 一样：Thought→Action→Observation→… │ 一样                                        │
  └─────────────────────┴────────────────────────────────────┴─────────────────────────────────────────────┘
