## 主流 LLM Agent 框架及各自特点

### 1. 框架全景

主流 Agent 框架按定位可分为**通用编排、多 Agent 协作、自主循环、领域专用**几类：

| 框架 | 定位 | 核心特点 | 适用场景 |
| --- | --- | --- | --- |
| LangChain | 全栈通用生态 | 组件丰富（Loader/Splitter/Retriever/Chain/Agent），生态最大 | 快速搭建 RAG + Agent，通用首选 |
| LangGraph | 图编排 / 状态机 | 把 Agent 建模为有状态图（节点+边），支持循环/分支/人机协同 | 复杂多步、需精确控制流转的 Agent |
| LlamaIndex | 数据检索强 | 数据连接与索引能力突出，RAG 见长 | 以检索/知识为核心的 Agent |
| AutoGen | 多 Agent 对话 | 把多个 Agent 当作对话参与者，角色互聊协作 | 多 Agent 讨论/协作任务 |
| CrewAI | 角色协作 | 定义角色（Crew）+ 任务（Task）+ 流程，偏"团队"隐喻 | 流程化的多角色协作 |
| MetaGPT | 软件工程多 Agent | 模拟软件团队（PM/架构/开发），SOP 驱动 | 自动化软件开发 |
| AutoGPT | 自主循环 | 给目标自主拆解执行（见 [[16.AutoGPT自主决策的实现原理]]） | 探索性、开放式自主任务 |

### 2. 选型维度

| 维度 | 说明 |
| --- | --- |
| 任务复杂度 | 简单 RAG→LangChain/LlamaIndex；复杂流转→LangGraph |
| 是否多 Agent | 单 Agent 足矣→LangChain；多角色协作→CrewAI/AutoGen/MetaGPT |
| 可控性 vs 自主性 | 要精确控制流转→LangGraph；要高自主→AutoGPT 类 |
| 生态与社区 | LangChain 生态最大，踩坑资料多 |
| 学习曲线 | LangChain/LlamaIndex 上手快，LangGraph/MetaGPT 概念多 |

### 3. LangChain vs LangGraph 的关系

很多人混淆二者：

| 维度 | LangChain | LangGraph |
| --- | --- | --- |
| 定位 | 通用组件库 + Chain | 状态图编排引擎 |
| 表达力 | 链式（DAG 为主） | 显式图，支持循环/条件/持久化状态 |
| 适合 | 线性管线、简单 Agent | 复杂 Agent（多步循环、人机协同、回溯） |
| 关系 | LangGraph 是 LangChain 生态中用于复杂 Agent 编排的引擎 | — |

组件细节见 [[2.LangChain的核心组件详解]]，架构见 [[3.LangChain的核心架构解析]]。

### 4. 一句话总结

主流 Agent 框架各有侧重：**LangChain 通用全栈、LangGraph 图编排精确控制、LlamaIndex 检索见长、AutoGen/CrewAI/MetaGPT 多 Agent 协作、AutoGPT 自主循环**；选型看任务复杂度、是否多 Agent、可控性需求与生态，复杂流转优先 LangGraph。
