## OpenClaw 的 Agent Runner 工作原理及运行阶段

### 1. Agent Runner 是什么

Agent Runner 是 OpenClaw 的**执行引擎**，负责驱动单个 Agent 的运行——把"消息 + 上下文"喂给 LLM，解析出回复或工具调用，执行工具，回填结果，循环直至产出最终回复。其本质是 Thought→Action→Observation 循环，与经典 ReAct 同源（见 [[1.ReAct循环的完整过程]]）。

> 区别：ReAct 是推理范式（Thought / Action / Observation 文本协议），Agent Runner 是工程化的执行容器——在 ReAct 循环外叠加了上下文管理、工具策略管道、终止控制、异常重试等工程能力。

### 2. 运行阶段（七阶段）

| 阶段 | 动作 | 输入 | 输出 |
| --- | --- | --- | --- |
| ① 初始化 | 加载 Agent 配置、工具集、Skills、System Prompt | Agent 配置 | 就绪的执行实例 |
| ② 上下文组装 | 向 Context Engine 取 System Prompt + 记忆 + 历史 + 工具说明，超限则裁剪 / 压缩 | 会话键 | LLM 上下文 |
| ③ LLM 推理 | 调 LLM，产出文本回复或工具调用请求 | 上下文 | 回复 / 工具调用 |
| ④ 解析工具调用 | 解析 LLM 输出为结构化工具名 + 参数（Function Calling） | LLM 输出 | 工具调用对象 |
| ⑤ Tool Pipeline 校验执行 | 参数校验 → 权限检查 → 审计 →（危险操作人工确认）→ 执行 | 工具调用 | 工具结果 |
| ⑥ 结果回填 | 工具结果（过大则截断 / 摘要）作为 Observation 追加进上下文 | 工具结果 | 更新后的上下文 |
| ⑦ 终止判定 | 判断是否结束：Final Answer / max_steps / 超时 / 用户中断 | 状态 | 结束 or 回到② |

### 3. 执行循环图

```
        ┌─── ① 初始化 ───┐
        │                 ▼
        │   ② 上下文组装（Context Engine）
        │                 │
        │                 ▼
        │          ③ LLM 推理
        │                 │
        │        ┌────────┴────────┐
        │     工具调用           直接回复
        │        │                 │
        │        ▼                 │
        │  ④ 解析工具调用          │
        │        ▼                 │
        │  ⑤ Tool Pipeline 执行    │
        │        ▼                 │
        │  ⑥ 结果回填（Observation）│
        │        │                 │
        │        ▼                 ▼
        └─ ⑦ 终止判定 ───► 否（回②）
                          │
                         是
                          ▼
                     最终回复
```

### 4. 与 LangGraph executor / AgentExecutor 的对应

| 概念 | LangChain AgentExecutor | LangGraph executor | OpenClaw Agent Runner |
| --- | --- | --- | --- |
| 执行模型 | ReAct / Functions 循环 | 图遍历 + 状态机 | Thought→Action→Observation 循环 |
| 上下文管理 | 简单 Memory | 状态对象 | 可插拔 Context Engine |
| 工具执行 | 直接调 | 节点执行 | 过 Tool Pipeline 策略管道 |
| 终止 | max_iterations | 图终止条件 | Final Answer / max_steps / 超时 |
| 异常 | 基本重试 | 节点异常处理 | 分类重试 + 错误回填 |

三者执行模型同源（都基于 LLM 工具调用循环），OpenClaw Agent Runner 的差异在于把上下文管理和工具管控抽成可插拔组件，而非内置硬编码。

### 5. 异常与重试

| 异常类型 | 处理 |
| --- | --- |
| 工具执行失败 | 错误信息作为 Observation 回填，LLM 下轮修正参数重试 |
| 参数校验失败 | 生成错误 Observation，不执行工具 |
| 权限拒绝 | 返回拒绝原因，不执行 |
| LLM 输出不可解析 | 重试一次或降级为纯文本 |
| 超时 / max_steps | 强制终止，返回部分结果或提示 |
| 死循环倾向 | 状态去重 + 失败计数熔断（见 [[17.Agent死循环问题的解决方法]]） |

### 6. 一句话总结

Agent Runner = OpenClaw 的**执行引擎**，以七阶段（初始化 → 上下文组装 → LLM 推理 → 解析工具调用 → Tool Pipeline 执行 → 结果回填 → 终止判定）驱动 Thought→Action→Observation 循环，在 ReAct 范式上叠加可插拔上下文管理、工具策略管道与异常重试，把单 Agent 的自主多步执行工程化。链路定位见 [[25.OpenClaw中用户消息从输入到回复的完整链路]]。
