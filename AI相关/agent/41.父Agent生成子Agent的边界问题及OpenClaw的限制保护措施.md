## 父 Agent 生成子 Agent 的边界问题及 OpenClaw 的限制保护措施

### 1. 边界问题：派生失控的风险

让父 Agent 能生成子 Agent 很强大，但若不加约束会失控：

| 边界问题 | 说明 |
| --- | --- |
| 无限递归 | 子 Agent 又生子 Agent，子子孙孙无穷尽，栈/图深度爆炸 |
| 资源耗尽 | 子 Agent 数量失控，token/CPU/内存/并发连接被吃光 |
| 权限放大 | 子 Agent 继承甚至超出父 Agent 权限，越权操作 |
| 上下文爆炸 | 子 Agent 结果回传过多，撑爆父 Agent 上下文 |
| 结果不可控 | 子 Agent 偏题/失败/死循环，父 Agent 被拖垮 |
| 死循环 | 父子互相派生或子 Agent 间循环引用（见 [[17.Agent死循环问题的解决方法]]） |

### 2. 通用限制方法

| 方法 | 思路 |
| --- | --- |
| 最大深度限制 | 限制派生层级（如最多 2~3 层） |
| 数量限制 | 限制同时存在的子 Agent 总数 |
| 资源配额 | 给每个子 Agent 设 token/时间预算 |
| 权限单调递减 | 子 Agent 权限不超过父 Agent |
| 生命周期回收 | 子 Agent 完成或超时自动回收 |

### 3. OpenClaw 的限制保护措施

OpenClaw 这类 Agent 框架的典型设计，在派生子 Agent 前过一道保护校验：

```
父 Agent 请求派生子 Agent
   │
   ├─① 深度校验：当前层级 < 最大深度？
   ├─② 数量校验：活跃子 Agent 数 < 上限？
   ├─③ 预算校验：剩余 token/资源预算充足？
   ├─④ 权限校验：子 Agent 权限 ⊆ 父 Agent 权限？
   ├─⑤ 工具集裁剪：子 Agent 只能拿到父工具集的子集
   └─ 通过 → 派生（带超时）；任一不通过 → 拒绝并回退
```

| 保护措施 | 说明 |
| --- | --- |
| 生成深度限制 | 设最大派生深度（如 3 层），超出直接拒绝 |
| 子 Agent 数量上限 | 限制单父/全局活跃子 Agent 数，防数量爆炸 |
| token / 资源预算 | 子 Agent 带 token 与时间预算，耗尽即终止 |
| 权限不超过父 Agent | 权限单调递减，子 Agent 不能调用父 Agent 没有的危险工具 |
| 超时自动回收 | 子 Agent 超时未完成强制终止，释放资源 |
| 结果大小限制 | 子 Agent 回传结果超阈值则压缩/摘要 |

> 工具权限分层控制见 [[37.Agent工具权限控制的设计及OpenClaw的工具策略管道分层]]，多 Agent 协作与子 Agent 支持见 [[40.多Agent协作的适用场景及OpenClaw对子Agent的支持方式]]。

### 4. 一句话总结

父 Agent 生成子 Agent 存在递归失控、资源耗尽、权限放大、上下文爆炸等边界风险；OpenClaw 这类框架通过**深度限制、数量上限、资源预算、权限单调递减、超时回收、结果大小限制**等措施在派生前校验拦截，保证多 Agent 派生可控、可回收、不越权。
