## RAG 系统召回结果与用户 query 意图不匹配的改进方向

召回结果与用户意图不匹配，是 RAG 最常见也最致命的问题——检索没找对，后面生成再强也是"基于错误证据的胡说"。改进要**按环节定位、对症下药**。

### 1. 原因分析：为什么不匹配

| 原因类别 | 具体表现 |
| --- | --- |
| query 表述差 | 口语化/省略/带指代/术语不对，直接检索拿不到 |
| embedding 领域不匹配 | 通用 embedding 模型对垂直术语理解差，语义对不上 |
| 切片不当 | 答案被切断、语义丢失、chunk 过大稀释相关性 |
| 缺查询理解 | 没做改写/扩展/路由，原始 query 一把梭 |
| 单一检索 | 只用向量或只用 BM25，语义或字面某一路必漏 |
| 无 Rerank | 粗召回结果排序粗糙，相关片段排不进 top-k |
| 意图误判 | 该走 SQL/图谱的走了向量，该检索的走了生成 |

### 2. 改进方向（按环节）

#### 查询侧：把 query 加工成"好检索的样子"

| 手段 | 作用 | 详见 |
| --- | --- | --- |
| Query Rewriting 查询改写 | 口语/省略/指代 → 完整规范表述 | [[43.RAG中Query Rewriting查询重写的定义及检索效果优化方法]] |
| Query Expansion 查询扩展 | 补同义词/相关词，扩大召回面 | [[06.查询扩展的定义及在RAG中的应用价值]] |
| Multi-Query 多查询 | 生成多个等价问法，多路检索后合并 | [[43.RAG中Query Rewriting查询重写的定义及检索效果优化方法]] |
| HyDE | 用 LLM 生成伪答案去检索，答案比问题更贴近文档表述 | [[04.详解RAG的完整工作流程]] |
| 意图识别/路由 | 判断走哪个知识库、是否转 Text-to-SQL/图谱 | [[04.详解RAG的完整工作流程]] |

#### 检索侧：让召回更全更准

| 手段 | 作用 | 详见 |
| --- | --- | --- |
| 混合检索 | 向量（懂语义）+ BM25（懂字面）多路召回融合 | [[03.混合检索的定义及在大模型应用中的核心作用]] |
| 领域微调 embedding | 用领域语料微调 embedding，提升术语语义匹配 | [[14.RAG中Embedding Model的选型因素及方法]] |
| 调切片策略 | 语义切片/父子文档/调 chunk_size，保语义完整 | [[11.RAG中常见分块策略及各自差异]] |
| 元数据过滤 | 按来源/时间预过滤，缩小范围提精度 | [[34.RAG系统利用元数据过滤提升检索精度的方法]] |
| 调 top-k | 召回量宁多勿少，交给后处理精筛 | [[42.RAG检索中Top-K的含义及K值的确定方法]] |

#### 后处理侧：把相关的排到前面

| 手段 | 作用 | 详见 |
| --- | --- | --- |
| Rerank 重排 | Cross-Encoder 对粗召回精排，相关片段顶到 top-k | [[02.RAG中Rerank的含义及实现方式]] |
| 阈值过滤 | 丢弃低相关片段，防噪声污染上下文 | [[02.RAG中Rerank的含义及实现方式]] |
| 去重/合并 | 多路召回去重，合并同源片段 | [[03.混合检索的定义及在大模型应用中的核心作用]] |

#### 评估侧：用数据驱动迭代

| 手段 | 作用 |
| --- | --- |
| 建评测集 | 标注 query-正确文档对，量化 recall@k / MRR / nDCG |
| 错例分析 | 对召回失败 case 归因（查询/检索/切片），定向优化 |
| A/B 对比 | 改一处比一组指标，避免盲调 |

### 3. 改进优先级建议

| 优先级 | 手段 | 理由 |
| --- | --- | --- |
| P0 | 混合检索 + Rerank | 工业标配，投入产出比最高，先补这两板斧 |
| P0 | 查询改写/扩展 | query 质量是源头，改动小收益大 |
| P1 | 切片优化 + 元数据过滤 | 地基性优化，影响全链路 |
| P1 | 评测集建设 | 没度量就没改进 |
| P2 | 领域微调 embedding | 成本高，前几步做完仍有瓶颈再上 |

> 若是"检索不到任何相关文档"，属于召回为零的极端情况，见 [[44.RAG检索不到相关文档的处理方案]]；若是"召回了但模型仍胡说"，见 [[27.RAG系统幻觉问题的实用解决方法]]。

### 4. 一句话总结

召回与意图不匹配要**按环节定位**：查询侧做改写/扩展/HyDE/路由把 query 加工好，检索侧上混合检索+领域 embedding+调切片保召回全，后处理侧用 Rerank+过滤排得准，评估侧建评测集驱动迭代——优先级是"混合检索+Rerank+查询改写"打头阵。
