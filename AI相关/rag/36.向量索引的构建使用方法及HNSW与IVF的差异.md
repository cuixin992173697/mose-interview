## 向量索引的构建、使用方法及 HNSW 与 IVF 的差异

### 1. 向量索引是什么

向量索引 = 为高维向量构建的**近似最近邻（ANN）数据结构**，让"在 N 个向量里找最相似的 K 个"从 O(N) 暴力遍历降到近似亚线性，支撑毫秒级检索。详见 [[21.向量数据库中ANN的定义及应用价值]]。

### 2. 构建与使用流程

```
建索引（选算法 + 调参数）→ 插入向量 → 查询（query 向量 + ANN 检索 + 调参）→ top-K
```

| 步骤 | 说明 |
| --- | --- |
| ① 选索引算法 | HNSW / IVF / LSH / PQ 等，按精度、速度、内存权衡（见 [[20.向量数据库中HNSW、LSH、PQ的含义]]） |
| ② 调建索引参数 | 不同算法参数不同，影响构建时间和索引质量 |
| ③ 插入向量 | 把 embedding 逐条/批量写入，构建索引结构 |
| ④ 查询检索 | query 向量化 → ANN 检索 top-K → 可配查询参数调精度/速度 |
| ⑤ 调查询参数 | 查询时参数（如 efSearch、nprobe）实时调，精度↑则速度↓ |

```python
# Milvus 示例：建 HNSW 索引 + 查询
collection.create_index("vector", {
    "index_type": "HNSW",
    "metric_type": "COSINE",
    "params": {"M": 16, "efConstruction": 200}
})
# 查询时调 efSearch
results = collection.search(data=[q], anns_field="vector",
    param={"params": {"efSearch": 64}}, limit=10)
```

### 3. HNSW vs IVF 核心差异

| 维度 | HNSW | IVF |
| --- | --- | --- |
| 原理 | 分层小世界图，相邻向量连边，逐层细化搜索 | K-means 聚类成 nlist 个桶，查询时只扫 nprobe 个最近桶 |
| 是否需训练 | ❌ 不需要 | ✅ 需要训练聚类中心 |
| 关键参数 | M（邻居数）、efConstruction（建图质量）、efSearch（查询精度） | nlist（聚类数）、nprobe（查询桶数） |
| 精度 | 高（图结构保邻近性） | 中（取决于 nprobe 覆盖） |
| 查询速度 | 快 | 快（nprobe 小时更快） |
| 内存 | 大（存图结构） | 小（只存聚类分配） |
| 构建速度 | 较慢（建图） | 训练+分配，较快 |
| 适合规模 | 中大规模、内存充足 | 大规模、内存敏感、可接受训练 |

### 4. 参数调优要点

**HNSW：**
- `M`：每层邻居数，↑ 召回↑内存↑，常用 8~48。
- `efConstruction`：建图候选数，↑ 索引质量↑构建慢，常用 100~500。
- `efSearch`：查询候选数，↑ 召回↑查询慢，常用 50~500，可运行时调。

**IVF：**
- `nlist`：聚类数，通常 √N 量级，过大训练慢、过小精度差。
- `nprobe`：查询扫描桶数，↑ 召回↑速度↓，运行时调，常用 1~nlist 的较小比例。

### 5. 选型建议

| 情况 | 推荐 |
| --- | --- |
| 追求高召回、内存够 | HNSW |
| 海量数据、内存敏感 | IVF（+PQ 量化进一步省内存） |
| 不能离线训练/数据频繁变 | HNSW |
| 要极致省内存可接受精度损失 | IVF_PQ |

### 6. 一句话总结

向量索引是 ANN 检索的核心：**HNSW 用分层图、无需训练、精度高但吃内存；IVF 用聚类倒排、需训练、省内存但精度靠 nprobe 调**——构建时选算法调建索引参数，查询时调查询参数在精度与速度间权衡。
