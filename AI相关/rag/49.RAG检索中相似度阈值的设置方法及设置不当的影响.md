## RAG 检索中相似度阈值的设置方法及设置不当的影响

### 1. 什么是相似度阈值

相似度阈值 = 检索召回后，按相似度分数过滤的**门槛**：相似度低于阈值的 chunk 直接丢弃，不送入生成上下文。

```
query → 检索 top-N → 按相似度分数过滤(≥ 阈值才保留) → top-K 进上下文 → 生成
```

它和 top-K 是两种不同的"截断"手段：

| 维度 | top-K（数量截断） | 相似度阈值（质量截断） |
| --- | --- | --- |
| 截断依据 | 排名，固定取前 K 个 | 分数，低于门槛一律丢 |
| 返回量 | 恒定 K 个 | 不定，可能 0~N 个 |
| 解决问题 | 控上下文长度/成本 | 控噪声、防"硬凑无关结果" |
| 典型配合 | 先 top-K 再阈值过滤，或先阈值过滤再 top-K | — |

> 实践中二者常组合：先 top-N 召回 → 相似度阈值过滤 → 再 top-K 精选（见 [[42.RAG检索中Top-K的含义及K值的确定方法]]）。

### 2. 设置方法

#### 方法一：基于评测集调参（推荐）

用标注好"相关 chunk"的评测集，统计相关 chunk 与无关 chunk 的相似度分数分布，找**分界点**作为阈值：

| 步骤 | 说明 |
| --- | --- |
| 跑评测集 | 对每个 query 检索，记录每个 chunk 的相似度分数及相关性标签 |
| 画分数分布 | 相关/无关 chunk 的分数分布曲线，看两者分离程度 |
| 选分界点 | 取分离最清晰的分数作为阈值（最大化召回-噪声差） |
| 回归验证 | 用 recall@k、precision@k 验证（见 [[09.RAG调优后效果评估的方法及实际应用中的评估标准]]） |

#### 方法二：看召回分数分布的分位数

无标注时，统计线上 query 的召回分数分布，取**分位数**（如 P10~P25）作为阈值——低于大多数召回分数的视为异常低相关。

#### 方法三：结合业务容忍度

不同业务对"漏召回"和"噪声"的容忍度不同：

| 业务类型 | 阈值倾向 | 理由 |
| --- | --- | --- |
| 高精度（法律/医疗/合规） | 偏高 | 宁可拒答，不容噪声误导 |
| 高召回（客服/百科问答） | 偏低 | 宁可多召回，避免答不上来 |
| 平衡型（通用知识库） | 中等 | 召回与精度兼顾 |

#### 方法四：分档 / 动态阈值

不设单一死阈值，而是按场景动态调整：

| 策略 | 说明 |
| --- | --- |
| 分档阈值 | 按文档类别/来源设不同阈值（权威源阈值低些，普通源阈值高些） |
| 动态阈值 | 按当前 query 召回分数分布动态定（如取本批召回均值-标准差） |
| 置信度分档 | 高分直接答、中分带引用答、低分拒答（见 [[44.RAG检索不到相关文档的处理方案]]） |

### 3. 设置不当的影响

| 阈值 | 后果 | 表现 |
| --- | --- | --- |
| 太高 | 漏召回 | 相关 chunk 被误杀，检索不到 → 拒答率↑、用户体验差 |
| 太高 | 上下文不足 | 留下的 chunk 太少，生成信息不全 |
| 太低 | 噪声混入 | 无关 chunk 进上下文 → 误导模型、幻觉↑（见 [[27.RAG系统幻觉问题的实用解决方法]]） |
| 太低 | 上下文污染 | 噪声稀释关键信息，lost-in-the-middle 加剧 |
| 太低 | token 浪费 | 无关内容占满上下文预算，成本↑ |

> 最危险的是**太低**：表面"检索到了"，实则塞了一堆噪声，模型被带偏还难溯源——比"检索不到"更隐蔽。

### 4. 与 top-K、Rerank、拒答机制的关系

| 机制 | 作用 | 与阈值的配合 |
| --- | --- | --- |
| top-K | 控数量 | 阈值过滤后若仍 >K，再 top-K 截断 |
| Rerank | 精排提精度 | 先 Rerank 重排，再按 Rerank 分数设阈值更准（见 [[02.RAG中Rerank的含义及实现方式]]） |
| 拒答机制 | 兜底 | 阈值过滤后无结果 → 触发拒答/降级检索，而非硬答 |
| 混合检索 | 召回 | 多路分数需归一化后再统一设阈值 |

> 用 Rerank 分数设阈值通常比用一阶段检索分数更可靠——Cross-Encoder 分数区分度更大。

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 分数归一化 | 不同检索器/距离度量分数量纲不同，设阈值前先归一化（余弦相似度已在 [-1,1]，相对好定） |
| 距离 vs 相似度 | 余弦相似度越大越相关（阈值设下限）；欧氏距离越小越相关（阈值设上限），别搞反 |
| 离线调+在线监控 | 离线用评测集定阈值，上线后监控拒答率/命中率，漂移则回调 |
| 不同 embedding 不同阈值 | 换 embedding 模型后分数分布会变，阈值需重调 |
| 阈值 + top-K 双保险 | 单靠任一都不稳，组合使用最鲁棒 |

### 6. 一句话总结

相似度阈值是检索结果的**质量闸门**：设置方法以"评测集分数分布找分界点"为主、结合业务容忍度与动态分档；太高会漏召回导致拒答，太低会放噪声导致幻觉——实践中与 top-K、Rerank、拒答机制组合使用，并随 embedding 更新回归重调。
