## 向量数据库的核心工作流程

向量数据库围绕"**建库 → 检索 → 维护**"运转，本质是一条 embedding 驱动的数据流。完整 RAG 流程见 [[04.详解RAG的完整工作流程]]，这里聚焦向量库自身。

### 1. 全景流程图

```
【建库（离线/写入）】
  原始文档 → 切片 → Embedding 向量化
            → 向量 + 原文 + 元数据
            → 写入向量库（建 ANN 索引 + 存元数据）

【检索（在线查询）】
  query → Embedding 向量化
        → ANN 检索（可选元数据过滤）
        → 返回 top-k（向量/原文/元数据/相似度分数）

【维护】
  增 / 删 / 改 → 增量更新索引 → 保持一致性
```

### 2. 建库流程

| 步骤 | 动作 | 说明 |
| --- | --- | --- |
| ① 数据准备 | 文档加载 + 切片 | 见 [[04.详解RAG的完整工作流程]] 切片环节 |
| ② 向量化 | 切片经 Embedding 模型编码 | 产出稠密向量，常用 768/1024/1536 维 |
| ③ 构造记录 | 组装 (向量, 原文, 元数据) 三元组 | 元数据含来源/页码/章节/时间/权限 |
| ④ 建 ANN 索引 | 选择 HNSW/IVF 等索引并构建 | 见 [[20.向量数据库中HNSW、LSH、PQ的含义]]、[[36.向量索引的构建使用方法及HNSW与IVF的差异]] |
| ⑤ 写入存储 | 向量+元数据落盘，索引持久化 | 支持分片（sharding）分布到多节点 |

### 3. 检索流程

| 步骤 | 动作 | 说明 |
| --- | --- | --- |
| ① query 向量化 | 用**同一** Embedding 模型编码查询 | 模型必须与建库一致，否则向量空间不对齐 |
| ② 元数据过滤（可选） | 按来源/时间/权限预过滤 | 缩小搜索范围，提精度保安全 |
| ③ ANN 检索 | 在索引上做近似最近邻搜索 | 返回 top-k 候选，见 [[21.向量数据库中ANN的定义及应用价值]] |
| ④ 相似度计算 | 用余弦/欧氏/内积打分 | 见 [[22.向量数据库中余弦相似度、欧几里得距离、曼哈顿距离的定义及差异]] |
| ⑤ 返回结果 | 返回候选向量对应的原文 + 元数据 + 分数 | 交给 RAG 的 Rerank/生成环节 |

```python
# Milvus 检索示例
results = collection.search(
    data=[query_vector],          # query 向量化结果
    anns_field="embedding",
    param={"metric_type": "COSINE", "params": {"ef": 64}},
    limit=10,                     # top-k
    expr='source == "hr_manual" and year >= 2023',  # 元数据过滤
    output_fields=["text", "source", "page"]
)
```

### 4. 维护：增删改

| 操作 | 说明 |
| --- | --- |
| 增量插入 | 新向量写入并挂到 ANN 索引（HNSW 支持在线插入；IVF 需周期性重训聚类） |
| 删除 | 标记删除（软删）或物理删除，部分索引需 compact 清理碎片 |
| 更新 | 删旧 + 插新（向量不可变，更新即重建该记录） |
| 索引重建 | 数据大量变更或参数调整后，全量重建索引以恢复性能 |

### 5. 与 RAG 的集成点

| RAG 环节 | 向量库的角色 |
| --- | --- |
| 离线索引 | 承载切片向量的存储与 ANN 索引（建库流程） |
| 在线检索 | 接收 query 向量，返回 top-k 片段（检索流程） |
| 元数据过滤 | 支持按来源/权限过滤，保障检索精度与数据安全 |
| 混合检索 | 向量库提供向量路，配合 BM25 全文检索做融合（见 [[03.混合检索的定义及在大模型应用中的核心作用]]） |

### 6. 关键机制

| 机制 | 说明 |
| --- | --- |
| 模型一致 | 建库与查询必须用同一 Embedding 模型，否则向量空间错位 |
| 索引-精度-速度三角 | 索引参数（ef_search/nprobe）在召回率与延迟间权衡 |
| 元数据即过滤力 | 元数据越规范，过滤检索越精准，安全可控 |
| 增量与一致性 | 在线写入需保证检索可见性与索引一致性 |
| 分布式扩展 | 分片 + 副本支撑水平扩展与高可用 |

向量库必要性及与传统库差异见 [[33.RAG中向量数据库的必要性及与传统数据库的差异]]，核心原理见 [[19.向量数据库的核心原理简述]]。

### 7. 一句话总结

向量库工作流程 = **离线"切片→embedding→建 ANN 索引+存元数据"建库，在线"query embedding→ANN 检索+元数据过滤→返回 top-k"查询，外加增删改维护索引一致性**；建库与查询必须用同一 embedding 模型，元数据过滤是精度与安全的杠杆。
