## RAG 的完整工作流程及核心步骤

> 本篇是核心步骤速览，便于快速串联全流程。每个环节的深入展开见 [[04.详解RAG的完整工作流程]]，RAG 定义与局限性见 [[01.简述RAG的定义及核心工作流程+局限性]]。

RAG 分 **离线建库** 和 **在线问答** 两大阶段，核心步骤如下：

```
【离线】 文档加载 → 切片 → 向量化 → 入库
【在线】 查询理解 → 检索 → Rerank → 上下文组装 → LLM 生成 → 溯源后处理
```

### 1. 离线建库（把知识变成可检索的向量库）

| 步骤 | 一句话 | 产出 |
| --- | --- | --- |
| ① 文档加载 | 解析 PDF/Word/HTML 等原始文档，还原结构、清洗、标注元数据 | 干净的结构化文档 |
| ② 切片 | 把长文档切成适合检索的小片段（chunk） | chunk 列表 |
| ③ 向量化 | 用 embedding 模型把每个 chunk 编码成稠密向量 | chunk 向量 |
| ④ 入库 | 向量 + 元数据存入向量库，建 ANN 索引（+全文索引支撑混合检索） | 可检索的知识库 |

### 2. 在线问答（检索 + 生成）

| 步骤 | 一句话 | 产出 |
| --- | --- | --- |
| ⑤ 查询理解 | 对用户 query 做改写/扩展/路由/指代消解，变成更利于检索的表述 | 优化后的 query |
| ⑥ 检索 | 向量检索 + 关键词检索多路召回，融合得候选片段 | top-N 候选 chunk |
| ⑦ Rerank | 用 Cross-Encoder 对候选精排，取最相关的 top-K | top-K 相关 chunk |
| ⑧ 上下文组装 | 把 top-K 片段 + 元数据 + query 拼成 Prompt（含压缩/排序） | 完整 Prompt |
| ⑨ LLM 生成 | 大模型基于上下文生成答案（可流式） | 候选答案 |
| ⑩ 溯源后处理 | 强制引用核对、安全过滤、缓存、评测 | 带引用的最终答案 |

### 3. 核心要点

| 要点 | 说明 |
| --- | --- |
| 检索是地基 | 召回质量决定生成上限，检索不到/检索噪声→幻觉，工业工程量集中于此 |
| 生成是出口 | 检索再准，Prompt 设计与模型能力也决定最终答案质量 |
| 离线/在线分离 | 建库离线做，问答在线做，知识更新不动模型 |
| 元数据贯穿 | 过滤、溯源、权限控制全靠元数据 |
| 评测驱动 | 用 recall@k/MRR/忠实度等指标量化迭代 |

### 4. 一句话总结

RAG 完整流程 = **离线"加载→切片→向量化→入库"四步建库 + 在线"查询理解→检索→Rerank→上下文组装→LLM 生成→溯源后处理"六步问答**，检索是地基、生成是出口，两者环环相扣。深入展开见 [[04.详解RAG的完整工作流程]]。
