## 简述 Advanced RAG 的核心内涵

### 1. 什么是 Advanced RAG
Advanced RAG = 在 Naive RAG（朴素 RAG：切片→向量化→检索→生成）基础上，对**检索前、检索中、检索后**各环节做系统性优化，解决 Naive RAG 检索不准、上下文噪声、幻觉等问题。

- 一句话：**Naive RAG 能跑，Advanced RAG 跑得准。**
- Naive RAG 基础见 [[01.简述RAG的定义及核心工作流程+局限性]]，完整流程见 [[04.详解RAG的完整工作流程]]。

### 2. 三阶段优化全景

| 阶段 | 环节 | 优化技术 |
| --- | --- | --- |
| Pre-retrieval（检索前） | 查询理解与改写 | 查询改写、查询扩展（见 [[06.查询扩展的定义及在RAG中的应用价值]]）、多查询生成、HyDE、查询路由、历史改写（指代消解） |
| Retrieval（检索中） | 多路召回 | 混合检索（向量+BM25，见 [[03.混合检索的定义及在大模型应用中的核心作用]]）、多路融合、元数据过滤 |
| Post-retrieval（检索后） | 结果精排与重组 | Rerank（见 [[02.RAG中Rerank的含义及实现方式]]）、提示压缩（见 [[08.提示压缩的定义及在RAG中的应用意义]]）、上下文去重与重排、lost-in-the-middle 优化 |

### 3. 各阶段优化详解

#### Pre-retrieval：把"烂问题"变"好问题"
用户问题往往口语化、带指代、过短或过泛，直接检索效果差。

| 技术 | 作用 |
| --- | --- |
| 查询改写 | 口语化→规范完整表述 |
| 查询扩展 | 补同义词/相关词，扩召回 |
| 多查询 | 生成多个等价问法，多路检索后融合 |
| HyDE | 用 LLM 生成伪答案去检索（答案比问题更接近文档表述） |
| 查询路由 | 按意图分发到不同知识库或 Text-to-SQL |
| 历史改写 | 多轮指代消解，还原实体 |

#### Retrieval：把"该召回的一个不漏"
| 技术 | 作用 |
| --- | --- |
| 混合检索 | 向量懂语义 + BM25 懂字面，互补 |
| 元数据过滤 | 先按来源/时间/权限过滤再相似度检索 |
| 多路召回 | 向量 + 关键词 + 图/SQL 多路融合 |

#### Post-retrieval：把"最相关的排前面、上下文最干净"
| 技术 | 作用 |
| --- | --- |
| Rerank | Cross-Encoder 精排，提精度 |
| 提示压缩 | 压缩冗余上下文，省 token |
| 去重重排 | 去重复片段，重要信息放首尾 |
| 上下文窗口管理 | token 预算内精选证据 |

### 4. 与 Naive RAG、Modular RAG 的对比

| 维度 | Naive RAG | Advanced RAG | Modular RAG |
| --- | --- | --- | --- |
| 核心思路 | 切片→检索→生成一条龙 | 在 Naive 基础上加前后优化 | 把 RAG 拆成可插拔模块重组 |
| 优化方式 | 无 | 对已有流程各环节增强 | 改架构，模块可替换/循环 |
| 复杂度 | 低 | 中 | 高 |
| 检索质量 | 一般 | 高 | 高且灵活 |
| 适用 | 快速验证、简单场景 | 工业主流 | 复杂定制、需高度灵活 |
| 与 Advanced 关系 | 基础 | 进阶 | 更进一步（见 [[18.简述Modular RAG的核心定义]]） |

### 5. 价值
- **提升检索精度**：查询改写 + 混合检索 + Rerank 三板斧，召回与精度双提升。
- **降低幻觉**：证据更准更全 + Prompt 约束 + 拒答策略。
- **工程可控**：各环节可独立优化与评测，迭代有抓手。
- **性价比高**：在不换大模型的前提下显著提升效果，是工业落地的主流形态。

### 6. 一句话总结
Advanced RAG 的核心内涵 = **在 Naive RAG 基础上，对"检索前（查询改写/扩展/路由/HyDE）→ 检索中（混合检索/多路召回）→ 检索后（Rerank/提示压缩/上下文重组）"全链路系统性优化**，是工业级 RAG 的主流形态，介于 Naive 与 Modular 之间。
