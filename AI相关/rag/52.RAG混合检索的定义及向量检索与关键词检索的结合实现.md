## RAG 混合检索的定义及向量检索与关键词检索的结合实现

> 本篇侧重"如何把向量检索与关键词检索结合落地 + 代码"。混合检索的定义、作用与融合策略对比见 [[03.混合检索的定义及在大模型应用中的核心作用]]。

### 1. 定义

混合检索 = **向量检索（稠密）+ 关键词检索（稀疏）多路并行召回，再融合结果**，取长补短。

```
                ┌─→ 向量检索（语义） ─┐
query → 改写/扩展 ┤                    ├→ 融合(RRF/加权) → top-K → [可选 Rerank] → 上下文
                └─→ BM25 检索（字面）─┘
```

| 检索路 | 擅长 | 短板 |
| --- | --- | --- |
| 向量检索（Embedding + ANN） | 语义相似、同义改写、泛化 | 精确词/专有名词/数字易漏 |
| 关键词检索（BM25/TF-IDF） | 精确词命中、专有名词、代码标识符 | 不懂同义、词面不匹配就召不到 |

### 2. 为什么结合

| 场景 | 单一方式的问题 | 结合后 |
| --- | --- | --- |
| 问"GPT-4 定价" | 向量可能漏掉字面 "GPT-4" | BM25 精确命中 |
| 问"大模型怎么微调" | BM25 召不到写"LLM"的文档 | 向量靠语义命中 |
| 数字/ID/SKU | 向量把数字语义化易混 | BM25 精确匹配 |

一句话：向量懂"意思"，关键词懂"字面"，混合让两者都上线（详见 [[03.混合检索的定义及在大模型应用中的核心作用]]）。

### 3. 结合实现步骤

| 步骤 | 说明 |
| --- | --- |
| ① 双索引并存 | 同一份文档切片既建向量索引（embedding 入向量库）又建全文索引（BM25 倒排），切片元数据一致 |
| ② 并行检索 | 同一 query 同时走向量检索与 BM25 检索，各召回 top-N |
| ③ 结果融合 | 用 RRF 或加权融合两路结果，去重排序，取 top-K |
| ④ 可选 Rerank | 对融合后的 top-K 用 Cross-Encoder 精排（见 [[02.RAG中Rerank的含义及实现方式]]） |
| ⑤ 进上下文 | 融合/精排后的 top-K chunk 拼进 Prompt 生成 |

### 4. 融合公式

#### RRF（Reciprocal Rank Fusion，工业最常用）

```
RRF_score(d) = Σ  1 / (k + rank_i(d))     # k 常取 60
```

- 只用排名，不用分数，**无需归一化**，对异构检索器鲁棒。

#### 加权融合

```
final_score = α * norm(dense_score) + (1-α) * norm(sparse_score)     # α 经验 0.5~0.7
```

- 需先把两路分数归一化（min-max/z-score），再加权。

| 融合方式 | 是否需归一化 | 适用 |
| --- | --- | --- |
| RRF | 否 | 异构检索器、分数不可比（默认首选） |
| 加权融合 | 是 | 检索器分数可靠可比时 |

### 5. 代码示例（LangChain）

用 `EnsembleRetriever` 组合向量检索器与 BM25 检索器，自动做加权融合：

```python
from langchain_community.retrievers import BM25Retriever
from langchain_community.vectorstores import FAISS
from langchain.retrievers import EnsembleRetriever
from langchain_openai import OpenAIEmbeddings

# 1. 文档切片（双索引共用同一批 chunks）
chunks = text_splitter.split_documents(docs)

# 2. 向量索引（稠密）
vectorstore = FAISS.from_documents(chunks, OpenAIEmbeddings())
vector_retriever = vectorstore.as_retriever(search_kwargs={"k": 20})

# 3. BM25 索引（稀疏）
bm25_retriever = BM25Retriever.from_documents(chunks)
bm25_retriever.k = 20

# 4. 混合检索：加权融合（向量 0.6 + BM25 0.4）
hybrid_retriever = EnsembleRetriever(
    retrievers=[vector_retriever, bm25_retriever],
    weights=[0.6, 0.4],
)

# 5. 检索（LangChain 内部已做加权融合）
results = hybrid_retriever.invoke("GPT-4 的定价是多少？")
```

> 进阶：在 EnsembleRetriever 之后接 `ContextualCompressionRetriever` + Reranker 做精排，进一步提升精度。

向量库侧的混合检索（如 Milvus 2.4+ 内置稀疏向量、Weaviate/Elasticsearch 原生支持混合查询）也可在后端一次查询完成融合，无需应用层手动合并。

### 6. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 切片元数据一致 | 双索引必须基于同一批 chunks，元数据（来源/页码）一致，否则溯源错乱 |
| 权重调参 | α/weights 需基于评测集调（看 recall@k/MRR），不同业务最优值不同 |
| 召回量 | 两路各 top-N（如 20~50），融合后取 top-K（如 5~10） |
| 与 Rerank 配合 | 混合检索做宽召回，Rerank 做精排序，工业标配组合拳 |
| 增量同步 | 新文档要同时增量入向量索引与 BM25 索引，双路同步 |
| 分数归一化 | 用加权融合时务必先归一化，否则量纲大的检索器压制另一方 |

### 7. 一句话总结

混合检索的落地 = **双索引并存（向量库 + BM25 全文索引）→ 同一 query 并行检索 → RRF/加权融合去重 → 可选 Rerank 精排**；LangChain 里用 `EnsembleRetriever` 组合向量与 BM25 检索器即可实现，是工业级 RAG 兼顾语义与字面召回的标配方案，定义与作用详见 [[03.混合检索的定义及在大模型应用中的核心作用]]。
