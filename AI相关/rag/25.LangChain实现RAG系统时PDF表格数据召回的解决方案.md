## LangChain 实现 RAG 系统时 PDF 表格数据召回的解决方案

PDF 表格是 RAG 的老大难：解析难、向量化丢失结构、表格内答案召回不到。本篇给出一套从解析到检索的工程化方案。文档解析通用方法见 [[15.RAG索引流程中文档解析的实现方式]]，LangChain RAG 整体实现见 [[41.RAG的定义及基于LangChain的RAG应用实现]]。

### 1. 问题：为什么 PDF 表格召回难

| 难点 | 表现 |
| --- | --- |
| 解析丢失结构 | PDF 表格是定位坐标，普通文本抽取把表格拆成乱序文字，行列关系全丢 |
| 向量化丢失结构 | 表格转成纯文本后 embedding，结构信息消失，语义模糊 |
| 切片切断表格 | 表格被切到两个 chunk，查询时只召回到半张表 |
| 召回不到表内答案 | 答案是表格里的某个数值，关键词/向量都难精准命中 |
| 数字/单位易混 | 表格多数字 ID/金额，向量检索把数字语义化易混淆 |

### 2. 解决方案（六板斧）

#### ① 表格专用解析

用专门识别表格结构的解析器，而非纯文本抽取：

| 工具 | 特点 |
| --- | --- |
| pdfplumber | Python，基于规则识别线框表格，准确度高 |
| Camelot | 基于流/线框两种模式，输出 DataFrame |
| Unstructured | 通用文档解析，自动识别表格/标题/列表，LangChain 原生支持 |
| PyMuPDF(fitz) | 速度快，可结合自定义逻辑抽表格 |

#### ② 表格结构化为可检索文本

把识别出的表格转成**保留结构、利于检索**的格式：

- **Markdown 表格**：行列关系清晰，embedding 后语义完整，LLM 也好读。
- **键值/JSON**：每行转成 `字段: 值` 的自然语言，适合精确字段查询。
- **长表降维**：超宽表转成多行 `键值对` 文本，便于向量化。

```
原始表格：
| 产品 | 价格 | 库存 |
| GPT-4 | $0.03 | 100 |

结构化为：
"产品 GPT-4 的价格为 $0.03，库存为 100。"
```

#### ③ 表格单独切片 + 生成文字摘要

- 表格作为独立 chunk，不被切断。
- 用 LLM 给每张表生成**自然语言摘要**，摘要和表格分别向量化、互相关联（父子文档思路）。
- 检索命中摘要 → 回填完整表格进上下文。

#### ④ Text-to-SQL 路由结构化查询

对强结构化查询（"XX 产品的库存是多少"），路由到 Text-to-SQL 直接查结构化表，绕过向量检索：

| 路径 | 适用 |
| --- | --- |
| 向量检索 | 模糊语义查询、表格描述类问题 |
| Text-to-SQL | 精确字段/聚合/筛选查询（库存、总额、排名） |

#### ⑤ 表格 + 文字混合检索

表格文本既建向量索引又建 BM25 全文索引，混合检索融合（见 [[03.混合检索的定义及在大模型应用中的核心作用]]），兼顾语义与字面（数字/型号精确命中）。

#### ⑥ Rerank 精排

对含表格的召回结果用 Cross-Encoder 精排，把真正相关表格顶到 top-k（见 [[02.RAG中Rerank的含义及实现方式]]）。

### 3. LangChain 实现

| 环节 | LangChain 组件 |
| --- | --- |
| 加载 PDF | `PyMuPDFLoader` / `UnstructuredPDFLoader`（后者自动识别表格） |
| 表格处理 | 自定义解析 + 转 Markdown，或用 `Unstructured` 的 Table 元素 |
| 切片 | `MarkdownHeaderTextSplitter` 按标题切；表格整体保留为独立 chunk |
| 父子文档 | `MultiVectorRetriever`：用摘要检索，回填完整表格 |
| 检索 | `EnsembleRetriever` 混合向量 + BM25 |
| 生成 | `RetrievalQA` / LCEL 链 |

```python
from langchain_community.document_loaders import UnstructuredPDFLoader
from langchain_text_splitters import MarkdownHeaderTextSplitter
from langchain.retrievers import MultiVectorRetriever
from langchain.storage import InMemoryStore

# 1. 加载并识别表格（Unstructured 会把表格标为 Table 元素）
docs = UnstructuredPDFLoader("report.pdf", strategy="hi_res").load()

# 2. 表格转 Markdown + 生成摘要（父子文档）
import llm  # 你的 LLM
parent_store = InMemoryStore()            # 存完整表格(父)
child_vectors = []                        # 摘要向量(子)
for doc in docs:
    if doc.metadata.get("category") == "Table":
        table_md = doc.page_content       # 已结构化的 markdown 表格
        summary = llm.summarize(table_md) # LLM 生成摘要
        doc_id = hash(table_md)
        parent_store.mset([(str(doc_id), table_md)])
        child_vectors.append((summary, doc_id))

# 3. MultiVectorRetriever：摘要检索 → 回填完整表格
retriever = MultiVectorRetriever(
    vectorstore=vectorstore,              # 存摘要向量
    docstore=parent_store,                # 存完整表格
    id_key="doc_id",
)

# 4. 混合检索（向量 + BM25）+ Rerank 视情况叠加
from langchain.retrievers import EnsembleRetriever
hybrid = EnsembleRetriever(
    retrievers=[retriever, bm25_retriever], weights=[0.6, 0.4]
)
```

### 4. 方案选型建议

| 场景 | 推荐组合 |
| --- | --- |
| 表格少、结构简单 | pdfplumber 转 Markdown + 向量检索 |
| 表格多、需精确字段查询 | 结构化入库 + Text-to-SQL 路由为主，向量检索兜底 |
| 表格+大段文字混合 | Unstructured 解析 + 父子文档 + 混合检索 + Rerank |
| 扫描件表格 | OCR（PaddleOCR/Tesseract）→ 结构化 → 同上 |

### 5. 一句话总结

PDF 表格召回难在"结构丢失"，解法是**专用解析器抽表格 → 结构化为 Markdown/键值 → 父子文档（摘要检索+回填整表）→ Text-to-SQL 路由精确查询 → 混合检索+Rerank 精排**；LangChain 里用 Unstructured loader + MultiVectorRetriever + EnsembleRetriever 落地。
