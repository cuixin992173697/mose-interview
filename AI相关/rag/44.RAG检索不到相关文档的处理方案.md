## RAG 检索不到相关文档的处理方案

### 1. 场景与原因

RAG 在线问答时，检索阶段可能"什么都召不回"或"召回结果与问题无关"。常见原因：

| 原因类别 | 具体表现 | 根因 |
| --- | --- | --- |
| query 超出知识库范围 | 用户问的知识库里根本没有 | 知识覆盖不足 |
| query 表述问题 | 口语化/指代/与文档表述不一致 | 查询理解缺失（见 [[43.RAG中Query Rewriting查询重写的定义及检索效果优化方法]]） |
| Embedding 领域不匹配 | 通用模型在垂直领域语义对不齐 | 模型选型/微调问题（见 [[14.RAG中Embedding模型的选型因素及方法]]） |
| 切片不当 | 答案被切断或语义丢失 | 切片策略问题（见 [[10.RAG中分块的定义及分块的必要性]]） |
| 过滤过严 | 元数据过滤把正确 chunk 滤掉了 | 过滤条件设置不当 |
| 检索方式单一 | 纯向量检索漏掉字面命中文档 | 缺混合检索（见 [[03.混合检索的定义及在大模型应用中的核心作用]]） |
| 相似度阈值过高 | 阈值卡掉了本应召回的结果 | 阈值设置不当 |

### 2. 处理方案（按优先级）

#### 方案一：查询改写 / 扩展重试

第一召回收空时，先尝试改写或扩展 query 再检索一次：

| 手段 | 说明 |
| --- | --- |
| Query Rewriting | 改写成更贴近文档的表述（见 [[43.RAG中Query Rewriting查询重写的定义及检索效果优化方法]]） |
| Query Expansion | 补同义词/相关词扩大召回面（见 [[06.查询扩展的定义及在RAG中的应用价值]]） |
| Multi-Query | 生成多个等价问法并行检索 |
| HyDE | 用假设答案去检索，绕开 query-文档表述差异 |

#### 方案二：降级检索（放宽约束）

把第一轮过严的约束松开，扩大召回面：

| 降级动作 | 说明 |
| --- | --- |
| 放宽元数据过滤 | 去掉或放宽时间/来源/权限等过滤条件 |
| 调大 K | 把 top-K 调大，给更多候选机会（见 [[42.RAG检索中Top-K的含义及K值的确定方法]]） |
| 降低相似度阈值 | 让分数稍低的结果也能进入候选 |
| 换检索方式 | 纯向量检索失败时改试 BM25，或反之 |

#### 方案三：多路 / 混合检索

单路检索天然有盲区，切换或叠加多路：

- 向量 + BM25 混合检索（RRF 融合），见 [[03.混合检索的定义及在大模型应用中的核心作用]]。
- 叠加 Text-to-SQL / 图检索等结构化检索。

#### 方案四：HyDE 假设答案检索

query 与文档表述差异大时，先让 LLM 假设答案，用伪答案检索（见 [[43.RAG中Query Rewriting查询重写的定义及检索效果优化方法]]）。

#### 方案五：诚实拒答（避免幻觉的关键）

若上述手段仍召回不到相关文档，**应明确告知用户"库内无相关内容"，而非让模型编造**：

| 做法 | 说明 |
| --- | --- |
| 检索结果为空 | 直接返回"未在知识库中找到相关内容" |
| 相似度均低于阈值 | 视为无可靠证据，拒答 |
| Prompt 约束 | 明确要求"上下文中没有的信息就说不知道"（见 [[27.RAG系统幻觉问题的实用解决方法]]） |

> 这是 RAG 防幻觉的底线：宁可说"不知道"，也不要无依据地编。

#### 方案六：引导用户

拒答的同时给出建设性引导，提升下一次命中：

- 建议换种问法 / 补充关键信息（时间、实体、领域）。
- 列出知识库覆盖的主题范围，帮用户对齐预期。

#### 方案七：记录未命中 query，反哺知识库

把未命中的 query 落库分析：

| 用途 | 说明 |
| --- | --- |
| 知识缺口发现 | 高频未命中主题 = 知识库应扩充的方向 |
| 切片/索引优化 | 针对性补文档、调切片、调 embedding |
| 评测反哺 | 作为评测集负样本，检验拒答能力 |

#### 方案八：谨慎兜底到通用知识

某些场景（如通用助手）可在库内无果时，兜底到模型自身的通用知识，但**必须明确标注来源区别**，避免把"模型猜测"伪装成"库内证据"：

- 标注"以下内容来自模型通用知识，未经知识库验证"。
- 高严谨场景（医疗/法律/金融）应直接禁用此兜底，强制拒答。

### 3. 处理流程总览

```
原始 query 检索
   ├── 有相关结果 → 正常生成（带溯源）
   └── 无相关结果
         ├── 改写/扩展重试（Multi-Query / HyDE）
         │     ├── 命中 → 生成
         │     └── 仍未命中
         │           ├── 降级检索（放宽过滤 / 调大 K / 换方式 / 混合检索）
         │           │     ├── 命中 → 生成（标注置信度）
         │           │     └── 仍未命中
         │           │           ├── 诚实拒答 + 引导用户
         │           │           ├── （可选）谨慎兜底通用知识 + 标注来源
         │           │           └── 记录 query 反哺知识库
```

### 4. 与"召回结果意图不匹配"的区别

| 场景 | 区别 | 关联文档 |
| --- | --- | --- |
| 召回为空/无关（本篇） | 根本没拿到相关文档 | [[44.RAG检索不到相关文档的处理方案]] |
| 召回了文档但与意图不匹配 | 拿到了文档，但理解错意图/排序差 | [[24.RAG系统召回结果与用户query意图不匹配的改进方向]] |

二者常交织：意图不匹配严重时表现为"召回了但没用"，可先走本篇的改写/降级/混合检索，再按意图匹配方向优化排序与 Rerank。

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 阈值与兜底策略前置 | 上线前定好相似度阈值、重试次数、兜底与否，别让模型临场决定 |
| 拒答体验 | 拒答要友好 + 引导，而非冷冰冰"无结果" |
| 未命中监控 | 跟踪未命中率、未命中主题分布，驱动知识库扩充 |
| 严格场景禁兜底 | 医疗/法律/金融等高严谨场景，强制拒答，禁用通用知识兜底 |
| 全链路溯源 | 即使兜底，也要让用户能区分"库内证据"与"模型猜测"（见 [[28.RAG系统中信息来源标注与引用的实现方式]]） |

### 6. 一句话总结

RAG 检索不到文档时的标准应对 = **先查询改写/扩展重试 → 再降级检索/混合检索/HyDE 兜一圈 → 仍无果则诚实拒答并引导用户、记录 query 反哺知识库，必要时谨慎兜底通用知识但必须标注来源**；核心原则是"宁可说不知道，也不无依据地编"，这是 RAG 区别于纯大模型、抑制幻觉的底线（见 [[27.RAG系统幻觉问题的实用解决方法]]）。
