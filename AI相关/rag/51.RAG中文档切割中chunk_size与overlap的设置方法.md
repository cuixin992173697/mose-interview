## RAG 中文档切割中 chunk_size 与 overlap 的设置方法

> chunk_size 和 overlap 是文档切片的两个核心参数，直接决定召回质量。切片策略的选择见 [[11.RAG中常见分块策略及各自差异]]，分块必要性见 [[10.RAG中分块的定义及分块的必要性]]。

### 1. 两个核心参数

| 参数 | 定义 | 作用 |
| --- | --- | --- |
| chunk_size | 每个切片的长度（按 token 或字符计） | 决定单个 chunk 的信息量与检索粒度 |
| overlap | 相邻切片之间的重叠长度 | 避免语义在切片边界被切断 |

```
|<--- chunk_size --->|<-overlap->|
        chunk A        |===重叠===|
                       |<--- chunk_size --->|
                            chunk B
```

### 2. chunk_size 的设置

#### 考虑因素

| 因素 | 说明 |
| --- | --- |
| Embedding 最大输入 | 不能超过 embedding 模型的最大 token 上限（如 512/8192） |
| 内容密度 | 语义密集的文本可小些，稀疏的可大些 |
| 检索粒度 | 小 chunk 定位精准，大 chunk 上下文更全 |
| 生成上下文预算 | chunk_size × top-K 不能超 LLM 上下文窗口 |
| embedding 效果 | embedding 对短文本语义更聚焦，长文本语义被稀释 |

#### 典型值与影响

| chunk_size | 影响 |
| --- | --- |
| 太大（如 >1024 token） | 语义稀释（向量不聚焦）、单个 chunk 命中后塞入过多无关内容、token 成本高 |
| 太小（如 <128 token） | 上下文碎片化、跨段信息丢失、chunk 数量爆炸、存储与检索开销增 |
| 典型值 | **256~512 token**（通用经验起步值） |

> 经验：chunk_size 应让单个 chunk 尽量"讲清一件事"——太小讲不完，太大讲多件事稀释语义。

### 3. overlap 的设置

#### 作用

防止关键信息恰好被切在两个 chunk 的边界上，导致任一单独 chunk 语义不完整、检索不到。

```
无 overlap：...RAG 的核心是检索|生成...   ← "检索生成"被切断，两个 chunk 都讲不清
有 overlap：...RAG 的核心是检索生成|...检索生成是...  ← 边界信息在两个 chunk 都有
```

#### 典型值与影响

| overlap | 影响 |
| --- | --- |
| 太大（如 >30%） | 冗余存储、同一信息重复召回挤占 top-K、成本增 |
| 太小（如 0~5%） | 边界语义丢失，切断关键信息 |
| 典型值 | **10%~20%**（如 chunk_size=512 时 overlap=50~100） |

> overlap 不必等于"一句话长度"，能覆盖一个完整语义单元（一句话/一个短段）即可。

### 4. 设置方法

#### 方法一：评测调参（推荐）

固定其他变量，扫描 chunk_size（如 128/256/512/1024）× overlap（如 0/10%/20%），用评测集跑 **Recall@k / MRR**，选最优组合：

| 步骤 | 说明 |
| --- | --- |
| 建评测集 | 标注 query 与对应相关 chunk |
| 网格扫描 | 遍历 chunk_size × overlap 组合建索引、检索 |
| 看指标 | 对比 Recall@k/MRR，选拐点（见 [[09.RAG调优后效果评估的方法及实际应用中的评估标准]]） |
| 回归生成 | 验证最终答案准确率，避免只优化检索 |

#### 方法二：按文档类型/问答类型调整

| 场景 | chunk_size | overlap | 理由 |
| --- | --- | --- | --- |
| FAQ/短问答 | 小（128~256） | 小（10%） | 答案短，精准定位 |
| 长文档/深度问答 | 大（512~1024） | 中（15%） | 需要上下文连贯 |
| 代码/函数 | 按函数边界 | 0 | 函数是天然语义单元，不切断 |
| 法律/条款 | 按条款边界 | 小 | 条款独立完整 |
| 表格/结构化 | 整表为一个 chunk | 0 | 表格不可切断 |

#### 经验起步值表

| 文档类型 | chunk_size | overlap |
| --- | --- | --- |
| 通用文本 | 512 token | 50~100 token（~10-20%） |
| 短文本/FAQ | 256 token | 25~50 token |
| 长文档/技术文档 | 512~1024 token | 100 token |
| 代码 | 按函数 | 0 |

### 5. 参数联动与陷阱

| 要点 | 说明 |
| --- | --- |
| chunk_size 与 top-K 联动 | chunk_size 大则 top-K 要小（控上下文总量）；chunk_size 小则 top-K 可大 |
| 与 embedding 模型匹配 | 换 embedding 模型后最优 chunk_size 可能变，需重调 |
| 切分符优先级 | 优先按标题/段落/句子边界切，再在边界内凑 chunk_size，而非硬按字符切（语义切片，见 [[11.RAG中常见分块策略及各自差异]]） |
| overlap 不能替代语义切片 | overlap 只是边界补救，根本上还是要按语义边界切 |
| 父子文档解耦 | 检索用小 chunk（精准），生成回填大 chunk（完整），可绕开 chunk_size 两难（见 [[11.RAG中常见分块策略及各自差异]]） |

### 6. 一句话总结

chunk_size 决定"每个切片多大"（典型 256~512 token，太大语义稀释、太小上下文碎片），overlap 决定"相邻切片重叠多少"（典型 10%~20%，防边界丢信息）；设置以评测集调参为主、按文档类型调整，并注意与 top-K、embedding 模型、切分符优先级联动——本质上是在"检索精度"与"上下文完整"之间找平衡。
