## RAG 中 Rerank 的含义及实现方式

### 1. 什么是 Rerank（重排）

Rerank = 对第一阶段检索召回的候选结果，用更精细的模型**重新打分排序**，把真正相关的片段排到前面。

它出现在两阶段检索架构的"第二阶段"：

```
查询 → 一阶段检索（召回 top-N，快但粗）→ Rerank（精排 top-K，慢但准）→ 拼进 Prompt
```

| 阶段 | 目标 | 典型方法 | 返回量 | 速度 |
| --- | --- | --- | --- | --- |
| 一阶段召回（Retrieve） | 高召回率，先把可能的捞回来 | 向量检索 / BM25 / 混合检索 | top-N（如 50~100） | 快（毫秒级） |
| 二阶段重排（Rerank） | 高精度，把最相关的排前面 | Cross-Encoder 交叉编码 | top-K（如 5~10） | 慢（N 次 forward） |

### 2. 为什么需要 Rerank

一阶段向量检索用的是 **双塔模型（Bi-Encoder）**：问题和文档各自编码成向量，靠余弦相似度匹配。

- 优点：文档可离线预编码，检索时只算一次问题向量 + 近似最近邻（ANN），极快。
- 缺点：问题和文档**独立编码**，没法捕捉两者的细粒度交互，语义匹配精度有限。

Rerank 用 **交叉编码器（Cross-Encoder）**：把 `[问题, 文档]` 拼一起送进模型，能建模两者的交互，精度高得多，但每对都要跑一次 forward，没法预计算，所以只能用在候选量小的第二阶段。

| 维度 | Bi-Encoder（一阶段） | Cross-Encoder（Rerank） |
| --- | --- | --- |
| 输入 | 问题、文档分别编码 | 问题+文档拼接后联合编码 |
| 交互 | 无（靠向量距离） | 全交互，精度高 |
| 预计算 | 文档向量可离线存 | 不可，每次实时算 |
| 速度 | 快，支持 ANN 检索 | 慢，逐条 forward |
| 角色 | 召回（高 recall） | 精排（高 precision） |

> 经典比喻：Bi-Encoder 是"先粗筛简历"，Cross-Encoder 是"再逐份细看面试"。粗筛要快（量大），细看要准（量小）。

### 3. Rerank 的实现方式

#### 方式一：Cross-Encoder 模型重排（主流）

用专门的 rerank 模型对每个候选 `[query, doc]` 打相关性分数，按分数重排取 top-K。

- 常见模型：`bge-reranker`、`Cohere Rerank`、`jina-reranker`、`ms-marco-MiniLM` 等。
- 调用形式（以 bge-reranker-large 为例）：把 query 和每个候选 doc 拼成 pair，模型输出一个相关性 logits，比较大小即可。

```python
from FlagEmbedding import FlagReranker
reranker = FlagReranker('BAAI/bge-reranker-large', use_fp16=True)
pairs = [[query, doc] for doc in candidates]
scores = reranker.compute_score(pairs)   # 每个候选一个分数
top_k = [doc for _, doc in sorted(zip(scores, candidates), reverse=True)[:5]]
```

#### 方式二：LLM 作为 Reranker

直接让大模型判断相关性：给一批候选片段，让它输出"哪些与问题最相关，按相关度排序"。

- 优点：无需额外训练，零样本，能理解复杂语义。
- 缺点：贵、慢，候选多时上下文膨胀；适合候选量小或对精度要求极高的场景。
- 常见范式：`Listwise Rerank`（让 LLM 对整个列表排序）、`Pairwise`（两两比较）、`Score-based`（打分）。

#### 方式三：传统特征 / 规则重排

用规则特征对召回结果二次加权，常作为补充而非主力：

- BM25 分数、关键词命中数、字段权重（标题命中 > 正文命中）。
- 时间衰减（新文档加分）、来源权重、业务规则。

#### 方式四：多模型融合重排

把多个 reranker 的分数归一化后加权融合（如 RRF——Reciprocal Rank Fusion），兼顾不同模型的优势。

### 4. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 候选量配比 | 召回 top-N（50~100）→ Rerank 取 top-K（3~10），N 太大重排慢，太小丢召回 |
| 模型选型 | 中文优先 bge-reranker；英文可用 Cohere / ms-marco；精度要求高上 large 版 |
| 批处理与 GPU | Cross-Encoder 逐条算，务必 batch + GPU，否则延迟难接受 |
| 阈值过滤 | 不只取 top-K，还可按分数阈值丢弃低相关片段，避免噪声进上下文 |
| 与混合检索配合 | 混合检索负责"召回全"，Rerank 负责"排得准"，二者互补是工业标配（见 [[03.混合检索的定义及在大模型应用中的核心作用]]） |
| 缓存 | 相同 query 的 rerank 结果可缓存，热点问题命中率高 |

### 5. 一句话总结

Rerank 是 RAG 检索的"精排层"：**用 Cross-Encoder（或 LLM）对粗召回结果做交叉打分，把最相关的片段顶到前面**，弥补向量检索精度不足的问题。它和混合检索是工业级 RAG 提升召回质量的两板斧。
