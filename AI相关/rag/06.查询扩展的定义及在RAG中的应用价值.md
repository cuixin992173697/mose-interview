## 查询扩展的定义及在 RAG 中的应用价值

### 1. 什么是查询扩展（Query Expansion）

查询扩展 = 在用户原始 query 的基础上，**补充或生成更多相关的检索词/检索语句**，用扩展后的 query 集合去检索，再合并结果。

它和"检索"是两个阶段：扩展发生在检索之前，目的是让检索"撒的网更大"。

```
原始 query → 扩展（补同义词/生成多问法/伪答案）→ 多路检索 → 结果融合
```

| 概念 | 操作对象 | 目标 |
| --- | --- | --- |
| 查询扩展 | 在原 query 上**加内容**（同义词、相关词、等价问法） | 扩大召回面，提升 recall |
| 查询改写 | 把原 query **换一种表述** | 让表述更利于检索，修正口语化/指代 |

> 二者常配合使用，区别见文末。查询改写详见 [[43.RAG中Query Rewriting查询重写的定义及检索效果优化方法]]。

### 2. 为什么需要查询扩展

用户原始 query 往往"短、口语化、词面单一"，直接检索召回率低：

| 问题 | 表现 | 扩展如何补救 |
| --- | --- | --- |
| 词面窄 | 只有一个关键词，语义覆盖不全 | 补同义词/相关词扩大命中面 |
| 同义表述遗漏 | 文档里写"大模型"，用户问"LLM"，词面不匹配 | 扩展出 "LLM/大语言模型/基础模型" |
| 单一问法召回偏 | 一种问法只命中一类文档 | 多等价问法多路召回再融合 |
| 口语化/省略 | "那个怎么用" 检索不到 | 扩展补全实体与意图 |

一句话：**用户问得窄，但知识库表述多样——扩展负责把"问法"对齐"写法"。**

### 3. 实现方式

#### 方式一：同义词词典扩展

用人工/领域词典给 query 补同义词、相关词，拼成扩展 query。

- 优点：可控、快、零成本调用。
- 缺点：词典维护成本高、覆盖不全、跨领域差。
- 适合：术语稳定的垂直领域（医疗、法律、金融）。

#### 方式二：LLM 生成扩展词

让大模型基于原 query 生成多个相关检索词或等价问法：

```
Prompt: 请基于用户问题生成 5 个语义相关的检索关键词，用于知识库召回。
用户问题：{query}
输出：词1, 词2, 词3, 词4, 词5
```

- 优点：泛化强、零样本、覆盖同义与相关表述。
- 缺点：多一次 LLM 调用，增加延迟与成本；可能扩展偏题。

#### 方式三：Multi-Query（多查询生成）

让 LLM 把原 query 改写成多个**等价问题**，每个独立检索后合并去重：

```python
# LangChain MultiQueryRetriever 思路
queries = llm.generate_alternatives(user_query)   # 生成 N 个等价问法
docs = []
for q in queries:
    docs += vectorstore.similarity_search(q, k=5)
docs = dedupe(docs)                                # 合并去重
```

- 优点：召回最全，是工业 RAG 提 recall 的常用招。
- 缺点：N 倍检索开销，需控制 N（通常 3~5）。

#### 方式四：HyDE（Hypothetical Document Embeddings）

先让 LLM 针对原 query **假设一个答案**，再用这个"伪答案"去做向量检索：

```
query → LLM 生成假设答案（伪文档）→ 用伪文档向量去检索 → 召回真实片段
```

- 直觉：答案的表述比问题更接近文档表述，向量更对齐。
- 适合：问题短而抽象、文档表述具体的场景。
- 风险：LLM 幻觉生成的伪答案可能带偏检索。

#### 方式五：伪相关反馈（Pseudo-Relevance Feedback, PRF）

第一轮检索拿到 top-k 后，从这些"假设相关"的文档里**抽取高频词/重要词**，加回 query 再检索一轮：

```
query → 检索 top-k → 抽取高频词扩展 query → 再检索 → 最终结果
```

- 优点：无需 LLM，基于检索结果自适应扩展。
- 缺点：若首轮召回差，扩展词也会跑偏（错误放大）。

### 4. 应用价值

| 价值 | 说明 |
| --- | --- |
| 提升召回率 | 多问法/多关键词覆盖更多相关文档，recall↑ |
| 对齐同义表述 | 解决"问法≠写法"的词面不匹配问题 |
| 弥补 embedding 短板 | 单一向量检索对短 query 语义模糊，扩展后更稳 |
| 支撑多路融合 | 扩展出的多 query 天然适配混合检索 + RRF 融合 |
| 降低幻觉 | 召回更全 → 上下文证据更充分 → 生成更可靠 |

### 5. 查询扩展 vs 查询改写

| 维度 | 查询扩展（Expansion） | 查询改写（Rewriting） |
| --- | --- | --- |
| 操作 | 加词/加 query（1→N） | 换表述（1→1，或 1→更好的 1） |
| 目标 | 扩大召回面（recall） | 修正表述、对齐检索（precision + recall） |
| 典型 | Multi-Query、HyDE、同义词 | 指代消解、口语转书面、补全省略 |
| 关系 | 常在改写之后再做扩展 | 常作为扩展的前置步骤 |

> 召回结果与意图不匹配的整体改进方向见 [[24.RAG系统召回结果与用户query意图不匹配的改进方向]]。

### 6. 一句话总结

查询扩展 = **在原 query 上补同义词/生成多等价问法/伪答案，多路召回再融合**，用来扩大检索覆盖面、提升召回率，是 RAG 提升 recall 的关键手段，常与查询改写、混合检索、Rerank 配合使用。
