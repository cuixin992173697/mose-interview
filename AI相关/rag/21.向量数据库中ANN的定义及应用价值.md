## 向量数据库中 ANN 的定义及应用价值

### 1. 什么是 ANN

ANN（Approximate Nearest Neighbor，近似最近邻）= 在海量向量中，**以近似方法**快速找出与查询向量最相似的 top-k，**牺牲少量精度换取大幅提速**。

与之相对的是精确最近邻（NN / kNN），即老老实实和库里每个向量算距离再排序。

### 2. 为什么需要 ANN

高维向量的**精确 kNN 必须暴力遍历全库**：

```
精确 kNN 复杂度：O(N × D)
  N = 向量数量，D = 向量维度
```

- 100 万条 768 维向量，每次查询要算 7.68 亿次乘加，毫秒级返回无望。
- 数据量到亿级，暴力计算根本不可行。

ANN 的思路：用**索引结构**（图/哈希/聚类/量化）把搜索空间剪枝，只在小范围内计算，复杂度近似降到 O(logN)，从而在亿级数据上做到毫秒级返回。

| 维度 | 精确 kNN | ANN |
| --- | --- | --- |
| 复杂度 | O(N×D)，全量遍历 | 近似 O(logN)，剪枝搜索 |
| 精度 | 100% 精确 | 牺牲少量精度（召回率 90%+ 可调） |
| 速度 | 慢，亿级不可行 | 毫秒级 |
| 适用规模 | 小规模（万级以下） | 百万~亿级 |
| 是否需建索引 | 否 | 是（HNSW/IVF/LSH 等） |

### 3. 应用价值

| 价值 | 说明 |
| --- | --- |
| 毫秒级海量检索 | 让百万/亿级向量的相似度检索落到毫秒，是 RAG/推荐/搜索可用的前提 |
| 解锁语义检索 | 向量相似 = 语义相似，ANN 让"按意思找"在大规模数据上可行 |
| 支撑 RAG 在线问答 | RAG 每次问答都要检索，没有 ANN 就无法做到实时响应 |
| 精度可调 | 召回率与速度可通过索引参数（如 ef_search、nprobe）权衡，适配不同场景 |
| 成本可控 | 相比暴力计算，ANN 用极低算力完成检索，支撑大规模在线服务 |

### 4. 常见 ANN 算法

| 算法 | 原理 | 特点 |
| --- | --- | --- |
| HNSW | 分层可导航小世界图 | 速度精度兼顾，主流默认（见 [[20.向量数据库中HNSW、LSH、PQ的含义]]） |
| IVF | 倒排文件，聚类分桶 + 桶内检索 | 可控粒度，常与 PQ 组合 |
| LSH | 局部敏感哈希分桶 | 快、精度一般 |
| ANNOY | 随机投影树 | Spotify 开源，适合静态数据 |
| ScaNN | 各向异性量化 | Google 出品，精度速度优 |

HNSW 与 IVF 的差异及构建使用方法详见 [[36.向量索引的构建使用方法及HNSW与IVF的差异]]，向量库整体原理见 [[19.向量数据库的核心原理简述]]。

### 5. 一句话总结

ANN = **用索引剪枝把高维精确 kNN 的 O(N) 暴力计算降到近似 O(logN)**，以少量精度损失换来毫秒级海量向量检索，是向量数据库乃至整个 RAG/语义检索得以在线可用的技术基石。
