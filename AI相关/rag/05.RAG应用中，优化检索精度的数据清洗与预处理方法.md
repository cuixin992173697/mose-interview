## RAG 应用中，优化检索精度的数据清洗与预处理方法

> Garbage in, garbage out——RAG 的检索质量上限由知识库数据质量决定。本篇聚焦"入库前"的清洗与预处理，文档解析的通用方法见 [[15.RAG索引流程中文档解析的实现方式]]，切片见 [[10.RAG中分块的定义及分块的必要性]] [[11.RAG中常见分块策略及各自差异]]，整体流程定位见 [[04.详解RAG的完整工作流程]]。

### 1. 为什么清洗与预处理直接决定检索精度

向量检索的本质是"query 向量与文档向量比相似度"。如果文档本身脏、乱、结构丢失，embedding 出来的向量就失真，召回必然偏：

| 脏数据问题 | 对检索的影响 |
| --- | --- |
| 页眉页脚/水印/导航条混入正文 | 向量被无关文本稀释，语义偏移 |
| 乱码/编码错误/OCR 错字 | embedding 编码失真，召回噪声 |
| 表格被拆成乱序文字 | 结构丢失，表内数值召回不到 |
| 重复/近重复文档 | 同一信息多次召回，挤占 top-K，浪费上下文 |
| 段落边界错乱 | 切片切断语义，chunk 语义不完整 |
| 缺元数据 | 无法过滤检索，噪声多、权限失控 |

一句话：**清洗和预处理是把"原始文档"变成"可被准确检索的知识"的必经工序，做不好后面检索/Rerank/Prompt 再调都白搭。**

### 2. 数据清洗（去脏去噪）

#### 文档级清洗

| 清洗项 | 说明 |
| --- | --- |
| 去页眉页脚/水印/导航 | 重复出现的页眉页脚、水印、目录导航条整段剔除，避免污染正文 |
| 去乱码/不可见字符 | 清除零宽字符、控制字符、乱码符号 |
| 编码统一 | 统一转 UTF-8，处理 GBK/GB2312 等遗留编码 |
| 去重复/近重复文档 | 用哈希（精确去重）+ MinHash/SimHash（近重复去重），避免同一知识多份占 top-K |
| 去空白文档/过短片段 | 删除无内容或过短的文档，避免空召回 |
| OCR 纠错 | 扫描件 OCR 结果做错字修正（可结合 LLM/规则） |

#### 文本级清洗

| 清洗项 | 说明 |
| --- | --- |
| 去 HTML/XML 标签 | 网页类文档去标签，保留正文文本 |
| 标点/空格规范化 | 全半角统一、多余空格/换行压缩、标点修正 |
| 去噪声段落 | 去版权声明、免责声明、广告、版本号等与正文无关的固定段落 |
| 停用词处理 | BM25 等稀疏检索需去停用词；向量检索一般不去（embedding 需完整语境） |

### 3. 数据预处理（结构化与语义化）

清洗是"去坏的"，预处理是"把好的整理成更好检索的"。

#### 结构还原

| 预处理项 | 说明 | 收益 |
| --- | --- | --- |
| 标题层级还原 | 解析出 H1/H2/H3 层级并保留 | 支持按标题切分、上下文定位 |
| 表格结构化 | 表格转 Markdown/键值/JSON，不被拆散 | 表内数据可检索（见 [[25.LangChain实现RAG系统时PDF表格数据召回的解决方案]]） |
| 段落边界修正 | 按语义合并被错误换行打断的段落 | 切片语义完整 |
| 图表文字摘要 | 图表/图片用 LLM/OCR 生成文字描述 | 非文本内容可被检索 |

#### 元数据标注（检索精度的关键杠杆）

给每个文档/chunk 打上结构化元数据，支撑过滤检索（详见 [[34.RAG系统利用元数据过滤提升检索精度的方法]]）：

| 元数据 | 作用 |
| --- | --- |
| 来源/文档名 | 溯源、按来源过滤 |
| 时间/版本 | 时间优先、过滤过期内容 |
| 章节/页码 | 精确溯源到段落 |
| 类别/标签 | 按主题路由检索 |
| 权限 | 按用户权限过滤，安全控制 |

#### 语义级预处理

| 预处理项 | 说明 |
| --- | --- |
| 术语标准化 | 把同义术语归一（"LLM/大语言模型/大模型"统一），减少词面不匹配 |
| 长文档分段 | 超长文档先按章节预分段，再切片，避免切片跨章节 |
| 碎片合并 | 过短段落按语义合并到邻近段落，避免碎片 chunk |
| 摘要增强 | 给长 chunk 生成摘要，摘要与原文关联（父子文档），提升召回精度 |

### 4. 清洗与预处理的全流程位置

```
原始文档
  → ① 文档解析（[[15]]）
  → ② 数据清洗（去页眉页脚/乱码/去重/编码统一）      ← 本篇
  → ③ 结构还原（标题/表格/段落/图表摘要）            ← 本篇
  → ④ 元数据标注                                       ← 本篇
  → ⑤ 语义预处理（术语归一/分段/碎片合并/摘要）       ← 本篇
  → ⑥ 切片（[[10]][[11]]）
  → ⑦ 向量化入库（[[12]][[39]]）
```

清洗与预处理发生在"解析之后、切片之前"，是检索质量的奠基环节。

### 5. 质量校验

| 校验项 | 方法 |
| --- | --- |
| 解析完整性 | 抽查文档是否丢内容、表格是否还原 |
| 清洗后可读性 | 人工抽检清洗后正文是否通顺、无残留噪声 |
| 去重效果 | 统计去重前后文档数，查近重复残留 |
| 检索效果回归 | 用评测集跑 recall@k/MRR，对比清洗前后（见 [[09.RAG调优后效果评估的方法及实际应用中的评估标准]]） |

### 6. 一句话总结

数据清洗与预处理是 RAG 检索精度的"地基"：**清洗负责去脏去噪（页眉页脚/乱码/去重/编码），预处理负责结构化与语义化（标题还原/表格结构化/元数据标注/术语归一/摘要增强）**，发生在解析后切片前——这一步做扎实，后续切片、向量检索、Rerank 才有发挥空间。
