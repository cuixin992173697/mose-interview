## 生产环境中 RAG 系统的性能优化与成本控制方法

### 1. 为什么要做性能与成本优化

RAG 比纯大模型多了一条"检索 + 拼上下文"的链路，带来两类额外开销：

| 开销类型 | 来源 | 影响 |
| --- | --- | --- |
| 延迟 | 向量化 + ANN 检索 + Rerank + 更长上下文的生成 | 用户首字时延升高 |
| 成本 | 每次请求都检索 + 拼 chunk，输入 token 暴涨；Rerank 调用 | token 费用 / GPU 费用上升 |

生产环境的核心矛盾：**既要准（多检索、多 chunk、大模型）、又要快、又要便宜**。优化要在三者间找平衡。

### 2. 性能优化

#### 检索侧

| 手段 | 说明 |
| --- | --- |
| ANN 索引调参 | HNSW 调 `ef_construction/ef_search`、IVF 调 `nprobe`，在精度与速度间取平衡（见 [[36.向量索引的构建、使用方法及HNSW与IVF的差异]]） |
| 异步并行 | 向量检索、BM25 检索、Rerank 能并行的不串行，缩短关键路径 |
| 预取/预计算 | 高频 query 预计算检索结果；query 向量化结果缓存 |
| 连接池与批处理 | 向量库连接复用；embedding 批量推理而非逐条 |

#### 生成侧

| 手段 | 说明 |
| --- | --- |
| 上下文压缩 | 提示压缩 / chunk 摘要，砍冗余 token（见 [[08.提示压缩的定义及在RAG中的应用意义]]） |
| 流式输出 | 边生成边返回，降低首字时延体感 |
| 小模型生成 | 非关键场景用小模型生成，关键场景用大模型 |
| 上下文排序 | 重要信息放首尾，缓解 lost-in-the-middle |

#### 架构侧

| 手段 | 说明 |
| --- | --- |
| 异步管线 | 检索与生成解耦，非阻塞；长任务用队列 + 回调 |
| 连接池/资源复用 | 模型推理实例复用，避免冷启动 |
| 分级缓存层 | 多级缓存（本地 → Redis → 语义缓存）层层兜底 |

### 3. 成本控制

| 手段 | 机制 | 节省点 |
| --- | --- | --- |
| Embedding 缓存 | 文档向量化只算一次并持久化；相同 query 向量化结果缓存 | 重复 embedding 调用 |
| Rerank 控量 | 召回 top-N 控制在合理范围（如 50），只对必要候选 rerank | Rerank forward 次数 |
| 提示压缩 | 压缩 chunk / 去冗余，缩短输入 | 生成输入 token |
| 模型分级路由 | 简单问题走小模型/检索直接答，复杂问题才上大模型 | 大模型调用次数 |
| 语义缓存 | 相同或语义相似 query 直接复用历史答案 | 整条检索+生成链路 |
| Top-K 动态调整 | 简单问题小 K，复杂问题大 K | 上下文 token |

> 模型分级路由示意：先由轻量分类器判断 query 难度/类型 → 命中缓存直接返回；闲聊/事实查询走小模型；复杂推理/多跳走大模型 + 全量检索。

### 4. 语义缓存（成本优化的重点）

| 维度 | 说明 |
| --- | --- |
| 精确缓存 | query 完全相同命中，key 用 hash；命中率高时收益大 |
| 语义缓存 | query 向量化后找历史 query 向量最近邻，相似度超阈值则复用其答案；能覆盖"换个说法问同一问题" |
| 风险 | 语义相似但意图不同的 query 误命中 → 答非所问；需配合相似度阈值 + 关键实体校验 |
| 失效 | 知识库更新后相关缓存需失效，避免返回过时答案 |

### 5. 监控指标

没有监控的优化是盲优化。生产 RAG 至少盯这几组指标：

| 指标类别 | 具体指标 |
| --- | --- |
| 性能 | 首字延迟（TTFT）、端到端延迟、检索延迟、生成延迟、P50/P95/P99 |
| 吞吐 | QPS、并发数 |
| 成本 | 单请求 token 数、embedding 调用次数、Rerank 调用次数、大模型调用次数、单请求成本 |
| 质量 | 召回率（recall@k）、答案准确率、幻觉率、用户反馈率 |
| 缓存 | 缓存命中率、语义缓存误命中率 |
| 稳定性 | 检索成功率、超时率、错误率 |

> 质量评估方法见 [[09.RAG调优后效果评估的方法及实际应用中的评估标准]]。

### 6. 优化优先级建议

| 优先级 | 手段 | 理由 |
| --- | --- | --- |
| P0 | Embedding 缓存 + 语义缓存 | 投入小、收益立竿见影，直接砍重复调用 |
| P0 | 模型分级路由 | 把大模型调用留给真正需要的请求 |
| P1 | ANN 索引调参 + 异步并行 | 降延迟，工程量适中 |
| P1 | 提示压缩 + Top-K 控制 | 降 token 成本 |
| P2 | Rerank 控量 + 流式输出 | 精修体验与成本 |

### 7. 一句话总结

生产 RAG 优化 = **性能上靠 ANN 调参/异步并行/流式/上下文压缩降延迟，成本上靠 embedding 缓存/语义缓存/模型分级路由/Top-K 控量省调用，并用延迟·成本·质量三组监控指标闭环驱动**。核心是"把贵的算力留给真正需要的请求，其余靠缓存与分级兜底"。
