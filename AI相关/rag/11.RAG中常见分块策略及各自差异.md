## RAG 中常见分块策略及各自差异

### 1. 策略总览

分块策略决定"在哪切、切多大"，直接关系语义完整性与检索精度。常见策略如下：

| 策略 | 切分依据 | 粒度 | 语义保持 | 复杂度 |
| --- | --- | --- | --- | --- |
| 固定长度 | 字符/token 数 | 固定 | 差（易切断语义） | 低 |
| 滑动窗口 | 固定长度 + overlap | 固定 | 中 | 低 |
| 语义切片 | 句子/段落/标题边界 | 可变 | 好 | 中 |
| 递归切片 | 多级分隔符递归 | 可变 | 中好 | 中 |
| 父子文档 | 检索小块/回填大块 | 双层 | 好 | 高 |
| 按结构切 | Markdown/代码结构 | 可变 | 好 | 中 |
| 表格特殊处理 | 表格整体/行列结构化 | 结构化 | 好 | 高 |

### 2. 各策略详解

#### 策略一：固定长度切分（Fixed-size）

按固定字符/token 数硬切，可能从句子中间断开。

- 优点：实现最简单、速度快。
- 缺点：易切断句子/语义，边界信息丢失。
- 适用：快速原型、对语义不敏感的纯文本。

#### 策略二：滑动窗口（Sliding Window）

固定长度 + 相邻窗口重叠（overlap），弥补边界丢失。

```
chunk1: [0, 500]
chunk2: [450, 950]   # 与 chunk1 重叠 50
chunk3: [900, 1400]
```

- 优点：边界信息不丢，召回更稳。
- 缺点：存储/检索量略增（重叠部分重复）。
- 适用：通用默认方案。

#### 策略三：语义切片（Semantic / 基于分隔符）

按句子、段落、标题等**自然语义边界**切分，保证每个 chunk 语义完整。

- 实现：优先按段落 `\n\n` → 句子 `.。` 聚合，直到接近目标长度。
- 优点：语义完整，检索质量高。
- 缺点：chunk 长度不均，需设上下限。
- 适用：结构化文档（推荐生产用）。

#### 策略四：递归切分（RecursiveCharacterTextSplitter）

LangChain 的经典策略：按一组**优先级递减的分隔符**依次尝试切分。

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500, chunk_overlap=50,
    separators=["\n\n", "\n", "。", "，", " ", ""]  # 优先按段落，再按行、句、逗号
)
chunks = splitter.split_text(doc)
```

- 逻辑：尽量在高级别边界（段落）切，切不开才降级用次级分隔符，最后才硬切。
- 优点：兼顾语义完整与长度可控，工业最常用。
- 缺点：仍可能在不理想处断开。

#### 策略五：父子文档（Parent-Child / Small-to-Big）

**检索用小块（子），生成时回填大块（父）**，两层结构。

```
父块（大，上下文完整）
 ├─ 子块1（小，向量检索精准）
 ├─ 子块2
 └─ 子块3
检索命中子块 → 返回其所属父块作为生成上下文
```

- 优点：兼得"小块检索精准"与"大块上下文完整"。
- 缺点：存储与映射复杂，需维护父子关系。
- 适用：对精度和上下文都要求高的场景。

#### 策略六：按文档结构切分

针对结构化文档按其天然结构切：

- **MarkdownHeaderTextSplitter**：按 `#`/`##` 标题层级切，保留章节路径作为元数据。
- **代码切分**：按函数/类切分，保留完整函数体。
- **HTML**：按标签结构切。

```python
from langchain.text_splitter import MarkdownHeaderTextSplitter
splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=[("#", "h1"), ("##", "h2")]
)
# 每个 chunk 自带 {"h1": "...", "h2": "..."} 元数据
```

- 优点：结构信息不丢，溯源精确。
- 适用：Markdown/代码/HTML 等结构化文档。

#### 策略七：表格/特殊内容处理

表格不按文本切，而是整体保留或结构化：

- 表格整体作为一个 chunk，或转成 Markdown/键值文本。
- 超长表做行列转置降维（见 AI提效《02.Agent的Rag遇到pdf怎么处理》）。
- 图表生成文字摘要再切。

### 3. 差异对比表

| 维度 | 固定长度 | 滑动窗口 | 语义切片 | 递归切片 | 父子文档 | 按结构 |
| --- | --- | --- | --- | --- | --- | --- |
| 切分边界 | 无 | 无 | 语义边界 | 多级边界 | 语义边界 | 文档结构 |
| chunk 均匀 | 是 | 是 | 否 | 近似 | 否 | 否 |
| 语义完整 | 差 | 中 | 好 | 中好 | 好 | 好 |
| 上下文完整 | 差 | 中 | 中 | 中 | 好（父块） | 中 |
| 实现复杂度 | 低 | 低 | 中 | 中 | 高 | 中 |
| 元数据/溯源 | 弱 | 弱 | 中 | 中 | 强 | 强 |

### 4. 选型建议

| 场景 | 推荐策略 |
| --- | --- |
| 纯文本快速起步 | 滑动窗口 |
| 生产通用首选 | 递归切片 / 语义切片 |
| 精度+上下文都重要 | 父子文档 |
| Markdown/技术文档 | MarkdownHeaderTextSplitter |
| 代码库 | 按函数/类切分 |
| 含表格 PDF | 表格特殊处理 + 文本递归切片 |

### 5. 关键参数调优

| 参数 | 影响 | 调优方向 |
| --- | --- | --- |
| chunk_size | 太大语义稀释/噪声多，太小上下文碎 | 256~512 token 起步，按评测调 |
| overlap | 太小丢边界，太大冗余 | 10%~20% |
| 切分符 | 决定语义边界 | 优先段落/标题，兜底硬切 |

> 调参须用评测集量化（recall@k、答案准确率），见 [[09.RAG调优后效果评估的方法及实际应用中的评估标准]]。

### 6. 一句话总结

RAG 常见分块策略从"固定长度/滑动窗口"到"语义/递归切片"再到"父子文档/按结构切"，核心差异在**语义完整性、上下文完整性与实现复杂度的权衡**；生产首选递归切片或父子文档，参数 chunk_size/overlap 需评测驱动调优。分块必要性见 [[10.RAG中分块的定义及分块的必要性]]，它在 [[04.详解RAG的完整工作流程]] 离线阶段，依赖 [[15.RAG索引流程中文档解析的实现方式]] 还原文档结构。
