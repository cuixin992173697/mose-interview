## RAG 系统效果的评估方法及检索、生成环节的核心评估指标

> RAG = 检索 + 生成，必须分环节评估才能定位问题（是召回不到，还是召回到了但生成跑偏）。本篇侧重检索/生成各环节的**核心指标定义与计算**，评估体系与业务标准见 [[09.RAG调优后效果评估的方法及实际应用中的评估标准]]。

### 1. 为什么分环节评估

端到端"答案对不对"是个黑盒——答错了，可能是检索没召回（检索问题），也可能是召回了但模型没用上（生成问题）。分环节评估才能对症下药：

| 答错现象 | 检索环节 | 生成环节 | 对策方向 |
| --- | --- | --- | --- |
| 知识库有答案，但没召回 | ❌ recall 低 | — | 改检索/切片/embedding |
| 召回到了，但答案错 | ✅ | ❌ 幻觉/忽略上下文 | 改 Prompt/换模型/溯源 |
| 答案对但不可溯源 | — | ❌ 引用缺失 | 强制引用标注 |

### 2. 检索环节核心评估指标

检索评估回答"召回的相关文档排得准不准"。

| 指标 | 定义 | 公式直觉 | 关注点 |
| --- | --- | --- | --- |
| Recall@k | 前 k 个结果中召回的相关文档占所有相关文档的比例 | 相关命中数 / 应有相关总数 | 漏没漏（召回率） |
| Precision@k | 前 k 个结果中相关文档的占比 | 相关命中数 / k | 准不准（精度） |
| MRR（Mean Reciprocal Rank） | 第一个相关结果排名的倒数的平均 | 1/排名，求平均 | 相关结果排得靠不靠前 |
| NDCG@k | 考虑排名位置与相关度等级的归一化累计增益 | DCG/IDCG，位置折减加权 | 排序整体质量（支持多档相关度） |
| Hit Rate@k | 前 k 个中是否至少命中一个相关 | 命中 query 数 / 总 query 数 | 能不能命中（粗粒度） |

> 直觉：Recall 管"漏没漏"，Precision 管"杂不杂"，MRR 管"第一个相关排第几"，NDCG 管"整体排序好不好"。RAG 最常看 **Recall@k**（召回率）和 **MRR**（首个相关排名）。

示例：某 query 有 3 个相关文档，检索返回 top-5 中命中 2 个相关（排第 1、4 位）：

| 指标 | 计算 | 值 |
| --- | --- | --- |
| Recall@5 | 2/3 | 0.67 |
| Precision@5 | 2/5 | 0.40 |
| MRR | 1/1（第一个相关排第 1） | 1.0 |

### 3. 生成环节核心评估指标

生成评估回答"答案对不对、有没有依据"。

| 指标 | 定义 | 评估方式 |
| --- | --- | --- |
| Faithfulness（忠实度） | 答案中的事实性陈述能否被召回上下文支持 | 抽取答案事实断言，逐条核对是否在上下文中，可支持比例 |
| Answer Relevancy（答案相关性） | 答案是否切题回答了问题 | 由答案反推可能问题，与原问题算相似度 |
| Accuracy（准确性） | 答案与标准答案/事实是否一致 | 与标注答案对比，或人工/LLM 判定 |
| Hallucination Rate（幻觉率） | 答案中无上下文依据的断言占比 | 1 - 忠实度，或专门检测编造内容 |
| Citation Accuracy（引用准确率） | 引用标注是否正确指向支持来源 | 核对引用编号对应的 chunk 是否真支持该结论 |

> 忠实度（faithfulness）是 RAG 生成侧最核心指标——它直接衡量"答案是否基于检索证据"，与幻觉率互为反面（见 [[27.RAG系统幻觉问题的实用解决方法]]）。

### 4. 评估方法

| 方法 | 说明 | 优缺点 |
| --- | --- | --- |
| 人工评测 | 专家对答案打分（准确性/相关性/忠实度） | 最准，但贵、慢、不可规模化 |
| LLM-as-judge | 用强模型当裁判，按评分标准给答案打分 | 可规模化、便宜，但有裁判偏差 |
| RAGAS 框架 | 自动化评估框架，计算 faithfulness/answer_relevancy/context_precision/context_recall | 检索+生成全覆盖，主流方案 |
| 规则/NLI 校验 | 用自然语言推理模型判断"上下文是否蕴含答案" | 忠实度自动评估的底层手段 |

RAGAS 四大指标对照（检索侧 context_* + 生成侧 faithfulness/answer_relevancy）：

| RAGAS 指标 | 评估环节 | 含义 |
| --- | --- | --- |
| context_precision | 检索 | 召回上下文中相关部分的占比 |
| context_recall | 检索 | 应有相关上下文被召回的比例 |
| faithfulness | 生成 | 答案对上下文的忠实程度 |
| answer_relevancy | 生成 | 答案对问题的切题程度 |

### 5. 检索 vs 生成指标对照

| 维度 | 检索环节指标 | 生成环节指标 |
| --- | --- | --- |
| 评估对象 | 召回的文档列表 | 最终生成的答案 |
| 核心问题 | 召回全不全、排得准不准 | 答案对不对、有没有依据 |
| 代表指标 | Recall@k / MRR / NDCG | Faithfulness / Answer Relevancy |
| 依赖标注 | 相关文档标注 | 标准答案 + 上下文 |
| 改进杠杆 | 切片/embedding/混合检索/Rerank | Prompt/模型/溯源/压缩 |

### 6. 一句话总结

RAG 评估必须分环节：**检索侧看 Recall@k/MRR/NDCG（召回全不全、排得准不准），生成侧看 Faithfulness/Answer Relevancy/幻觉率（答案有没有依据、切不切题）**；方法上人工评测最准、LLM-as-judge 可规模化、RAGAS 框架检索生成全覆盖——分环节评估才能把"答错"定位到是检索还是生成的锅。完整评估体系见 [[09.RAG调优后效果评估的方法及实际应用中的评估标准]]。
