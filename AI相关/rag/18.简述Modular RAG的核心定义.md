## 简述 Modular RAG 的核心定义

### 1. 什么是 Modular RAG
Modular RAG = 把 RAG 拆成**可插拔、可替换、可组合的模块**（Retriever / Reranker / Memory / Fusion / Router / Generator 等），按业务需求自由拼装，支持模块间的循环与迭代。

- 一句话：**Advanced RAG 是给流程加优化，Modular RAG 是改架构把流程模块化。**
- 演进基础见 [[01.简述RAG的定义及核心工作流程+局限性]]、[[17.简述Advanced RAG的核心内涵]]。

### 2. 核心模块
| 模块 | 职责 | 可选实现 |
| --- | --- | --- |
| Router / 查询路由 | 判断走哪个知识库/是否检索/转 SQL | 意图分类器、LLM 路由 |
| Retriever / 检索器 | 召回相关片段 | 向量检索、BM25、混合检索 |
| Reranker / 重排器 | 精排召回结果 | Cross-Encoder、LLM rerank |
| Fusion / 融合器 | 多路结果合并去重 | RRF、加权融合 |
| Memory / 记忆 | 多轮上下文与历史管理 | 摘要记忆、向量记忆 |
| Generator / 生成器 | 基于 evidence 生成答案 | 各类 LLM |
| Evaluator / 评测器 | 自评答案与证据质量（部分实现） | LLM-as-judge |

### 3. 三代 RAG 演进路线

```
Naive RAG → Advanced RAG → Modular RAG
（一条龙）  （加优化）       （改架构模块化）
```

| 维度 | Naive | Advanced | Modular |
| --- | --- | --- | --- |
| 架构 | 固定线性流水线 | 固定流水线 + 各环节优化 | 模块化，可重组 |
| 流程 | 切片→检索→生成 | Pre/Mid/Post 优化 | 模块按需编排，支持循环迭代 |
| 灵活性 | 低 | 中 | 高（模块可替换/增删） |
| 复杂度 | 低 | 中 | 高 |
| 适用 | 简单场景 | 工业主流 | 复杂定制、多源异构、Agentic RAG |

### 4. 模块化带来的能力
| 能力 | 说明 |
| --- | --- |
| 可插拔 | 想换检索器/Reranker 不动整体，模块独立替换 |
| 可组合 | 按场景拼装：简单问答走 Retriever→Generator，复杂走 Router→多路→Fusion→Rerank→Generator |
| 支持循环 | 生成不满足可回到检索再补一轮（迭代式 RAG / Agentic RAG） |
| 复用 | 模块跨项目复用，沉淀组件库 |
| 可评测 | 每个模块独立评测，定位瓶颈精准 |

### 5. 代表实现
| 框架 | 模块化体现 |
| --- | --- |
| LangChain | Retrievers / Compressors / Rerankers / Memory / Chains 组件化拼装 |
| LlamaIndex | QueryEngine / Retriever / NodePostprocessor / ResponseSynthesizer 可组合 |
| 自研架构 | 按业务定义模块接口，编排引擎串联（支持 DAG/循环） |

> LangChain 实现见 [[41.RAG的定义及基于LangChain的RAG应用实现]]。

### 6. 与 Advanced RAG 的本质区别
- **Advanced RAG**：流程不变（仍是 检索→生成），在每环节加优化技术。
- **Modular RAG**：流程可变，把 RAG 重新定义为一组模块的编排，支持路由分叉、循环迭代、模块替换。
- 类比：Advanced 是"给流水线每个工位升级工具"，Modular 是"重新设计成可重组的柔性产线"。

### 7. 一句话总结
Modular RAG 的核心定义 = **把 RAG 拆成 Retriever/Reranker/Fusion/Router/Memory/Generator 等可插拔模块，按需组合、可替换、支持循环迭代**，是 RAG 从"固定流水线"走向"柔性可编排架构"的进阶形态，为 Agentic RAG 与复杂定制场景提供基础。
