## RAG 中 Embedding 向量化的定义及工作原理

### 1. 什么是 Embedding 向量化

Embedding 向量化 = **把文本（或图像等）映射成一段固定维度的稠密浮点向量**，让"语义相近的内容在向量空间中距离也近"。

它是 RAG 检索的地基：文档和问题都被向量化后，检索就退化成"在向量空间里找离问题向量最近的几个文档向量"。

| 维度 | 说明 |
| --- | --- |
| 输入 | 一段文本（token 序列） |
| 输出 | 固定维度的稠密向量（如 768 / 1024 / 1536 维） |
| 关键性质 | 语义相近 → 向量距离近；语义无关 → 向量距离远 |
| 在 RAG 中的角色 | 离线把文档切片向量化入库；在线把用户 query 向量化后做相似度检索 |

> 本篇聚焦"向量化怎么发生、为什么能表征语义"。概念解读与角色定位见 [[12.解读RAG中的Embedding嵌入技术]]，常见模型见 [[13.RAG中常用的Embedding模型]]。

### 2. 工作原理：从文本到向量的 5 步

```
原始文本 → ①token 化 → ②Transformer encoder 编码 → ③pooling 汇聚 → ④归一化 → ⑤输出向量
```

#### ① Token 化（Tokenization）

把文本切成模型能处理的最小单元 token，并映射成 token id。

- 中文常用字/词级或 BPE；英文常用 BPE/WordPiece。
- 序列前面加特殊 token（如 `[CLS]`），末尾加 `[SEP]`，并叠加位置编码。

#### ② Transformer Encoder 编码

token 序列送进多层 Transformer encoder，每层靠**自注意力**让每个 token 与全序列交互，最终每个 token 都得到一个融合了上下文的隐向量。

- 关键：自注意力使"bank"在"river bank"和"bank account"中得到不同的上下文表征——这就是"字面相同但语义不同"能被区分的根源。

#### ③ Pooling 汇聚

把变长的 token 隐向量序列汇聚成**一个**定长句向量，三种主流做法：

| Pooling 方式 | 做法 | 特点 |
| --- | --- | --- |
| CLS pooling | 直接取 `[CLS]` 位置的向量 | BERT 系传统做法，但 CLS 训练得好才有效 |
| Mean pooling | 对所有 token 向量求平均 | 句向量模型（如 sentence-bert、bge）常用，更稳健 |
| Max pooling | 逐维取最大值 | 较少用，对显著特征敏感 |

#### ④ 归一化（Normalization）

对句向量做 L2 归一化，使其长度为 1。

- 好处：归一化后**余弦相似度 = 点积**，检索时直接用点积即可，计算更快、ANN 索引更友好。

#### ⑤ 输出向量

得到最终的定长稠密向量，存入向量库（文档侧）或用于检索（query 侧）。距离度量见 [[22.向量数据库中余弦相似度、欧几里得距离、曼哈顿距离的定义及差异]]。

### 3. 为什么向量能"表征语义"：训练机制

Embedding 模型的语义能力不是 Encoder 结构自带的，而是**对比学习（Contrastive Learning）训练**出来的。

核心思想：**拉近正例对、推远负例对。**

| 样本对 | 含义 | 训练目标 |
| --- | --- | --- |
| 正例对（positive） | 语义相同/相近（同义句、问题-答案、query-相关文档） | 向量距离 ↓ |
| 负例对（negative） | 语义不同/无关（随机文档、hard negative） | 向量距离 ↑ |

- 损失函数常用 InfoNCE：`-log( exp(sim(q,p+)/τ) / Σ exp(sim(q,neg)/τ) )`，让正例相似度远高于所有负例。
- **Hard negative**（字面相似但语义不同的负例）对提升判别力至关重要——例如把"如何训练狗"作为"如何训练猫"的 hard negative。
- 训练数据规模通常达亿级（如 bge 用了大量 query-文档对）。

> 直觉：训练把"意思一样的话"挤到一起、"意思无关的话"推开，最终向量空间的几何结构就反映了语义结构。

### 4. 与传统文本表示的对比

| 表示方式 | 维度 | 是否含语义 | 典型问题 |
| --- | --- | --- | --- |
| One-hot / 词袋 | 词表大小，极稀疏 | 几乎无 | 维度灾难、词表对不齐 |
| TF-IDF / BM25 | 词表大小，稀疏 | 仅字面统计 | 不懂同义、词面不匹配就废 |
| Word2Vec / GloVe | 低维稠密，词级 | 静态词级语义 | 一词多义无法区分、无句级语义 |
| Transformer Embedding | 中高维稠密，句级 | 上下文相关、句级语义 | 计算成本高（但离线可预计算） |

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| query 与文档同模型 | 必须用同一个 Embedding 模型向量化，否则向量空间不一致，相似度无意义 |
| 向量维度权衡 | 维度高→表达力强但存储/检索成本高；常见 768~1536 维 |
| 归一化统一 | 入库前统一 L2 归一化，检索用点积或余弦一致 |
| 输入长度限制 | Encoder 有 max_seq_len（常 512），超长文本需先切片（见 [[10.RAG中分块的定义及分块的必要性]]） |
| 领域适配 | 通用模型在垂直领域可能不准，可用领域数据微调（见 [[14.RAG中Embedding模型的选型因素及方法]]） |

### 6. 一句话总结

Embedding 向量化 = **文本经 token 化 → Transformer encoder 编码 → pooling 汇聚 → 归一化，输出一个能反映语义的定长稠密向量**；其语义能力来自对比学习训练（拉近正例、推远负例），是 RAG 把"语义匹配"变成"向量距离计算"的底层基石。
