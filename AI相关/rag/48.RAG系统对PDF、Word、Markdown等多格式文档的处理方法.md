## RAG 系统对 PDF、Word、Markdown 等多格式文档的处理方法

> 本篇侧重各格式横向对比与处理实践。文档解析的通用方法（难点、结构还原、清洗）见 [[15.RAG索引流程中文档解析的实现方式]]，PDF 表格专项见 [[25.LangChain实现RAG系统时PDF表格数据召回的解决方案]]，流程定位见 [[04.详解RAG的完整工作流程]]。

### 1. 为什么要按格式分别处理

不同格式的文档结构差异巨大，解析方式不对会直接丢失信息、污染向量：

| 格式 | 结构特征 | 解析难点 |
| --- | --- | --- |
| PDF | 定位坐标流，无语义结构 | 多栏、表格、扫描件、图文混排 |
| Word | 结构化 XML（.docx），有样式 | 表格、嵌入对象、样式映射 |
| Markdown | 纯文本+标记，原生结构化 | 几乎无难点，最友好 |
| HTML | 标签树，含大量噪声 | 去导航/广告/脚本，保留正文 |
| Excel | 二维表格 | 行列结构化、合并单元格、多 sheet |
| PPT | 按页组织 | 文本分散、图表、演讲者备注 |

### 2. 各格式处理方法

#### PDF

| 工具 | 特点 |
| --- | --- |
| PyMuPDF(fitz) | 速度快，文本/布局抽取好 |
| pdfplumber | 表格识别强，基于线框规则 |
| Unstructured | 通用，自动识别表格/标题/列表，LangChain 原生支持 |
| 扫描件 | 走 OCR（PaddleOCR/Tesseract）后再解析 |

处理要点：多栏文档按栏还原阅读顺序；表格单独结构化（见 [[25.LangChain实现RAG系统时PDF表格数据召回的解决方案]]）；保留页码用于溯源。

#### Word（.docx）

| 工具 | 特点 |
| --- | --- |
| python-docx | 读段落/表格/样式，保结构 |
| Unstructured | 通用解析 |

处理要点：保留标题层级（Heading 样式）；表格转 Markdown/键值；图片可提取后生成摘要。

#### Markdown

最友好的格式，原生带结构标记：

| 工具 | 特点 |
| --- | --- |
| 直接读文本 | 按标题/段落切即可 |
| MarkdownHeaderTextSplitter（LangChain） | 按 H1/H2/H3 切分并携带标题上下文 |

处理要点：按标题切分保语义；代码块整体保留不被切断。

#### HTML

| 工具 | 特点 |
| --- | --- |
| BeautifulSoup / lxml | 解析标签树 |
| html2text | 转 Markdown |
| Trafilatura / readability | 自动正文抽取，去导航/广告/脚本 |

处理要点：去掉 `<script>/<style>/导航/广告`，只留正文；保留标题层级与链接文本。

#### Excel

| 处理方式 | 说明 |
| --- | --- |
| 行转键值 | 每行转成"字段:值"自然语言，利于向量化 |
| 转 Markdown 表格 | 小表整体保留结构 |
| 转 CSV | 结构化存储，配合 Text-to-SQL 查询 |

处理要点：合并单元格展开；多 sheet 分别处理；超宽表降维（长表转多行键值）。

#### PPT

| 处理方式 | 说明 |
| --- | --- |
| python-pptx | 按页读文本框、表格、备注 |
| 按页切片 | 一页一 chunk 或按标题聚合 |

处理要点：合并演讲者备注与页面文本；图表生成文字摘要。

### 3. 多格式统一管道

工业 RAG 通常用统一管道抹平格式差异：

```
任意格式文档
  → 格式路由（按扩展名/MIME 选解析器）
  → 统一解析（输出统一中间结构：文本+标题层级+表格+元数据）
  → 统一清洗（去噪/编码/去重）
  → 统一切片（按结构切片，表格/代码特殊处理）
  → 向量化入库（向量 + 元数据 + 全文索引）
```

| 环节 | 作用 |
| --- | --- |
| 格式路由 | 按类型分发到对应解析器 |
| 统一中间结构 | 各格式解析后归一为 {content, metadata, tables} 结构 |
| 统一清洗/切片 | 后续流程与格式无关，复用同一套逻辑 |

> Unstructured、LlamaIndex 的 reader、LangChain 的 document loader 都遵循"多格式输入→统一 Document 输出"的思路。

### 4. 格式适配速查表

| 格式 | 推荐解析器 | 切片建议 | 特别注意 |
| --- | --- | --- | --- |
| PDF | PyMuPDF / Unstructured | 按页+段落，表格独立 | 多栏顺序、扫描件 OCR |
| Word | python-docx | 按标题层级 | 表格、样式映射 |
| Markdown | 直接读 / HeaderSplitter | 按标题切 | 代码块整体保留 |
| HTML | Trafilatura / BeautifulSoup | 按标题/段落 | 去广告导航 |
| Excel | pandas / openpyxl | 行转键值 | 合并单元格、多 sheet |
| PPT | python-pptx | 按页 | 合并备注 |

### 5. 一句话总结

多格式处理的核心是"格式路由→统一解析成中间结构→统一清洗切片入库"：**PDF 用 PyMuPDF/Unstructured 攻多栏表格、Word 保样式、Markdown 按标题切、HTML 去噪保正文、Excel 行转键值、PPT 按页合并备注**，最终抹平格式差异走统一 RAG 管道。解析通用方法见 [[15.RAG索引流程中文档解析的实现方式]]。
