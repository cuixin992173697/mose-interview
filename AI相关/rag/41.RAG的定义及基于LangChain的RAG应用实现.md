## RAG 的定义及基于 LangChain 的 RAG 应用实现

### 1. RAG 定义（简述）

RAG（Retrieval-Augmented Generation，检索增强生成）= **检索 + 生成**：先从外部知识库检索相关片段，拼进 Prompt，再让大模型基于"问题 + 证据"生成答案。它把"知识更新"与"模型能力"解耦，让回答既新又准、可溯源。

> 完整定义、工作流程与局限性见 [[01.简述RAG的定义及核心工作流程+局限性]] 与 [[04.详解RAG的完整工作流程]]。本篇聚焦用 LangChain 落地实现。

### 2. LangChain 中的 RAG 核心组件

LangChain 把 RAG 拆成可组合的组件，用 LCEL（LangChain Expression Language）串成管道：

| 组件 | 作用 | 常见类 |
| --- | --- | --- |
| DocumentLoader | 加载文档（PDF/HTML/Markdown/网页等） | `PyPDFLoader`/`WebBaseLoader`/`DirectoryLoader` |
| TextSplitter | 切片 | `RecursiveCharacterTextSplitter`/`MarkdownHeaderTextSplitter` |
| Embeddings | 向量化 | `HuggingFaceEmbeddings`/`OpenAIEmbeddings` |
| VectorStore | 向量库封装 | `Chroma`/`FAISS`/`Milvus`/`PGVector` |
| Retriever | 检索器，从 VectorStore 转换而来 | `vectorstore.as_retriever()` |
| LLM | 大模型 | `ChatOpenAI`/`ChatAnthropic` 等 |
| Prompt | 提示模板 | `ChatPromptTemplate` |
| Runnable / LCEL | 用 `|` 管道串接组件 | `retriever | prompt | llm` |
| OutputParser | 解析输出 | `StrOutputParser` |

### 3. 标准实现流程（load → split → embed → store → retrieve → generate）

#### ① 离线建库

```python
from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import Chroma

# 1. 加载
docs = PyPDFLoader("knowledge.pdf").load()

# 2. 切片
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_documents(docs)

# 3 & 4. 向量化 + 入库
embeddings = HuggingFaceEmbeddings(model_name="BAAI/bge-large-zh-v1.5")
vectorstore = Chroma.from_documents(chunks, embeddings, persist_directory="./db")
```

#### ② 在线问答（LCEL 写法，推荐）

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

retriever = vectorstore.as_retriever(search_kwargs={"k": 5})
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

prompt = ChatPromptTemplate.from_template("""
你是一个严谨的问答助手。仅根据下方上下文回答问题，上下文中没有的信息就回答"不知道"。
上下文：
{context}

问题：{question}
""")

def format_docs(docs):
    return "\n\n".join(d.page_content for d in docs)

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)

answer = rag_chain.invoke("RAG 的核心工作流程是什么？")
```

#### ② 进阶：带记忆的多轮问答

```python
from langchain.chains import create_history_aware_retriever, create_retrieval_chain
from langchain.chains.combine_documents import create_stuff_documents_chain

# 历史改写：把多轮指代消解后再检索（见 [[43.RAG中Query Rewriting查询重写的定义及检索效果优化方法]]）
condense_prompt = ChatPromptTemplate.from_template("""
根据对话历史和最新问题，改写成一个独立、可检索的问题。
历史：{chat_history}
问题：{input}
""")
history_retriever = create_history_aware_retriever(llm, retriever, condense_prompt)

qa_prompt = ChatPromptTemplate.from_template("""
仅根据上下文回答，无依据则说不知道。
上下文：{context}
问题：{input}
""")
qa_chain = create_stuff_documents_chain(llm, qa_prompt)
rag_chain = create_retrieval_chain(history_retriever, qa_chain)

# 带 chat_history 调用
rag_chain.invoke({"input": "它的局限性呢？", "chat_history": [...]})
```

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 选对 Splitter | 通用用 RecursiveCharacterTextSplitter；Markdown 用 header 切分；代码用 Language 专属 splitter |
| 切片参数 | chunk_size 256~512、overlap 10%~20%，按评测调（见 [[10.RAG中分块的定义及分块的必要性]]） |
| 持久化 | VectorStore 持久化到磁盘，避免每次重启重建 |
| Prompt 约束 | 明确"仅依据上下文、无关说不知道"，降幻觉（见 [[27.RAG系统幻觉问题的实用解决方法]]） |
| PDF 表格 | PyPDFLoader 对表格弱，需 Unstructured/表格抽取方案（见 [[25.LangChain实现RAG系统时PDF表格数据召回的解决方案]]） |
| LCEL 优先 | 新代码用 LCEL runnables，比旧版 RetrievalQA 更灵活、可流式、可观测 |

### 6. 一句话总结

基于 LangChain 实现 RAG = **用 DocumentLoader→TextSplitter→Embeddings→VectorStore→Retriever 组件搭离线建库管道，用 LCEL `retriever | prompt | llm | parser` 串在线问答链路**，再按需叠加混合检索、Rerank、记忆等进阶能力，是落地 RAG 最快的工程脚手架。
