## 解读 RAG 中的 Embedding 嵌入技术

### 1. 什么是 Embedding

Embedding（嵌入）= 把文本（或图像等）映射成一个**固定维度的稠密实数向量**，使得**语义相近的文本→向量也相近**。

```
"大模型"        → [0.12, -0.34, 0.56, ..., 0.07]   (768维)
"大语言模型"    → [0.11, -0.32, 0.55, ..., 0.09]   (向量很近)
"今天天气不错"  → [-0.41, 0.88, 0.02, ..., -0.33]  (向量很远)
```

- 维度常见 384 / 768 / 1024 / 1536。
- 向量间的距离（余弦相似度等）即语义相似度。

> 距离度量见 [[22.向量数据库中余弦相似度、欧几里得距离、曼哈顿距离的定义及差异]]。

### 2. 工作原理

Embedding 模型的典型架构：

```
文本 → Tokenize → Transformer Encoder → 各 token 向量 → Pooling → 句子向量
```

| 环节 | 作用 |
| --- | --- |
| Tokenize | 文本切分成 token |
| Transformer Encoder | 编码每个 token 的上下文语义（如 BERT 架构） |
| Pooling | 把多个 token 向量聚合成一个句子向量（mean/cls pooling） |
| 归一化（可选） | 向量 L2 归一化，便于算余弦相似度 |

### 3. 为什么 Embedding 能表征语义：对比学习

Embedding 之所以"语义相近→向量相近"，靠的是**对比学习（Contrastive Learning）**训练：

- 构造**正例对**（语义相同/相关）：同义句、问题-答案、标题-正文。
- 构造**负例对**（语义无关）：随机其他文本。
- 训练目标：**拉近正例对的向量距离，推远负例对的向量距离**。

```
损失（如 InfoNCE）： maximize  sim(q, q+) / [ sim(q,q+) + Σ sim(q, q-) ]
```

经过大规模这样训练，模型学会把"语义相近"映射到"向量空间相近"，于是检索时算向量距离就能反映语义相似度。

### 4. 与传统文本表示的区别

| 维度 | One-Hot / 词袋 | Embedding |
| --- | --- | --- |
| 表示形式 | 稀疏 0/1 高维 | 稠密实数低维 |
| 维度 | 词汇表大小（万~百万级） | 几百~几千 |
| 语义 | 无（只记有无） | 有（语义相近向量相近） |
| 上下文 | 无（词独立） | 有（Transformer 编码上下文） |
| 相似度计算 | 难（稀疏、无语义） | 易（稠密向量距离） |
| 泛化 | 词面不匹配即失效 | 同义/改写能命中 |

### 5. 在 RAG 中的角色

Embedding 是 RAG 检索的"翻译层"，把"文本相似度问题"转成"向量距离问题"：

| 阶段 | 作用 |
| --- | --- |
| 离线索引 | 把每个文档 chunk 向量化，存入向量库 |
| 在线检索 | 把用户 query 向量化，与文档向量算相似度，取 top-k |

```
离线：chunk_i → Embedding → vec_i → 入库
在线：query → Embedding → vec_q → 与所有 vec_i 算相似度 → top-k
```

- 文档与 query 用**同一个 Embedding 模型**编码，才能在同一向量空间比较。
- 检索质量 = Embedding 模型质量 × 切片质量 × 距离度量。

### 6. 关键特性与注意点

| 特性 | 说明 |
| --- | --- |
| 维度与信息量 | 维度越高表达力越强，但存储/检索成本也越高 |
| 领域适配 | 通用 Embedding 在垂直领域（医疗/法律）可能弱，需微调或选领域模型 |
| 多语言 | 部分 Embedding 支持跨语言（如 bge-multilingual） |
| 长度上限 | 多数模型有 max_seq_length（如 512 token），超长需切片（见 [[10.RAG中分块的定义及分块的必要性]]） |
| 归一化 | 归一化后余弦相似度=内积，检索更快 |

### 8. 一句话总结

Embedding = **用 Transformer Encoder + 对比学习把文本映射成稠密向量，使"语义相近→向量相近"**，是 RAG 把"文本相似度检索"转化为"向量距离检索"的基石；相比 one-hot/词袋，它稠密、低维、带语义、能跨同义表述命中，是检索质量的根本来源。
