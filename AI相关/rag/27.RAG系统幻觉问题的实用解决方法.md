## RAG 系统幻觉问题的实用解决方法

### 1. RAG 幻觉的来源

RAG 不是"加了检索就不幻觉"，幻觉可能出现在任何一个环节：

| 来源 | 说明 |
| --- | --- |
| 检索不到 | 召回为空或无关，模型仍硬答 → 编造 |
| 检索噪声 | 召回了低相关/错误片段，模型被误导 |
| 模型编造 | 检索到证据，但模型忽略证据，用参数化记忆瞎编 |
| 上下文冲突 | 多份证据相互矛盾，模型随机"缝合" |
| 知识过期 | 知识库未及时更新，模型用过时信息作答 |

> 第一类"检索不到还硬答"是 RAG 最常见幻觉，根因往往在召回质量（改进方向见 [[24.RAG系统召回结果与用户query意图不匹配的改进方向]]）。

### 2. 按环节的实用解决方法

#### 检索侧：让证据又全又准

| 方法 | 作用 |
| --- | --- |
| 混合检索 | 向量+关键词互补，提升召回率 |
| Rerank 精排 | Cross-Encoder 剔除噪声，提高精度 |
| 查询改写/扩展 | 把问题改成更易检索的表述，减少"检索不到" |
| 阈值过滤 | 召回分数过低直接判"无相关文档"，触发拒答而非硬答 |

#### Prompt 侧：约束模型只用证据

| 方法 | 作用 |
| --- | --- |
| 明确约束 | "仅依据提供的上下文回答，上下文无依据则回答'不知道'" |
| 强制引用 | 要求每句结论标注来源编号 |
| 不确定显式化 | 要求模型对低把握内容标注"不确定" |
| 上下文压缩 | 去除冗余，让证据更聚焦（见 [[08.提示压缩的定义及在RAG中的应用意义]]） |

Prompt 模板示例：

```text
你是一个严谨的问答助手。请严格依据下方【参考资料】回答问题。
规则：
1. 答案中每个事实性结论必须能在参考资料中找到依据，并标注 [编号]。
2. 若参考资料不足以回答，直接回答"根据现有资料无法回答"，不得编造。
3. 资料间冲突时，说明冲突并优先采信标注更新/更权威的来源。

【参考资料】
[1] (来源:xx手册, p.12) ...
[2] (来源:xx规范, 2024) ...
【问题】...
```

#### 后处理侧：校验答案有据可依

| 方法 | 作用 |
| --- | --- |
| 强制溯源 | 答案的每个引用必须落在召回 chunk 集合内，否则判幻觉 |
| 引用核对 | 检查引用编号对应的 chunk 是否真支持该结论（可再用 LLM/规则核对） |
| 答案校验 | 用另一模型/NLI 模型判断"答案是否被上下文支持" |
| 无引用截断 | 删除无法溯源的结论句 |

溯源与引用的实现细节见 [[28.RAG系统中信息来源标注与引用的实现方式]]。

#### 系统侧：兜底与裁决

| 方法 | 作用 |
| --- | --- |
| 置信度阈值 | 召回分数/Rerank 分低于阈值直接拒答 |
| 多路投票 | 多次检索或多次生成取一致部分，矛盾处降权 |
| 知识冲突处理 | 多源矛盾时按权威/时间/多数投票裁决 |
| 人工兜底 | 高风险/低置信问题转人工，不强行作答 |

### 3. 方法选型对照

| 幻觉来源 | 首选方法 |
| --- | --- |
| 检索不到 | 混合检索+查询改写+阈值拒答 |
| 检索噪声 | Rerank+阈值过滤 |
| 模型编造 | Prompt 约束+强制引用+答案校验 |
| 上下文冲突 | 冲突消解+多路投票 |
| 知识过期 | 增量索引+时间优先+拒答兜底 |

### 4. 一句话总结

RAG 抑制幻觉是**全链路工程**：检索侧"找全找准"、Prompt 侧"约束只用证据"、后处理侧"校验有据可依"、系统侧"低置信兜底"——四层布防，单靠任何一层都不够。完整流程定位见 [[04.详解RAG的完整工作流程]]。
