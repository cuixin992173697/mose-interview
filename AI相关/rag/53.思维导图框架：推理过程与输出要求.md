## 思维导图框架：答题推理过程与输出要求

> 本篇是整个 RAG 面试系列的"方法论总纲"：不讲某个 RAG 技术点，而是讲**如何用思维导图框架组织答 RAG 题的推理过程与输出**，并在最后用它把前 52 篇归类成一张知识体系图，兼作系列导航。

### 1. 为什么用思维导图框架答 RAG 题

RAG 面试题往往是"定义 + 流程 + 对比 + 实践"的复合题，线性作答容易漏点、讲散。思维导图框架用 **"中心问题 → 分支维度 → 叶子要点"** 的结构强制拆解，带来三个好处：

| 好处 | 说明 |
| --- | --- |
| 拆得开 | 把一道大题拆成几个正交维度，逐个击破，不遗漏 |
| 想得清 | 层级关系显式化，主次分明，推理路径可追溯 |
| 讲得清 | 输出天然结构化，面试官跟得上、印象深 |

一句话：**拆得开 = 想得清 = 答得好。**

### 2. 思维导图框架的结构

```
                    [中心节点：题目核心问题]
                            │
        ┌──────────┬────────┼────────┬──────────┐
     一级分支1  一级分支2  一级分支3  一级分支4   一级分支5
     (是什么)  (为什么)  (怎么做)  (对比/选型) (局限/演进)
        │          │          │          │           │
     叶子要点   叶子要点   叶子要点   叶子要点    叶子要点
```

| 层级 | 作用 | 举例（以"RAG 完整流程"为例） |
| --- | --- | --- |
| 中心节点 | 题目问什么 | RAG 的完整工作流程 |
| 一级分支 | 拆解维度 | 离线建库 / 在线问答 / 关键机制 |
| 叶子要点 | 每维度的具体内容 | 离线：加载→切片→向量化→入库 |

### 3. 推理过程（怎么想）

按四步走，把题目"拆"成思维导图：

#### Step 1：审题定中心

先判断题目类型，确定中心节点：

| 题型 | 中心节点 | 代表题 |
| --- | --- | --- |
| 定义类 | "X 是什么" | [[01.简述RAG的定义及核心工作流程+局限性]] |
| 流程类 | "X 的完整流程" | [[04.详解RAG的完整工作流程]] |
| 对比类 | "A vs B 的差异与选型" | [[46.RAG与模型微调Fine-tuning的差异及选型方法]] |
| 方法类 | "X 怎么做/怎么设置" | [[51.RAG中文档切割中chunk_size与overlap的设置方法]] |

#### Step 2：按题型选维度模板（一级分支）

不同题型有固定的维度模板，照着拆不会漏：

| 题型 | 一级分支模板 |
| --- | --- |
| 定义类 | 是什么 → 为什么需要 → 怎么实现 → 与同类对比 → 局限与演进 |
| 流程类 | 阶段划分 → 每步输入/输出 → 关键机制 → 异常与边界 |
| 对比类 | 对比维度 → 差异表 → 各自适用场景 → 选型决策 |
| 方法类 | 为什么需要 → 实现方式 → 实践要点 → 效果评估 |

> 这套模板正是本系列 01–52 篇统一遵循的骨架——`## 题目` 下用 `###` 分维度，就是这个思维导图一级分支的落地。

#### Step 3：填叶子要点

每个一级分支下补具体内容：定义、参数、例子、代码。叶子要点遵循"先结论后展开"。

#### Step 4：查漏补缺

回头检查是否漏了常被忽略的维度：

| 易漏维度 | 提醒 |
| --- | --- |
| 成本/性能 | 这东西贵不贵、快不快 |
| 边界/失效 | 什么时候不适用、会出什么问题 |
| 工程实践 | 真实落地有什么坑 |
| 评估 | 怎么知道做得好不好 |

### 4. 输出要求（怎么讲）

思维导图想清楚后，落地成文档/口述要遵循固定结构：

| 输出要素 | 要求 | 本系列对应 |
| --- | --- | --- |
| 主标题 | `## 题目原文`，开门见山 | 每篇第 1 行 |
| 分维度 | `###` 一级分支，每点一个小标题 | 每篇 `###` |
| 表格化 | 对比、总结、参数必用表格 | 大量 `| |` 表 |
| 代码/公式 | 能上则上，体现落地能力 | 代码块 |
| 互链 | 关联题用 `[[编号.标题]]` 点出 | 跨篇 `[[ ]]` |
| 一句话总结 | 收尾压缩结论，便于记忆 | 每篇末节 |

**详略原则**：核心维度详讲（定义/流程/选型），边缘维度点到（成本/边界），不平均用力。

### 5. 示范：用框架拆一道流程题

以"RAG 完整流程"为例，展示从思维导图到文档结构的映射（对应 [[04.详解RAG的完整工作流程]] [[47.RAG的完整工作流程及核心步骤]]）：

```
中心：RAG 完整流程
├─ 离线建库
│   ├─ 文档加载与预处理  → 详见 05/15/48
│   ├─ 切片              → 详见 10/11/51
│   └─ 向量化入库        → 详见 12/19/23
├─ 在线问答
│   ├─ 查询理解          → 详见 06/07/43
│   ├─ 检索（多路召回）  → 详见 03/52/34
│   ├─ Rerank 精排       → 详见 02/37
│   ├─ 上下文组装+生成   → 详见 16/31/08
│   └─ 溯源后处理        → 详见 28
├─ 关键机制
│   ├─ 混合检索+Rerank   → 召回两板斧
│   ├─ 元数据贯穿全程    → 过滤/溯源/权限
│   └─ 评测驱动迭代      → 09/50

    ├─ 检索不到          → 44
    ├─ 召回不匹配        → 24

```

每个叶子节点都能在本系列找到对应详解——这就是思维导图框架把"一道题"和"整个知识网"串起来的效果。

### 7. 一句话总结

思维导图框架 = **中心问题 → 按题型模板拆维度 → 填叶子要点 → 查漏补缺**，输出按"`##` 题目 / `###` 分维度 / 表格 / 代码 / 一句话总结"结构化；它既是答单道题的推理脚手架，也能把整个 RAG 知识体系串成一张可导航的图。
