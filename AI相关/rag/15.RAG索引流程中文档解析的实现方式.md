## RAG 索引流程中文档解析的实现方式

### 1. 文档解析在索引流程中的位置
文档解析是 RAG 离线索引的**第一步**——把原始文件转成结构化文本，直接决定切片、向量化、检索的质量上限。

- 解析烂，后面全白搭。
- 完整流程位置见 [[04.详解RAG的完整工作流程]]。

### 2. 按格式的解析实现方式

| 格式 | 常用解析器 | 特点与难点 |
| --- | --- | --- |
| PDF | PyMuPDF（fitz）、pdfplumber、Unstructured、Camelot（表格）、Marker | 最难：多栏、表格、扫描件、图文混排、乱码 |
| Word | python-docx、Unstructured、docx2txt | 结构相对规整，注意样式与表格 |
| HTML | BeautifulSoup、lxml、trafilatura | 需去标签、去广告/导航，保留正文结构 |
| Markdown | 直接读 / markdown-it | 结构天然，按标题切分容易 |
| Excel | pandas、openpyxl、Unstructured | 表格需降维为多行结构化文本 |
| PPT | python-pptx、Unstructured | 按页提取文本与备注，图表需 OCR |
| 扫描件/图片 | OCR（PaddleOCR、Tesseract、云 OCR） | 准确率受图像质量影响 |

### 3. PDF 解析难点与对策（重灾区）
| 难点 | 问题 | 对策 |
| --- | --- | --- |
| 多栏排版 | 顺序读取会错乱串行 | 按版面分析还原阅读顺序（PyMuPDF 的 block / Layout 模型） |
| 表格 | 文本提取丢失行列结构 | Camelot/pdfplumber 抽表格 + 单独结构化 |
| 扫描件 | 文本层为空 | OCR（PaddleOCR 中文效果好） |
| 图文混排 | 图片/公式丢失 | 图表单独抽 + 生成文字摘要/描述 |
| 页眉页脚/水印 | 噪声重复 | 按位置/频率清洗 |

> PDF 表格召回方案详见 [[25.LangChain实现RAG系统时PDF表格数据召回的解决方案]]。

### 4. 结构还原
解析不能只拿纯文本，要尽量还原文档结构：

| 结构要素 | 为什么要保留 |
| --- | --- |
| 标题层级 | 支撑语义切片与父子文档，切片可带上下文 |
| 页码 | 溯源引用必备 |
| 表格编号与表头 | 表格结构化检索 |
| 图注/脚注 | 补全图表语义 |
| 段落边界 | 切片不跨语义单元 |

### 5. 清洗与元数据提取
| 步骤 | 说明 |
| --- | --- |
| 去噪 | 去页眉页脚、水印、重复空行、乱码字符 |
| 编码统一 | 统一 UTF-8，处理特殊字符 |
| 元数据提取 | 来源文件、页码、章节、时间、作者、权限标签 |
| 元数据作用 | 后续过滤检索（时间/来源/权限）与溯源引用 |

### 6. 解析质量对全流程的影响
| 环节 | 解析问题导致的后果 |
| --- | --- |
| 切片 | 结构丢失 → 切片跨语义单元（详见 [[10.RAG中分块的定义及分块的必要性]]） |
| 向量化 | 文本残缺 → embedding 偏离原意 |
| 检索 | 召回不到或召回噪声 |
| 生成 | 证据不全 → 幻觉或答非所问 |

### 7. 一句话总结
文档解析是 RAG 索引流程的第一步：**按格式选解析器（PDF 用 PyMuPDF/pdfplumber、Word 用 python-docx、HTML 用 BeautifulSoup），重点是还原结构（标题/页码/表格/图注）+ 清洗 + 提取元数据**，解析质量直接决定后续切片、检索、生成的上限。
