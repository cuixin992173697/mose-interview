## 提示压缩的定义及在 RAG 中的应用意义

### 1. 什么是提示压缩（Prompt Compression）

提示压缩 = 在把召回的文档片段塞进 Prompt **之前**，对其进行压缩——**去冗余、保关键**，用更少的 token 传递等价甚至更高信噪比的信息。

```
召回 top-k 片段（冗长、含噪声）
   ↓ 提示压缩
精简片段（只留与问题相关的关键句）
   ↓ 拼进 Prompt → LLM 生成
```

它和"上下文截断/摘要"是同一类技术家族，共同目标：**在有限上下文窗口里塞入更高价值的信息。**

### 2. 为什么需要提示压缩

| 痛点 | 说明 |
| --- | --- |
| 片段冗长 | 召回的 chunk 往往含大量无关背景，真正相关的只占一小部分 |
| token 超限 | 多片段拼接易超出模型上下文窗口 |
| 噪声稀释关键信息 | 大量无关文本稀释了关键句的注意力权重 |
| Lost-in-the-middle | 模型对长上下文中段的信息利用差，关键信息被埋没 |
| 成本与延迟 | token 越多，推理越慢越贵 |

一句话：**召回得多≠用得多，压缩负责把"有用的"从"召回的"里提炼出来。**

### 3. 实现方式

#### 方式一：抽取式压缩（Extractive）

从每个片段里**抽取与 query 相关的关键句**，丢弃其余。

- 方法：按句子切分，用相似度/相关性打分，保留 top 句子。
- 优点：无信息捏造，保真度高、快。
- 缺点：只删不加，压缩比有限。

#### 方式二：生成式压缩（Generative / 摘要）

让 LLM 把片段**摘要**成与问题相关的精简表述。

- 方法：Prompt 指示"仅依据以下片段，提取与问题相关的要点"。
- 优点：压缩比大、可重组表达。
- 缺点：多一次 LLM 调用（成本/延迟），有幻觉/信息丢失风险。

#### 方式三：专用压缩模型（token 级压缩）

用专门训练的小模型在 **token 级别**判断每个 token 是否该保留，直接输出压缩后的 token 序列。

- 代表：**LLMLingua**、**LongLLMLingua**（微软）。
- 原理：用小语言模型（如 GPT-2/Llama-7B）计算每个 token 的困惑度（perplexity），保留"信息量大、困惑度高"的 token，丢弃低信息量 token。
- 优点：压缩比高（可达 2~20×）、保真度较好、比再调大模型便宜。
- 缺点：引入额外小模型推理；极端压缩下语义可能受损。

```python
# LLMLingua 思路
from llmlingua import PromptCompressor
compressor = PromptCompressor(model_name="microsoft/llmlingua-2-bert-base-multilingual-cased-meetingbanker")
compressed = compressor.compress_prompt(
    recall_docs, rate=0.5, force_tokens=["问题", "答案"]
)
# compressed["compressed_prompt"] 即压缩后的上下文
```

#### 方式四：结构化 / 模板压缩

把片段转成结构化键值（如"来源→要点"表格），去掉自然语言冗余，靠格式省 token。

### 4. 三种方式对比

| 方式 | 压缩比 | 保真度 | 成本/延迟 | 适用 |
| --- | --- | --- | --- | --- |
| 抽取式 | 中 | 高（不捏造） | 低 | 追求保真、片段较长 |
| 生成式摘要 | 高 | 中（可能丢/编） | 高（多调 LLM） | 片段极长、可容忍轻微失真 |
| 专用压缩模型 | 高 | 中高 | 中（小模型） | 工业级通用首选（LLMLingua） |
| 结构化模板 | 中 | 高 | 低 | 结构化数据/表格场景 |

### 5. 应用意义

| 意义 | 说明 |
| --- | --- |
| 降本 | 压缩后 token 少，推理成本↓ |
| 提速 | 输入短，首 token 延迟↓ |
| 提升信噪比 | 去噪后关键信息占比↑，生成更聚焦准确 |
| 突破上下文限制 | 同一窗口能塞更多有效片段 |
| 缓解 lost-in-the-middle | 关键信息更易落在模型高注意力区 |

### 6. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 压缩率权衡 | 率越高越省但越易丢信息，需评测集调参（常见 0.3~0.7） |
| 压缩时机 | 在 Rerank 之后、拼 Prompt 之前压缩，只压真正要用的 top-K |
| 保关键 token | 用 force_tokens 保留 query 关键词、引用标记等不可丢的 token |
| 评测保真 | 压缩后用答案准确率/忠实度对比，确保压缩没伤效果 |
| 与缓存配合 | 压缩后上下文更稳定，利于语义缓存命中 |

### 7. 一句话总结

提示压缩 = **在召回片段拼进 Prompt 前，用抽取/摘要/专用模型（LLMLingua）去冗余保关键**，降低 token 成本与延迟、提升信噪比，是 RAG 上下文工程中"省着用窗口、用得更有价值"的关键手段。
