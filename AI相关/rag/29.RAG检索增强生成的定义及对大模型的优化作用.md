## RAG 检索增强生成的定义及对大模型的优化作用

### 1. RAG 的定义

RAG（Retrieval-Augmented Generation，检索增强生成）= 检索 + 生成。在调用大模型回答前，先从外部知识库检索相关片段，拼入 Prompt，让模型基于"问题+证据"生成答案。（完整定义与工作流程见 [[01.简述RAG的定义及核心工作流程+局限性]]、[[04.详解RAG的完整工作流程]]）

### 2. 对大模型的优化作用

RAG 不是替代大模型，而是补大模型的短板，让其在事实性、时效性、可信度上大幅提升：

| 优化作用 | 说明 |
| --- | --- |
| ① 注入实时/私有知识 | 大模型知识止于训练截止日，RAG 接入实时数据与企业私有文档 |
| ② 降低幻觉 | 答案有据可依，模型不必凭参数记忆"猜" |
| ③ 可溯源可信 | 每个结论可追到原文，用户能核对 |
| ④ 知识更新无需重训 | 改知识库即可，省去昂贵的重新训练 |
| ⑤ 低成本领域适配 | 无需微调即可让通用模型服务垂直领域 |
| ⑥ 提升事实准确性 | 领域事实从外部权威源获取，比模型记忆更准 |

### 3. RAG vs 微调：什么时候用哪个

二者不是对立，而是互补——RAG 管"知识"，微调管"能力/风格/格式"。

| 维度 | RAG | 微调（Fine-tuning） |
| --- | --- | --- |
| 解决什么 | 知识缺失、时效、幻觉 | 能力/风格/输出格式/特定任务 |
| 知识更新 | 改库即可，即时 | 需重新训练，慢且贵 |
| 成本 | 低（无需训练） | 高（数据+算力+标注） |
| 可溯源 | 是 | 否（知识压进权重） |
| 幻觉控制 | 强（有证据） | 弱（仍可能编造） |
| 适合场景 | 事实问答、文档问答、知识库 | 风格统一、格式固定、领域推理能力 |

选型建议：

| 场景 | 推荐 |
| --- | --- |
| 知识常更新、需溯源 | RAG |
| 输出风格/格式固定、推理模式特定 | 微调 |
| 既要领域知识又要领域能力 | RAG + 微调结合 |
| 预算有限、快速验证 | RAG（成本低、见效快） |

### 4. 一句话总结

RAG 通过**外挂知识库**优化大模型：注入实时私有知识、降低幻觉、可溯源、低成本适配领域——它和微调一个管"知识"一个管"能力"，常结合使用。
