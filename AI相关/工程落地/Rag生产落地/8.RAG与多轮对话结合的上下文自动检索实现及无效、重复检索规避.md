## RAG 与多轮对话结合的上下文自动检索实现及无效、重复检索规避

> 多轮对话里每轮都检索既慢又浪费，但不检索又怕漏新知识。本篇讲何时自动检索、如何规避无效与重复检索。查询改写见 rag 目录的《43.RAG中Query Rewriting查询重写的定义及检索效果优化方法》，检索不到的处理见《44.RAG检索不到相关文档的处理方案》。

### 1. 多轮 + RAG 的核心矛盾

| 矛盾 | 说明 |
| --- | --- |
| 每轮都检索 | 慢、贵、多数轮次其实是闲聊/追问，无需新知识 |
| 不检索 | 用户可能引入新话题，靠历史上下文答不出 |
| 指代问题 | "它/那个"指代前文，直接检索拿不到实体 |
| 重复检索 | 同一问题反复问，每次都检索召回同样结果，浪费 |

一句话：**得判断"这轮到底要不要检索、检索什么"，并复用已有结果**。

### 2. 上下文自动检索：判断何时检索

| 判断步骤 | 做法 |
| --- | --- |
| ① 意图判断 | LLM/分类器判断本轮是否需要外部知识（闲聊/澄清→不检索；事实提问→检索） |
| ② 指代消解 | 多轮中把"它/那个"还原成实体，生成独立可检索 query（历史改写） |
| ③ 新知识判断 | 本轮话题是否已在历史上下文中？在则复用，不在则检索 |
| ④ 检索触发 | 仅当"需要外部知识 且 未在历史中"时触发检索 |

```text
历史：用户问过"RAG 是什么"，已检索回答
当前："它的局限性呢？"
→ 指代消解："RAG 的局限性是什么？"
→ 判断：需要外部知识（局限性是新内容），历史上下文没有 → 触发检索
```

### 3. 无效检索规避

| 场景 | 规避手段 |
| --- | --- |
| 闲聊/寒暄轮次 | 意图判断为非知识型，跳过检索 |
| 澄清/追问 | "你是说 X 吗？"——不需新知识，跳过 |
| 历史已有答案 | 本轮问题等价于历史某轮，复用历史答案，不检索 |
| 检索结果为空 | 召回分数全低于阈值，直接走拒答（见 rag 目录《44》）而非反复重试 |

### 4. 重复检索规避

| 手段 | 说明 |
| --- | --- |
| query 去重 | 对当前 query 做归一化（小写/去停用词/语义哈希），命中缓存则复用 |
| 历史结果缓存 | 按 query 缓存召回结果，相同/相似 query 复用（见 [[3.同一用户同一问题的检索结果缓存设计及缓存过期与新知识更新的平衡]]） |
| 上下文复用 | 上一轮召回的片段仍在上下文窗口内时，本轮不重复检索同主题 |
| 会话级检索状态 | 记录本会话已检索过的 query+结果，避免会话内重复 |

### 5. 多轮检索的完整流程

```
用户输入
  │
  ├─ 意图判断 → 闲聊/澄清？→ 是：直接用历史上下文生成，不检索
  │                          ↓ 否
  ├─ 历史改写 → 指代消解生成独立 query
  │                          ↓
  ├─ 缓存/去重命中？→ 是：复用历史召回结果，跳过检索
  │                          ↓ 否
  ├─ 触发检索 → 多路召回 → Rerank
  │                          ↓
  ├─ 结果缓存写入（供后续轮次复用）
  │                          ↓
  └─ 组装上下文（历史 + 本轮召回）→ LLM 生成
```

### 6. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 改写质量 | 历史改写跑偏会带偏检索，需评测改写后召回率（见 rag 目录《43》） |
| 缓存粒度 | 按 query 缓存召回结果，注意知识更新时的失效（见 [[3.同一用户同一问题的检索结果缓存设计及缓存过期与新知识更新的平衡]]） |
| 意图分类器要轻 | 每轮都过分类器，用规则/小模型，别用大模型拖延迟 |
| 上下文窗口管理 | 多轮历史 + 多次召回会膨胀，需压缩/摘要管理（见 agent 目录《21》《27》） |
| 会话隔离 | 不同会话的检索缓存/状态隔离，防串（见 agent 目录《36》） |

### 7. 一句话总结

多轮对话 + RAG 的关键是**按需检索**：先用意图判断 + 历史改写决定"这轮要不要检索、检索什么"，再用 query 去重 + 历史结果缓存 + 上下文复用规避无效与重复检索，闲聊/澄清/已有答案的轮次直接跳过——既保证新话题能拿到知识，又避免每轮都检索的浪费。模糊问题优化见 [[4.模糊用户问题的意图识别、查询改写及多路召回优化方法]]，缓存设计见 [[3.同一用户同一问题的检索结果缓存设计及缓存过期与新知识更新的平衡]]。
