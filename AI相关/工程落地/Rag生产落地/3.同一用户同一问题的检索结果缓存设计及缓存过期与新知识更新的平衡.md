## 同一用户同一问题的检索结果缓存设计及缓存过期与新知识更新的平衡

> 检索结果缓存是 RAG 降延迟降成本的最有效手段之一，但缓存"该过期时不过期"会返回过时答案。本篇讲缓存设计 + 过期与知识更新的平衡。

### 1. 为什么需要结果缓存

| 价值 | 说明 |
| --- | --- |
| 降延迟 | 命中缓存 <5ms 返回，省掉 embedding+检索+生成 |
| 降成本 | 省掉重复 embedding 调用、LLM 生成 token |
| 抗并发 | 热点问题命中缓存，保护后端检索与 LLM |

RAG 场景有大量重复/相似问题（FAQ、热门咨询），缓存命中率往往可观。

### 2. 缓存设计

#### 缓存 key 设计

| 方式 | key | 特点 |
| --- | --- | --- |
| 精确缓存 | query 归一化（去空格/统一大小写/标点）后 hash | 严格匹配，命中率高但只认字面相同 |
| 语义缓存 | query 向量近邻匹配 | 相似问题复用，命中面广但有过时风险 |

> 精确缓存用归一化后的 query 文本做 key；语义缓存用 query embedding 找相似度 >阈值的已缓存 query。

#### 缓存层级

| 缓存层 | 缓存内容 | 命中收益 |
| --- | --- | --- |
| embedding 缓存 | query → embedding | 省 embedding 调用 |
| 检索片段缓存 | query → 召回的 top-K chunks | 省检索，仍需生成 |
| 结果缓存（端到端） | query → 最终答案 | 省整条链路，最快 |
| 生成缓存 | (query, chunks) → answer | 省 LLM 生成 |

### 3. 过期策略

| 策略 | 说明 | 适用 |
| --- | --- | --- |
| TTL | 写入后 N 时间过期 | 兜底，所有缓存都应设 |
| 主动失效 | 知识更新/删除时主动删相关缓存 | 强一致场景 |
| 版本号失效 | 缓存带知识 version，检索时比对，version 变则失效 | 精准失效 |
| LRU 淘汰 | 容量满时淘汰最久未用 | 控内存 |

### 4. 与新知识更新的平衡（核心难点）

缓存的最大风险：**知识库已更新，但缓存还返回旧答案**。

| 平衡手段 | 说明 |
| --- | --- |
| 知识更新触发失效 | 文档增删改时，主动失效相关缓存（按文档/分片粒度） |
| 版本号比对 | 缓存记录命中的知识 version，返回前比对当前 version，不一致则失效重查 |
| 按文档粒度失效 | 文档更新时，只失效"召回过该文档"的缓存，避免全量失效 |
| 语义缓存从严 | 语义缓存更难过时，需更短 TTL + version 校验，或关键场景不用语义缓存 |
| 分级 TTL | 高频变动知识短 TTL，稳定知识长 TTL |

> 语义缓存失效最难：相似 query 复用结果，但"相似"不等于"答案未变"，必须叠加 version 校验。

### 5. 缓存与更新联动流程

```
查询：
  query 归一化 → 查缓存
    ├ 命中且 version 一致 → 返回缓存（快）
    └ 未命中/version 不一致 → 走检索+生成 → 写缓存（带当前 version）

知识更新：
  文档增删改 → 失效"召回过该文档"的缓存条目 → 相关缓存下次查询自动重查
```

### 6. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 缓存带 version | 每条缓存记录命中的知识 version，返回前校验，防过时 |
| 语义缓存慎用 | 关键/强一致场景优先精确缓存，语义缓存只用于容错场景 |
| 命中率监控 | 命中率低则优化 key 设计，过高反而警惕过时风险 |
| 热点预热 | 高频问题预热缓存，降首查延迟 |
| 隔离用户敏感数据 | 用户私有数据相关结果不进共享缓存，或按用户隔离 |
| TTL 兜底 | 任何缓存都设 TTL 上限，防永久过时 |

> 性能优化与成本控制通用方法见 rag 目录的《40.生产环境中RAG系统的性能优化与成本控制方法》，百万级低延迟架构见 [[1.百万级文档RAG检索延迟小于200ms的索引、分片、缓存架构设计结合Milvus与Chroma]]。

### 7. 一句话总结

检索结果缓存 = **精确缓存（归一化 query 做 key）+ 语义缓存（相似 query 复用）+ 多级（embedding/片段/结果/生成）**；与新知识平衡的关键是 **版本号校验 + 知识更新触发按文档粒度失效 + TTL 兜底**，语义缓存必须叠加 version 校验防过时。
