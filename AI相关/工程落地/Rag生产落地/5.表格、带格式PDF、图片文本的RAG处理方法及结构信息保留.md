## 表格、带格式 PDF、图片文本的 RAG 处理方法及结构信息保留

> 纯文本切片会丢掉表格结构、PDF 格式、图片信息，导致召回不到表内数据、丢失上下文层级。本篇讲这三类富文档的处理与结构保留。

### 1. 表格处理

| 步骤 | 做法 |
| --- | --- |
| 专用解析 | pdfplumber / Camelot / Unstructured 识别表格结构（行列），而非纯文本抽取 |
| 结构化转换 | 表格转 Markdown 表格 / 键值对 / JSON，保留行列关系 |
| 长表降维 | 超宽表转成多行"字段:值"文本，便于向量化 |
| 独立切片 | 表格作为独立 chunk，不被切断 |
| 摘要增强 | LLM 生成表格自然语言摘要，摘要与表格关联（父子文档），摘要检索命中后回填整表 |

```
原始表格：
| 产品 | 价格 | 库存 |
| GPT-4 | $0.03 | 100 |

结构化文本：
"产品 GPT-4 的价格为 $0.03，库存为 100。"  ← 利于检索
```

> PDF 表格召回详见 rag 目录的《25.LangChain实现RAG系统时PDF表格数据召回的解决方案》。

### 2. 带格式 PDF 处理

| 结构信息 | 保留方法 |
| --- | --- |
| 标题层级 | 解析 H1/H2/H3，切片时按标题边界切，元数据记录层级路径 |
| 页码 | chunk 元数据带 page，溯源精确到页 |
| 段落边界 | 按段落切而非固定长度，保语义完整 |
| 列表/编号 | 保留列表项关系，避免拆散 |
| 样式/字体 | 关键样式（加粗/标题）可转 Markdown 标记保留 |

> 关键：**用结构化切片（按标题/段落）替代固定长度切片**，结构信息天然保留在 chunk 边界与元数据里。

### 3. 图片文本处理

| 类型 | 处理方法 |
| --- | --- |
| 扫描件/图片 PDF | OCR（PaddleOCR/Tesseract）提取文字 |
| 含图文档 | 图表/图片用 LLM/多模态模型生成文字摘要，摘要入库可检索 |
| 图片本身 | 多模态 embedding（CLIP 等）向量化图片，或摘要文本向量化 |
| 图注 | 保留图注文字与图片关联 |

> 图片摘要 + 父子文档：摘要检索命中 → 回填图片/原图引用。

### 4. 结构信息保留的总策略

| 策略 | 说明 |
| --- | --- |
| 元数据标注 | chunk 带 source/page/section/类型(文本/表格/图片) 元数据 |
| 父子文档 | 检索用小切片（子），生成回填大上下文（父：整表/整节） |
| 结构化切片 | 按标题/段落/表格边界切，而非固定长度 |
| 摘要增强 | 表格/图表生成文字摘要，摘要与原文关联 |
| 上下文路径 | chunk 记录所属标题路径（如"第3章 > 3.2 节"），保层级 |

### 5. 处理流程

```
富文档（PDF/带表格/带图）
  → 结构化解析（Unstructured/pdfplumber/OCR）
  → 分类型处理：
       文本 → 按标题/段落切片
       表格 → 转 Markdown + 摘要，独立 chunk
       图片 → OCR/多模态摘要，独立 chunk
  → 元数据标注（page/section/类型）
  → 父子文档关联（摘要检索→回填原文）
  → 向量化入库
```

### 6. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 表格别切散 | 表格整体作一个 chunk，切断则行列关系丢 |
| 摘要+原文双索引 | 摘要检索精度高，原文保证生成上下文完整 |
| 元数据贯穿 | page/section 用于溯源与过滤检索 |
| OCR 纠错 | 扫描件 OCR 错字影响召回，关键场景做纠错 |
| 多模态可选 | 图片多的话用多模态 embedding，少则文字摘要够用 |

> 文档解析通用方法见 rag 目录的《15.RAG索引流程中文档解析的实现方式》，多格式处理见《48.RAG系统对PDF、Word、Markdown等多格式文档的处理方法》，长文档中间内容丢失见 [[6.长文档10万字+RAG中间内容丢失的解决方法（父子分块、分层检索等）]]。

### 7. 一句话总结

富文档处理 = **表格专用解析转 Markdown/键值+独立切片+摘要 / 带格式 PDF 按标题段落结构化切片保层级 / 图片 OCR+多模态摘要**，结构信息靠**元数据标注 + 父子文档（摘要检索回填原文）+ 结构化切片**保留，避免纯文本切片丢结构。
