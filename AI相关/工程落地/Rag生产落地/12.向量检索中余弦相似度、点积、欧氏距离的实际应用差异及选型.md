## 向量检索中余弦相似度、点积、欧氏距离的实际应用差异及选型

> 本篇讲余弦相似度、点积（dot product）、欧氏距离三种度量在**生产向量检索**中的实际差异与选型。基础定义见 rag 目录的《22.向量数据库中余弦相似度、欧几里得距离、曼哈顿距离的定义及差异》，文本相似度算法全景见《38.RAG中文本相似度的计算方法及常见算法》。

### 1. 三种度量定义与公式

| 度量 | 公式 | 值域 | 越大/越小越相似 |
| --- | --- | --- | --- |
| 余弦相似度 Cosine | cos(A,B)=A·B/(‖A‖·‖B‖) | [-1, 1] | 越大越相似 |
| 点积 Dot Product | A·B = Σ aᵢbᵢ | (-∞, +∞) | 越大越相似 |
| 欧氏距离 L2 | d(A,B)=√(Σ(aᵢ-bᵢ)²) | [0, +∞) | 越小越相似 |

### 2. 实际应用差异

| 差异点 | 说明 |
| --- | --- |
| 归一化后点积 = 余弦 | 向量归一化（L2 norm=1）后，‖A‖=‖B‖=1，点积 A·B = cos(A,B)。很多向量库内部对归一化向量用点积冒充余弦，速度更快 |
| 余弦只看方向 | 与向量幅度无关，只比较语义方向——文本检索最常用，因 embedding 后幅度无意义 |
| 点积受范数影响 | 未归一化时点积 = 余弦×‖A‖×‖B‖，幅度大的向量点积偏大，排序会被幅度带偏；但计算最快（无除法无开方） |
| 欧氏受幅度影响 | 同时受方向和幅度影响，幅度差异大的向量欧氏距离大；图像/数值向量有时用 |

### 3. 选型表

| 场景 | 推荐度量 | 理由 |
| --- | --- | --- |
| 文本语义检索（RAG 主力） | 余弦相似度 / 归一化点积 | embedding 后只关心语义方向，幅度无意义 |
| 追求极致检索速度 | 归一化向量 + 点积（IP） | 归一化后点积=余弦，但点积计算最快，向量库 ANN 索引（HNSW）原生支持 |
| 图像/数值向量 | 欧氏距离 L2 | 幅度/位置有意义，距离反映整体差异 |
| 模型已输出归一化向量 | 点积 | 等价余弦且最快 |
| 不确定 | 余弦 | 最稳，对幅度不敏感 |

> 生产实践：**文本 RAG 几乎一律用余弦或"归一化后的点积"**。二者等价，选哪个看向量库支持与是否预归一化——Milvus/Chroma 都支持 COSINE/IP/L2，存向量时归一化、检索用 IP 是常见加速组合。

### 4. 归一化的作用与陷阱

| 要点 | 说明 |
| --- | --- |
| 为什么归一化 | 让点积等价余弦，既保语义又快；统一向量尺度，ANN 索引更稳 |
| 何时归一化 | embedding 后立即归一化再入库；query 向量同样归一化 |
| 陷阱：混合归一化 | 库里向量有的归一化有的没归一化，点积排序失真——务必全库统一 |
| 陷阱：度量与索引不匹配 | 用 L2 索引却按余弦排序会出错；索引与检索度量必须一致 |

### 5. 一句话总结

文本 RAG 向量检索度量选型：**归一化向量 + 点积（IP）= 余弦，语义准且计算最快，是生产主力组合**；欧氏距离留给图像/数值向量；关键是"向量归一化要全库统一、索引度量与检索度量要一致"。Embedding 模型选型见 [[11.中英文混合文档场景下Embedding模型的选型方法平衡效果与速度]]。
