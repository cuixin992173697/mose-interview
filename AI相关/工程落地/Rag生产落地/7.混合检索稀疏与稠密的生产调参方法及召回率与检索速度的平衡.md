## 混合检索稀疏与稠密的生产调参方法及召回率与检索速度的平衡

> 混合检索（BM25 稀疏 + 向量稠密）落地难在调参——权重怎么定、召回量给多少、速度怎么保。本篇讲生产调参实操。基础定义见 rag 目录的《03.混合检索的定义及在大模型应用中的核心作用》，LangChain 实现见《52.RAG混合检索的定义及向量检索与关键词检索的结合实现》，评估见《09.RAG调优后效果评估的方法及实际应用中的评估标准》。

### 1. 需要调的参数清单

| 参数 | 所在环节 | 作用 | 典型范围 |
| --- | --- | --- | --- |
| α（向量权重） | 融合 | 稠密 vs 稀疏的相对比重 | 0.5~0.7 |
| BM25 k1 | 稀疏检索 | 词频饱和度 | 1.2~2.0 |
| BM25 b | 稀疏检索 | 文档长度归一化 | 0.5~0.75 |
| RRF k | RRF 融合 | 排名平滑 | 60 |
| top-N（每路召回量） | 检索 | 一阶段召回宽度 | 50~100 |
| top-K（最终返回） | 融合后 | 送 Rerank/上下文 | 5~10 |
| ANN efSearch/HNSW M | 向量索引 | 召回率 vs 速度 | 越高越准越慢 |

### 2. 召回率 vs 检索速度的平衡

混合检索的耗时 = 向量检索 + BM25 检索 + 融合计算，三者都要平衡：

| 平衡维度 | 提速手段 | 对召回率的影响 |
| --- | --- | --- |
| top-N 召回量 | 调小 N（如 100→50） | 召回率↓，需评测找拐点 |
| 向量索引参数 | 降 HNSW efSearch/M | 召回率↓，但通常影响小 |
| BM25 扫描 | 限制候选文档集（元数据预过滤） | 召回率不变，速度↑ |
| 融合计算 | RRF（只算排名）比加权融合快 | 几乎无精度损失 |
| 并行检索 | 向量与 BM25 并行执行 | 速度↑，精度不变 |

> 经验：**召回阶段宁宽勿漏（N 大），精排阶段宁精勿杂（K 小 + Rerank）**。把精度压力交给 Rerank，检索只保召回率。

### 3. 调参方法：评测集驱动

不要拍脑袋调参，用评测集量化：

| 步骤 | 做法 |
| --- | --- |
| ① 建评测集 | 标注 (query, 相关文档集合) 100~500 条，覆盖语义型/精确型/混合型 |
| ② 选指标 | recall@k（召回率）、MRR（平均倒数排名）、nDCG |
| ③ 网格/贝叶斯调参 | 遍历 α ∈ {0.3,0.4,...,0.7}、N ∈ {50,80,100} 组合，算指标 |
| ④ 拐点选择 | 选 recall@k 不再明显上升、延迟可接受的最小 N 和最优 α |
| ⑤ 回归验证 | 改参数后跑全量评测集回归，防局部优化 |

```python
# 调参示例：遍历 α 找最优 recall@10
from itertools import product
best, best_score = None, 0
for alpha, N in product([0.3,0.4,0.5,0.6,0.7], [50,80,100]):
    scores = []
    for q, rel in eval_set:
        ranked = hybrid_retrieve(q, alpha=alpha, top_n=N)
        hit = len(set(ranked[:10]) & set(rel))
        scores.append(hit / max(len(rel),1))   # recall@10
    score = sum(scores)/len(scores)
    if score > best_score:
        best, best_score = (alpha, N), score
print("best:", best, "recall@10:", best_score)
```

### 4. 生产调参实操流程

| 阶段 | 动作 |
| --- | --- |
| 起步 | α=0.6、N=80、K=10、RRF k=60，跑通基线 |
| 评测 | 在评测集上算 recall@k / MRR，记录基线 |
| 调 α | 精确型 query 多则降 α（偏 BM25），语义型多则升 α |
| 调 N/K | 找 recall@k 拐点定 N，按上下文预算定 K |
| 加 Rerank | 检索保召回，Rerank 保精度，K 可适当放大后精排 |
| 上线+回归 | 线上采样回流持续评测，参数漂移时回归调参 |

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 分场景调参 | 不同业务（法律精确 vs 客服语义）最优 α 不同，别一套参数走天下 |
| 评测集代表性 | 必须覆盖长尾 query，否则调参过拟合到常见问题 |
| 速度预算 | 先定延迟 SLA（如 P95<200ms），再反推可接受的 N 和索引参数 |
| 动态权重 | 按查询类型动态调 α（见场景架构目录的多路召回动态权重），比固定值更稳 |
| Rerank 兜底 | 调参再细也有偏差，Rerank 统一精排最稳（见 [[13.RAG中rerank重排模型的选型及重排速度优化方法]]） |

### 6. 一句话总结

混合检索生产调参 = **评测集驱动地调 α（向量权重）、BM25 参数（k1/b）、RRF k、top-N/K、ANN 索引参数，在 recall@k/MRR 与 P95 延迟间找拐点**；原则是"召回宁宽、精排宁精"——检索保召回率、Rerank 保精度，再用动态权重适配不同 query 类型。自动化评估见 [[10.生产环境RAG效果的自动化评估方案召回率、MRR、Answer Relevancy实操]]。
