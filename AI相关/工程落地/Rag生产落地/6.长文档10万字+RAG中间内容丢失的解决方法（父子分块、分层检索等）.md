## 长文档 10 万字+ RAG 中间内容丢失的解决方法（父子分块、分层检索等）

> 长文档做 RAG 时，中间章节的内容经常"召不回、答不出"——本篇讲为什么丢、怎么用父子分块与分层检索捞回来。分块基础见 rag 目录的《10.RAG中分块的定义及分块的必要性》《11.RAG中常见分块策略及各自差异》，整体流程见《04.详解RAG的完整工作流程》。

### 1. 为什么长文档中间内容会丢失

| 丢失原因 | 说明 |
| --- | --- |
| 首尾偏倚 | 用户提问倾向命中开头/结尾片段，中间章节召回概率低 |
| 切片切断语义 | 中间章节被切到多个 chunk，单个 chunk 语义不全，相似度低被排掉 |
| lost-in-the-middle | 即便召回到中间片段，LLM 对长上下文中段信息注意力弱，仍答不出 |
| 摘要/目录未索引 | 中间章节的标题、摘要没单独建索引，无法被"概览式"检索命中 |
| 上下文断裂 | 召回到中间一个 chunk，但缺前后文，模型读不懂 |

一句话：**中间内容既"召不回"（检索层），又"答不出"（生成层）**，得两头治。

### 2. 方法一：父子分块（Parent-Child Chunking）

核心思想：**检索用小块（精准命中），生成用大块（上下文完整）**。

```
父块（大段，如一个章节 1000~2000 token）
  ├─ 子块1（小段 200~300 token）→ 建向量索引，用于检索
  ├─ 子块2 → 建向量索引
  └─ 子块3 → 建向量索引
检索：query 命中某子块 → 回填其所属父块进上下文
```

| 维度 | 子块 | 父块 |
| --- | --- | --- |
| 大小 | 小（200~300 token） | 大（章节级 1000~2000 token） |
| 用途 | 向量化、检索命中 | 回填上下文、送 LLM 生成 |
| 索引 | 建向量索引 | 存 docstore，不建向量索引 |
| 关联 | 子块记录 parent_id | 父块存完整文本 |

价值：小块保证中间细节能被精准召回，父块保证命中后上下文完整、不因切片断裂而读不懂。LangChain 用 `ParentDocumentRetriever` / `MultiVectorRetriever` 落地。

### 3. 方法二：分层检索（Hierarchical Retrieval）

核心思想：**先粗后细，逐层定位**，避免一次性在全部细 chunk 里大海捞针。

```
第一层：摘要/目录索引（每章摘要、标题）
  → 检索定位到"第 5 章"相关
第二层：该章的细 chunk 索引
  → 在第 5 章内细检索，命中具体段落
```

| 层级 | 内容 | 作用 |
| --- | --- | --- |
| L1 摘要层 | 每章/节摘要 + 标题，建索引 | 粗筛定位相关章节 |
| L2 细节层 | 章节内细 chunk，建索引 | 精准召回具体段落 |
| （可选）L3 全文 | 完整原文 | 命中后回填大上下文 |

价值：中间章节只要其摘要能被 L1 命中，就能进入 L2 精检，大幅提升中段内容召回率；同时缩小 L2 搜索范围，提速。

### 4. 其他配套方法

| 方法 | 说明 |
| --- | --- |
| 滑动窗口 overlap | 切片间保留 10%~20% 重叠，避免关键句被切断在边界 |
| 章节感知切片 | 按标题层级切，不让 chunk 跨章节，保语义完整 |
| 多粒度索引 | 同时建句子级 + 段落级 + 章节级索引，按 query 粒度路由检索 |
| 上下文扩展 | 命中 chunk 后，将其前后相邻 chunk 一并回填（context window 扩展） |
| 摘要增强 | 给每个 chunk 生成摘要，摘要与原文都建索引（MultiVector） |
| Lost-in-the-middle 规避 | 上下文组装时把最相关片段放首尾，中段放次要内容 |

### 5. 方法选型与组合

| 场景 | 推荐组合 |
| --- | --- |
| 长技术文档/手册（结构清晰） | 章节感知切片 + 分层检索（摘要定位+细节精检） |
| 长合同/长报告（细节密集） | 父子分块 + 滑动窗口 overlap |
| 超长文档（百万字） | 分层检索 + 多粒度索引 + 上下文扩展 |
| 通用兜底 | 父子分块 + Rerank 精排（见 [[13.RAG中rerank重排模型的选型及重排速度优化方法]]） |

### 6. 一句话总结

长文档中间内容丢失要两头治：**检索层用父子分块（小块命中、大块回填）+ 分层检索（摘要定位、细节精检）提升中段召回率，生成层用上下文扩展与首尾排序规避 lost-in-the-middle**；再配合章节感知切片、滑动窗口、多粒度索引，让 10 万字+ 文档的中段细节召得回、答得出。多格式文档处理见 [[5.表格、带格式PDF、图片文本的RAG处理方法及结构信息保留]]，检索调参见 [[7.混合检索稀疏与稠密的生产调参方法及召回率与检索速度的平衡]]。
