## RAG 中 rerank 重排模型的选型及重排速度优化方法

> 本篇讲 rerank 模型选型与速度优化。rerank 的含义与实现见 rag 目录的《02.RAG中Rerank的含义及实现方式》，必要性见《37.RAG中Reranking重排序的必要性及实现方式》。

### 1. rerank 模型选型

| 模型 | 类型 | 精度 | 速度 | 成本 | 语言 | 适用 |
| --- | --- | --- | --- | --- | --- | --- |
| bge-reranker-large | Cross-Encoder 开源 | ★★★★★ | ★★★ | 自部署 GPU | 中英 | 中文生产首选，精度高 |
| bge-reranker-base | Cross-Encoder 开源 | ★★★★ | ★★★★ | 自部署 | 中英 | 速度优先 |
| Cohere Rerank | 商用 API | ★★★★★ | ★★★★ | 按调用付费 | 多语言 | 免部署、英文强 |
| jina-reranker | Cross-Encoder 开源 | ★★★★ | ★★★★ | 自部署/免费 | 多语言 | 多语言均衡 |
| ms-marco-MiniLM | Cross-Encoder 开源 | ★★★★ | ★★★★ | 自部署 | 英文 | 英文轻量 |
| LLM as reranker | LLM 打分/排序 | ★★★★☆ | ★★ | LLM 调用费 | 通用 | 零样本、候选少、精度要求极高 |

选型决策：

| 诉求 | 选 |
| --- | --- |
| 中文 + 自部署 + 高精度 | bge-reranker-large |
| 中文 + 速度优先 | bge-reranker-base |
| 免部署 + 英文/多语言 | Cohere Rerank |
| 候选量小 + 复杂语义判断 | LLM reranker |
| 开源 + 多语言 | jina-reranker / bge-reranker-m3 |

### 2. 重排速度优化

| 优化手段 | 说明 | 收益 |
| --- | --- | --- |
| 候选量控制 | 召回 top-N（20~50）→ Rerank top-K（5~10），N 别太大 | 线性降时延，N 减半速度翻倍 |
| 批处理 batch | Cross-Encoder 逐条算，务必 batch + GPU | GPU 利用率↑，吞吐↑数倍 |
| 量化 | INT8/FP16 量化 rerank 模型 | 速度↑、显存↓、精度损失小 |
| 级联粗排+精排 | 先用轻量模型/BM25 粗排 top-100，再用 Cross-Encoder 精排 top-10 | 兼顾召回与精度，省精排算力 |
| 缓存 | 相同 query 的 rerank 结果缓存 | 热点 query 命中率高，直降延迟 |
| 异步/并行 | 多路召回结果合并后并行 rerank | 撬墙钟时间 |
| 截断/早停 | 分数远低于 top1 的候选提前丢弃 | 减少无效 forward |

### 3. 精度—速度平衡

| 配置 | 精度 | 速度 | 适用 |
| --- | --- | --- | --- |
| bge-reranker-large + N=50 + FP32 | ★★★★★ | ★★ | 离线/精度优先 |
| bge-reranker-large + N=20 + INT8 | ★★★★☆ | ★★★★ | 生产主力（推荐） |
| bge-reranker-base + N=20 | ★★★★ | ★★★★★ | 延迟敏感 |
| 级联 BM25 粗排 + base 精排 | ★★★★ | ★★★★ | 大候选量 |

> 经验：生产默认 **bge-reranker-large INT8 + 召回 top-20~30 + Rerank top-5~8**，P99 延迟可压到百毫秒级，精度损失可忽略。

### 4. 生产部署要点

| 要点 | 说明 |
| --- | --- |
| GPU 必备 | Cross-Encoder 逐条 forward，CPU 不可接受，务必 GPU + batch |
| 阈值过滤 | 不仅取 top-K，按分数阈值丢弃低相关片段，防噪声进上下文 |
| 与混合检索配合 | 混合检索保召回（见 [[7.混合检索稀疏与稠密的生产调参方法及召回率与检索速度的平衡]]），Rerank 保精度 |
| 超时降级 | Rerank 超时则退回召回排序结果，不阻塞主链路 |
| 监控 | 监控 rerank 延迟、top-K 变化率（重排是否真改变了排序） |

### 5. 一句话总结

rerank 选型与提速：**中文首选 bge-reranker-large，用 INT8 量化 + 候选量控制（top-20→top-5）+ GPU batch + 缓存**，在精度与速度间取生产最优解；候选量过大时用级联粗排+精排。无关片段规避与跑偏优化见 [[9.RAG检索无关片段的规避方法及LLM回答跑偏的优化手段]]。
