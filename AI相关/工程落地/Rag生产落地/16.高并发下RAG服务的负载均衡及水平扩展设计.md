## 高并发下 RAG 服务的负载均衡及水平扩展设计

> RAG 链路由"检索 + 生成"两个差异巨大的环节组成：检索偏 IO/算力（毫秒级）、生成偏 GPU（秒级），两者瓶颈不同、扩展方式也不同。性能优化总览见 rag 目录的《40.生产环境中RAG系统的性能优化与成本控制方法》，Agent 侧并发调度见 Agent生产落地目录的《7.高并发场景下Agent任务的排队、限流、优先级调度实现》，长连接高并发见流式输出目录的《6.高并发QPS≥1000下SSE长连接的复用、心跳检测、超时释放及OOM优化》。

### 1. 高并发挑战：三个环节各有瓶颈

RAG 请求链路：query → embedding → 向量检索 →（Rerank）→ 上下文组装 → LLM 生成。每环节瓶颈不同：

| 环节 | 瓶颈类型 | 典型耗时 | 扩展难点 |
| --- | --- | --- | --- |
| Embedding | CPU/GPU 算力 | 10~50ms | 模型加载重、显存占用 |
| 向量检索 | 内存 + IO | 5~50ms | 索引常驻内存、分片复杂 |
| Rerank | GPU 算力 | 50~200ms | 逐对 forward，慢 |
| LLM 生成 | GPU 算力 | 1~10s | 显存/吞吐上限，最贵最慢 |

> 生成是吞吐瓶颈（秒级、GPU 贵），检索是延迟瓶颈（要 <200ms）。水平扩展策略必须分别对待，不能一刀切。

### 2. 负载均衡策略

| 策略 | 适用环节 | 做法 |
| --- | --- | --- |
| 无状态服务水平扩展 | embedding / Rerank / 生成网关 | 多实例 + 负载均衡（round-robin / 最少连接） |
| 向量库分片 | 向量检索 | 按文档 id hash 分片到多节点，并行检索后合并 |
| 读写分离 | 向量库 | 写入走主节点、检索走副本，避免写影响检索延迟 |
| 按 query 路由 | 多知识库 | 先路由到目标库再检索，缩小搜索空间 |
| 一致性哈希 | 向量库分片 | 节点扩缩容时最小化数据迁移 |

### 3. 水平扩展分层设计

| 层 | 扩展方式 | 要点 |
| --- | --- | --- |
| Embedding 服务 | 无状态多实例 + GPU 池 | 可任意水平扩展，按 QPS 弹性伸缩 |
| 向量库 | 分片 + 集群 + 副本 | Milvus 集群分片（collection 分 shard）+ 副本提检索吞吐；Chroma 适合中小规模单机或轻量集群 |
| Rerank | 多实例 + 控候选量 | 候选 top-N 控小、batch+GPU、必要时降级跳过 |
| 生成服务 | 多实例 + 请求队列 | 按并发数限流、队列削峰、模型多副本 |
| 缓存层 | 独立缓存集群 | embedding 缓存 + 检索结果缓存 + 语义缓存，分担读压力 |

### 4. 整体架构图

```
                    [负载均衡 / 网关]
                          │
        ┌─────────────────┼─────────────────┐
   embedding 集群      缓存集群         生成服务集群
   (无状态多实例)    (结果/语义缓存)    (多实例+队列)
        │                 │                 │
        └────────┬────────┘                 │
                 │                          │
          [向量库集群]──────────────────────┘
      (分片 shard + 副本 replica)
      Milvus 集群 / Chroma
```

### 5. 容量规划

| 资源 | 估算依据 |
| --- | --- |
| 向量库节点数 | 文档量 × 维度 × 4B ÷ 单节点内存 × 副本数 |
| embedding 实例数 | 峰值 QPS × 单实例吞吐倒数 |
| 生成实例数 | 峰值并发数 ÷ 单实例并发上限（受显存/吞吐约束） |
| 缓存命中率 | 目标 30%~70%，命中部分不计入下游负载 |

### 6. 一句话总结

高并发 RAG 的扩展要分层：**embedding/生成走无状态多实例水平扩展，向量库走分片+副本集群+读写分离，缓存层分担读压力**，并按各环节瓶颈分别估算容量；低延迟检索架构见 [[1.百万级文档RAG检索延迟小于200ms的索引、分片、缓存架构设计结合Milvus与Chroma]]。
