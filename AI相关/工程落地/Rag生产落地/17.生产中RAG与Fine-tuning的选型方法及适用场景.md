## 生产中 RAG 与 Fine-tuning 的选型方法及适用场景

> RAG 和微调不是二选一，而是解决不同问题的两把刀。基础对比见 rag 目录的《46.RAG与模型微调Fine-tuning的差异及选型方法》，RAG 对大模型的优化作用见 rag 目录的《29.RAG检索增强生成的定义及对大模型的优化作用》。

### 1. 本质区别

| 维度 | RAG | Fine-tuning |
| --- | --- | --- |
| 改什么 | 不改模型参数，外挂知识库 | 改模型参数，注入能力/风格/知识 |
| 解决什么 | 知识的"广度+时效+溯源" | 能力的"风格/格式/领域推理/指令遵循" |
| 知识载体 | 外部向量库 | 模型权重 |
| 更新成本 | 更新知识库即可，便宜即时 | 重新训练，贵且慢 |

> 一句话：**RAG 补"知识"，微调补"能力"。**

### 2. 选型方法

| 需求 | 选型 | 理由 |
| --- | --- | --- |
| 知识频繁更新/私有知识/需溯源 | RAG | 知识外置，更新便宜 |
| 改输出风格/语气/格式遵循 | 微调 | 风格是"能力"，靠参数固化 |
| 领域推理能力不足（如医疗推理） | 微调 | 推理能力靠训练注入 |
| 指令遵循/特定任务范式 | 微调 | 指令对齐靠训练 |
| 事实准确性/降低幻觉 | RAG | 有据可依 |
| 既要领域能力又要最新知识 | 微调 + RAG | 微调提能力，RAG 供知识 |

### 3. 生产适用场景

| 场景 | 推荐 |
| --- | --- |
| 企业知识库问答 | RAG |
| 法律/医疗等专业问答 | RAG（强溯源）+ 必要时微调推理 |
| 代码生成（特定框架风格） | 微调 |
| 客服对话（统一话术语气） | 微调风格 + RAG 供产品知识 |
| 实时数据问答 | RAG |
| 固定格式抽取/结构化输出 | 微调 |

### 4. 成本/时效/效果/可解释对比

| 维度 | RAG | Fine-tuning |
| --- | --- | --- |
| 初始成本 | 低（建库） | 高（训练算力+数据） |
| 更新成本 | 极低 | 高（重训） |
| 时效性 | 实时 | 滞后（训练周期） |
| 效果（知识） | 强 | 弱（易忘/冲突） |
| 效果（风格/推理） | 弱 | 强 |
| 可解释/溯源 | 强（有出处） | 弱 |

### 5. 决策流程

```
需求 → 是"知识"问题？
        ├─ 是 → 知识频繁变/需溯源？→ RAG
        └─ 否 → 是"风格/格式/推理能力"问题？→ 微调
        └─ 既要能力又要知识 → 微调 + RAG
```

### 6. 一句话总结

生产选型看问题性质：**"知识"问题（时效/私有/溯源）用 RAG，"能力"问题（风格/格式/领域推理）用微调，二者结合可兼得**；动态知识更新机制见 [[14.动态知识更新场景下RAG的增量更新机制设计避免全量向量化]]。
