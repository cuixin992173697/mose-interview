## 生产环境 RAG 效果的自动化评估方案：召回率、MRR、Answer Relevancy 实操

> 生产 RAG 不能靠"感觉准"，得有自动化评估方案持续量化、驱动迭代。本篇讲评估方案落地与指标实操。评估体系见 rag 目录的《09.RAG调优后效果评估的方法及实际应用中的评估标准》《50.RAG系统效果的评估方法及检索、生成环节的核心评估指标》。

### 1. 自动化评估方案整体架构

| 环节 | 内容 |
| --- | --- |
| 评测集构建 | 标注 (query, 相关文档集, 标准答案) 100~500 条，覆盖各类型 |
| 自动跑批 | 跑全量评测集，收集检索结果 + 生成答案 |
| 指标计算 | 检索指标（recall@k/MRR/nDCG）+ 生成指标（faithfulness/answer relevancy） |
| 回归评测 | 每次改切片/检索/Prompt 后跑回归，对比基线防退化 |
| CI 集成 | 评测脚本接入 CI，指标低于阈值阻断上线 |
| 线上回流 | 采样线上真实 query 标注，持续扩充评测集 |

```
评测集 → 自动跑批 → 指标计算 → 与基线对比 → 回归报告 → CI 卡点
                ↑                                    │
            线上回流采样 ←─────────────────────────────┘
```

### 2. 检索指标实操：recall@k 与 MRR

| 指标 | 含义 | 公式 |
| --- | --- | --- |
| recall@k | 前 k 个结果中命中相关文档的比例 | hit@k / 相关文档总数 |
| MRR | 第一个相关文档排名的倒数的平均 | mean(1/rank_first_relevant) |
| nDCG@k | 考虑排名位置的相关度加权 | DCG/IDCG |

```python
def recall_at_k(ranked_ids, relevant_ids, k):
    hit = len(set(ranked_ids[:k]) & set(relevant_ids))
    return hit / max(len(relevant_ids), 1)

def mrr(ranked_ids, relevant_ids):
    for i, doc_id in enumerate(ranked_ids, 1):
        if doc_id in relevant_ids:
            return 1.0 / i
    return 0.0

# 跑批
recalls = [recall_at_k(r["ranked"], r["relevant"], 10) for r in eval_set]
mrrs = [mrr(r["ranked"], r["relevant"]) for r in eval_set]
print(f"recall@10={sum(recalls)/len(recalls):.3f}, MRR={sum(mrrs)/len(mrrs):.3f}")
```

### 3. 生成指标实操：Answer Relevancy 与 faithfulness

| 指标 | 含义 | 评估方式 |
| --- | --- | --- |
| Answer Relevancy | 答案与问题的相关程度（答非所问？） | LLM-as-judge 或 RAGAS |
| faithfulness | 答案是否忠于上下文（有无幻觉/编造） | 逐句核对答案能否被上下文支持 |
| context precision | 召回上下文中相关片段占比 | 检索质量侧面 |
| context recall | 标准答案所需信息在上下文中的覆盖度 | 检索是否召回到生成所需信息 |

RAGAS 框架实操（四指标自动化）：

```python
from ragas import evaluate
from ragas.metrics import (
    faithfulness, answer_relevancy, context_precision, context_recall
)
from datasets import Dataset

data = {
    "question": [...], "answer": [...],        # LLM 生成答案
    "contexts": [[...], ...], "ground_truth": [...]  # 召回片段 + 标准答案
}
result = evaluate(Dataset.from_dict(data),
                  metrics=[faithfulness, answer_relevancy,
                           context_precision, context_recall])
print(result)  # {'faithfulness':0.85, 'answer_relevancy':0.78, ...}
```

### 4. 评估闭环驱动迭代

| 改动 | 看哪些指标 |
| --- | --- |
| 调切片策略 | recall@k、context_recall |
| 调混合检索参数 | recall@k、MRR、nDCG（见 [[7.混合检索稀疏与稠密的生产调参方法及召回率与检索速度的平衡]]） |
| 加/调 Rerank | MRR、nDCG、context_precision |
| 调 Prompt | faithfulness、answer_relevancy |
| 换 Embedding 模型 | recall@k 全线 |

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 评测集质量 | 比指标算法更重要——标注不准，指标全废；需覆盖长尾/边界 case |
| LLM-as-judge 偏差 | 自动评估有偏差，定期人工抽检校准 |
| 线上回流 | 离线评测集会过时，持续把线上真实 query 标注回流 |
| 回归卡点 | 指标低于基线阈值时 CI 阻断，防改 A 坏 B |
| 成本控制 | 生成指标用 LLM 评估有成本，可抽样评估非全量 |
| 分场景评测 | 按业务场景/文档类型分组评测，定位哪类退化 |

### 6. 一句话总结

生产 RAG 自动化评估 = **构建评测集 → 自动跑批 → 算检索指标（recall@k/MRR/nDCG）+ 生成指标（faithfulness/answer_relevancy，用 RAGAS）→ 回归对比基线 → CI 卡点 → 线上回流持续扩充**；按改动类型盯对应指标，形成"评测驱动迭代"闭环。检索调参联动见 [[7.混合检索稀疏与稠密的生产调参方法及召回率与检索速度的平衡]]。
