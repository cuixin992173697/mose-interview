## 模糊用户问题的意图识别、查询改写及多路召回优化方法

> 用户问题常"又短又糙又多意图"，直接检索召回差。标准解法：**意图识别 → 查询改写 → 多路召回 → 融合**。

### 1. 模糊问题的类型

| 类型 | 表现 | 例子 |
| --- | --- | --- |
| 口语化/简略 | 词面与文档不匹配 | "那个怎么用" |
| 省略/指代 | 多轮中缺主语 | "它的价格呢" |
| 多意图 | 一句话问多件事 | "RAG 和微调的区别及各自成本" |
| 模糊/宽泛 | 检索方向不明确 | "讲讲大模型" |
| 错别字/表述差 | 关键词不对 | "郎格链"（LangChain） |

### 2. 意图识别

| 方法 | 说明 |
| --- | --- |
| 规则/关键词 | 关键词命中分类，快但弱 |
| LLM 分类 | 让 LLM 判断意图类别/是否需检索/路由到哪个库 |
| 多意图拆解 | 一句话多意图时，拆成多个子问题分别处理 |
| 意图路由 | 按意图决定走 RAG / Text-to-SQL / 通用问答 / 拒答 |

```
"RAG 和微调的区别及各自成本"
  → 意图拆解：[RAG vs 微调区别] [RAG 成本] [微调成本]
  → 各子问题分别检索
```

### 3. 查询改写

| 改写方法 | 作用 |
| --- | --- |
| 补全/规范化 | 口语化→书面完整，补主语/实体 |
| 指代消解 | 多轮中"它/那个"还原成实体 |
| 多查询 Multi-Query | 生成多个等价问法，多路召回后融合 |
| HyDE | 先假设答案，用伪答案检索 |
| 同义扩展 | 补同义词/相关词扩大命中 |

> 查询扩展见 rag 目录的《06.查询扩展的定义及在RAG中的应用价值》，查询重写见《43.RAG中Query Rewriting查询重写的定义及检索效果优化方法》。

### 4. 多路召回

| 召回路 | 擅长 | 角色 |
| --- | --- | --- |
| 向量检索 | 语义相似、同义 | 主力 |
| BM25 关键词 | 精确词/专有名词/数字 | 补字面 |
| 多 query 召回 | 多角度覆盖 | 提 recall |
| 元数据过滤 | 缩小范围 | 提精度 |

融合方式：RRF（倒数排名融合，工业首选，免归一化）或加权融合。

> 混合检索见 rag 目录的《03.混合检索的定义及在大模型应用中的核心作用》。

### 5. 优化闭环

```
模糊 query
  → 意图识别（拆解/路由）
  → 查询改写（补全/规范化/Multi-Query）
  → 多路召回（向量+BM25+多query，元数据过滤）
  → RRF 融合 → top-K
  → Rerank 精排
  → 生成
```

每步都可独立评测（recall@k / MRR），定位是改写差还是召回差。

### 6. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 改写别过度 | 简单明确 query 跳过改写，省 LLM 调用 |
| 多 query 控数 | Multi-Query 生成 3~5 个即可，多则成本涨 |
| 意图路由省算力 | 非检索意图别走 RAG（如闲聊直接通用问答） |
| 评测驱动 | 用 recall@k 量化改写/多路召回的收益 |
| 兜底 | 改写后仍召回差时，走未命中处理（见 rag 目录《44.RAG检索不到相关文档的处理方案》） |

> 召回与意图不匹配的整体改进见 rag 目录的《24.RAG系统召回结果与用户query意图不匹配的改进方向》，检索无关片段与跑偏优化见 [[9.RAG检索无关片段的规避方法及LLM回答跑偏的优化手段]]。

### 7. 一句话总结

模糊问题优化 = **意图识别（LLM 分类/拆解/路由）→ 查询改写（补全/规范化/Multi-Query/HyDE）→ 多路召回（向量+BM25+多 query + 元数据过滤）→ RRF 融合 → Rerank 精排**，用 recall@k/MRR 评测每步收益，按需启用避免过度改写增加成本。
