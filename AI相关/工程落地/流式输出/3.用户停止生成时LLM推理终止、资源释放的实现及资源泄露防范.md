## 用户停止生成时 LLM 推理终止、资源释放的实现及资源泄露防范

### 1. 停止生成的触发场景

| 场景 | 说明 |
| --- | --- |
| 用户主动停止 | 点击"停止生成"按钮 |
| 超时停止 | 生成超时或长时间无新 token |
| 页面离开 | 关闭/刷新页面、切走会话 |
| 上游取消 | 网关限流或业务规则主动取消 |

### 2. LLM 推理终止链路（端到端取消）

停止不是"前端不显示就行"，必须把取消信号层层传递到上游 LLM，否则模型仍在烧算力：

```
客户端 AbortController.abort()
   → fetch 取消（关闭 SSE/WS 连接）
   → 网关收到连接断开，取消下游推理请求
   → 推理服务收到取消，关闭上游 LLM stream（如 OpenAI stream 的 close/abort）
   → LLM 停止生成（不再计费后续 token）
```

| 层级 | 取消动作 |
| --- | --- |
| 客户端 | `AbortController.abort()` 取消 fetch，关闭 EventSource/WebSocket |
| 网关 | 检测连接断开，传播 cancel 到下游（带请求 id） |
| 推理服务 | 收到 cancel，关闭上游 LLM stream 连接，停止读取/转发 |
| LLM Provider | stream 连接关闭即停止生成，停止后续 token 计费 |

> 关键：上游 LLM 的 stream 连接必须显式关闭，否则模型继续生成、继续计费，只是结果被丢弃——这是最常见的"隐形资源泄露"。

### 3. 资源释放

| 资源 | 释放动作 |
| --- | --- |
| 网络连接 | 关闭客户端连接 + 关闭上游 LLM stream 连接 |
| 内存 buffer | 清空 token 缓冲、event 缓冲 |
| 定时器 | 清理心跳定时器、超时定时器 |
| 会话上下文 | 释放本次流的会话状态（若无需重连恢复） |
| 协程/线程 | 取消读取协程，避免悬挂 |

### 4. 资源泄露防范

| 泄露类型 | 表现 | 防范 |
| --- | --- | --- |
| 连接泄露 | 上游 LLM stream 未关闭，连接堆积 | `try-finally` 确保关闭；连接数上限熔断 |
| 内存泄露 | buffer/缓冲未清，长连接累积 | 流结束/取消时 finally 清空；缓冲设上限 |
| 协程泄露 | 读取协程未被取消，长期悬挂 | 用 context/cancel 传播取消信号；超时兜底 |
| 句柄泄露 | 定时器/监听器未清理 | finally 中 clearInterval/removeEventListener |
| 计费泄露 | LLM 仍在生成未停 | 显式关闭 stream，确认 Provider 停止计费 |

通用原则：**所有资源申请配对释放，用 try-finally 或 defer 保证取消路径也释放**；再加超时兜底（即使取消信号丢失，超时也能回收）。

### 5. 代码示例（前端 AbortController 取消流）

```javascript
const controller = new AbortController();

async function streamChat(query) {
  const res = await fetch("/api/chat/stream", {
    method: "POST",
    body: JSON.stringify({ query }),
    signal: controller.signal,        // 取消信号
  });
  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  try {
    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      appendToken(decoder.decode(value));
    }
  } catch (e) {
    if (e.name === "AbortError") {
      // 用户主动停止：前端已 abort，后端会收到连接断开并取消上游
      console.log("已停止生成");
    } else {
      throw e;
    }
  } finally {
    reader.releaseLock();              // 释放 reader
  }
}

// 用户点"停止"
stopBtn.onclick = () => controller.abort();
```

> 后端对应：监听请求取消（如 Node 的 `req.on('close')`、Go 的 `r.Context().Done()`），在其中关闭上游 LLM stream 并清理资源。

### 6. 一句话总结

停止生成要把取消信号端到端传到上游 LLM——**客户端 `AbortController` 取消 → 网关传播 → 推理服务关闭 LLM stream 连接停止计费**，并在 `finally` 中释放连接/buffer/定时器/协程；防范连接/内存/协程/计费泄露靠"显式关闭上游 stream + try-finally 释放 + 超时兜底"。内容安全停流见 [[7.流式输出中内容安全实时截断的实现方法敏感词检测、停流、上下文清理]]，报错兜底见 [[10.流式推理中LLM模型报错的兜底策略设计]]。
