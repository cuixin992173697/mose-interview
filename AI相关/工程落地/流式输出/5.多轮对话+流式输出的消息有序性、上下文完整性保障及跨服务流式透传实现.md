## 多轮对话+流式输出的消息有序性、上下文完整性保障及跨服务流式透传实现

多轮对话叠加流式输出，比单轮流式多了"轮次有序"和"跨轮上下文完整"两个维度，再加上服务拆分后的流式透传，工程上要同时管好"顺序、完整、透传"三件事。

### 1. 两个核心保障

| 保障 | 含义 | 不保障的后果 |
| --- | --- | --- |
| 消息有序性 | 同一轮 token 按生成顺序到达并渲染；多轮之间按轮次先后 | 文字错乱、前后轮拼接、回答读不懂 |
| 上下文完整性 | 历史轮次不丢、断线可恢复、多轮上下文连续 | 模型"失忆"、答非所问、重复提问 |

### 2. 消息有序性保障

#### 同轮 token 有序

流式输出本质是一个 token 序列，必须保证"先生成的先到达、先渲染"：

| 手段 | 说明 |
| --- | --- |
| 单调递增 event id | 每个 chunk 携带递增序号（seq），前端按 seq 排序渲染，乱序到达可重排 |
| 单连接串行 | 同一会话同一轮走同一条流，避免多连接交叉 |
| 前向渲染 | 只有序号连续时才追加渲染，缺口处缓冲等待 |

```text
data: {"seq":1,"text":"你"}
data: {"seq":2,"text":"好"}
data: {"seq":3,"text":"，"}      ← 前端按 seq 追加，乱序到达先缓冲重排
data: {"seq":4,"text":"世界"}
data: [DONE]                     ← 本轮结束标记
```

#### 多轮有序

| 手段 | 说明 |
| --- | --- |
| 轮次 id（turn_id） | 每轮对话有唯一 turn_id，前端按 turn_id 顺序拼接对话气泡 |
| 前轮完成才开下轮 | 上一轮 `[DONE]` 未到不发起下一轮，避免轮次交叉 |
| 客户端序列号 | 客户端维护全局递增 msg_id，与服务端 turn_id 对应 |

### 3. 上下文完整性保障

| 场景 | 保障方法 |
| --- | --- |
| 正常多轮 | 服务端按 session_id 维护历史消息列表，每轮把历史+新问题一起送 LLM |
| 断线重连 | 会话状态持久化（Redis/DB），重连后按 session_id 恢复历史，继续该会话 |
| 流式中断 | 已生成内容落库（草稿态），重连续打 |
| 跨轮引用 | 历史消息带稳定 msg_id，模型/前端可引用"上一条" |

> 断线重连的恢复细节见 [[2.流式返回中网络中断重连的上下文恢复方法及防重复、防丢包策略]]。

### 4. 跨服务流式透传

生产架构通常是多层：`客户端 → 网关 → 业务服务 → 推理服务 → 上游 LLM`。流式输出必须**逐层透传 stream，不能在任何一层 buffer 全量**，否则流式退化成"一次性返回"，延迟暴涨。

```
客户端 ←SSE← 网关 ←stream← 业务服务 ←stream← 推理服务 ←stream← 上游 LLM
         │         │              │              │
         └─ traceId / eventId / session_id 逐跳传递 ─┘
```

| 透传要点 | 说明 |
| --- | --- |
| 不 buffer 全量 | 每层收到 chunk 立即向下游转发，不攒齐再发 |
| 背压控制 | 下游慢时，上游阻塞或丢弃，避免内存积压（见 [[6.高并发QPS≥1000下SSE长连接的复用、心跳检测、超时释放及OOM优化]]） |
| 逐跳传递元数据 | traceId / eventId / session_id / seq 在每层透传，保证有序与可追踪 |
| 超时与保活 | 每跳设置读写超时 + 心跳，单挂断链不拖垮全链 |
| 错误传播 | 上游出错时通过流内 error 事件向下游传，而非静默断流 |

### 5. 透传实现要点

| 要点 | 做法 |
| --- | --- |
| 反压 | 用响应式流（Reactor/Flow）或 Node Stream 的 pipe，下游慢自动暂停上游读取 |
| 超时 | 首 token 超时（如 30s）+ chunk 间隔超时（如 60s 无数据判死） |
| 错误传播 | 流内插入 `{"event":"error","code":...}` 后正常关闭，前端据 code 兜底 |
| 连接管理 | 上游连接随下游关闭而关闭，避免泄露（见 [[3.用户停止生成时LLM推理终止、资源释放的实现及资源泄露防范]]） |

### 6. 一句话总结

多轮+流式要在"消息有序（seq/turn_id 单调递增+按序渲染）、上下文完整（session 持久化+断线恢复）、跨服务透传（逐层 stream 不 buffer+背压+元数据逐跳传递）"三方面同时布防，任何一层 buffer 全量或丢元数据都会让流式退化或错乱；透传全链路追踪见 [[12.跨服务流式透传的日志埋点设计及全链路追踪实现]]，非文本事件插入见 [[4.流式返回中非文本事件的插入方法及前端渲染兼容]]。
