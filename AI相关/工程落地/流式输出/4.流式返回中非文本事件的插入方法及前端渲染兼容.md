## 流式返回中非文本事件的插入方法及前端渲染兼容

### 1. 为什么需要非文本事件

流式输出不只是"一段文字逐字吐出"，生成过程中常需穿插非文本信号：

| 非文本事件 | 用途 |
| --- | --- |
| 工具调用状态 | 显示"正在搜索…/正在执行代码…" |
| 进度 | "已处理 3/10 篇文档" |
| 引用来源 | 给出某句结论的出处（chunk id/页码） |
| 图片/卡片 | 生成图表、渲染结构化卡片 |
| 错误 | 中途报错但不中断整体 |
| 心跳 | 保活探针，维持连接 |

这些事件要和文本 token 流**穿插但有序**地呈现，且不能扰乱打字机渲染。

### 2. 插入方法

#### 方法一：SSE 的 event 字段区分多事件类型

SSE 协议原生支持 `event:` 字段，可按类型分发：

```
event: message
data: {"text":"根据资料"}

event: citation
data: {"chunk_id":12,"source":"xx手册 p.5"}

event: message
data: {"text":"，GPT-4 的定价是…"}

event: tool_call
data: {"tool":"search","status":"running"}

event: done
data: {}
```

前端 `EventSource` 用 `addEventListener` 按事件名分别处理。

#### 方法二：JSON 结构化 chunk 带 type 字段

不分 event 名，统一走 `message`，但 data 内用 `type` 区分（WebSocket 或受限端常用）：

```json
{"type":"text","text":"根据资料"}
{"type":"citation","chunk_id":12,"source":"xx手册 p.5"}
{"type":"tool_call","tool":"search","status":"running"}
{"type":"text","text":"，GPT-4 的定价是…"}
{"type":"done"}
```

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| SSE event 字段 | 协议原生、前端按名分发清晰 | 仅 SSE 可用，小程序 EventSource 不支持时失效 |
| JSON type 字段 | 通用、WebSocket/降级都能用 | 需自己解析分发 |

### 3. 前端渲染兼容

| 要点 | 说明 |
| --- | --- |
| 按 type 分发渲染器 | text → 打字机追加；citation → 行内引用角标；tool_call → 状态条；image → 图片位 |
| 严格按序插入 | 所有事件按到达顺序进入同一渲染队列，避免非文本事件插错位置 |
| 文本与非文本交错 | 引用角标要紧跟对应文本之后，需用占位符锚定位置 |
| 防重排卡顿 | 非文本卡片用固定高度占位，避免插入时整段重排；批量更新而非逐 token 重渲染 |
| 增量渲染 | 文本用追加式 DOM/虚拟列表，避免每次重新解析整段 markdown |

### 4. 事件协议设计示例

```typescript
type StreamEvent =
  | { type: "text"; text: string }
  | { type: "citation"; chunk_id: number; source: string; pos: number } // pos=锚定文本位置
  | { type: "tool_call"; tool: string; status: "running" | "done"; result?: string }
  | { type: "image"; url: string }
  | { type: "error"; message: string }
  | { type: "done" };
```

前端渲染队列：

```javascript
function handleEvent(ev) {
  switch (ev.type) {
    case "text":       appendText(ev.text); break;
    case "citation":   insertCitation(ev.pos, ev.source); break;
    case "tool_call":  updateToolStatus(ev.tool, ev.status); break;
    case "image":      insertImage(ev.url); break;
    case "error":      showError(ev.message); break;
    case "done":       finishMessage(); break;
  }
}
```

### 5. 一句话总结

流式非文本事件插入靠 **SSE 的 `event` 字段或 JSON chunk 的 `type` 字段区分事件类型**，前端按 type 分发渲染器并严格按序插入（引用用位置锚定、卡片用固定占位防重排），实现文本打字机与非文本事件的有序兼容渲染。多端有序性与透传见 [[5.多轮对话+流式输出的消息有序性、上下文完整性保障及跨服务流式透传实现]]。
