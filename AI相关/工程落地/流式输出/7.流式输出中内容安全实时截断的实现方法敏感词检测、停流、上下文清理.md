## 流式输出中内容安全实时截断的实现方法：敏感词检测、停流、上下文清理

流式输出是一边生成一边吐字，内容安全必须"实时"——检测到敏感词要立即停止，不能等整段生成完再事后过滤（敏感内容已经发到前端了）。

### 1. 为什么必须实时截断

| 事后过滤的问题 | 实时截断的价值 |
| --- | --- |
| 敏感内容已发到前端、已被用户看到 | 命中即停，敏感内容不出端 |
| 已生成的 token 已计费/已缓存 | 减少无效生成与成本 |
| 整段返工重生成，延迟翻倍 | 只截断到命中点，体验好 |

### 2. 实时截断的难点

| 难点 | 说明 |
| --- | --- |
| token 跨越敏感词 | 敏感词可能被切到两个 chunk（如"敏"在 chunk1、"感"在 chunk2），单 chunk 匹配会漏 |
| 字符流增量匹配 | 必须在流式字符流上做增量匹配，不能等全量 |
| 多语言/变体 | 谐音、拆字、拼音、英文混合等绕过手段 |
| 误杀 | 正常内容含敏感字串被误截断 |

### 3. 实现方法（四步）

#### ① 增量敏感词匹配

在流式字符流上做增量匹配，主流用 **DFA（确定有限自动机）或 AC 自动机**：

| 算法 | 特点 |
| --- | --- |
| DFA | 经典敏感词匹配，状态机逐字符转移，O(n) |
| AC 自动机 | 多模式匹配，一次扫描匹配全部敏感词，适合大词库 |

关键：维护一个"待匹配缓冲区"，跨 chunk 的部分匹配留在缓冲区，下一个 chunk 到来后续接匹配。

```python
# 伪代码：流式增量敏感词检测
class StreamSensitiveFilter:
    def __init__(self, words):
        self.dfa = build_dfa(words)   # 预构建 DFA
        self.buf = ""                 # 跨 chunk 缓冲
    def feed(self, chunk_text):
        self.buf += chunk_text
        safe, hit, self.buf = self.dfa.match_stream(self.buf)
        # safe: 可安全放行的前缀; hit: 是否命中敏感词; self.buf: 留待下 chunk 的尾部
        return safe, hit
```

#### ② 命中即停流

检测到敏感词命中后，立即停止上游推理 + 截断下游输出：

| 动作 | 说明 |
| --- | --- |
| 停止上游推理 | 中断 LLM 推理请求（abort），停止继续生成（机制同 [[3.用户停止生成时LLM推理终止、资源释放的实现及资源泄露防范]]） |
| 截断下游输出 | 不再把命中点之后的内容发给前端 |
| 通知前端 | 发送 `event: blocked` 事件，前端展示安全文案 |

```text
data: {"seq":5,"text":"这是一段正"}
data: {"seq":6,"text":"常内容"}      ← 命中敏感词
event: blocked
data: {"reason":"content_policy"}    ← 通知前端已截断
data: [DONE]
```

#### ③ 已输出部分清理/替换

| 情况 | 处理 |
| --- | --- |
| 敏感词未输出到前端 | 直接丢弃，无需清理 |
| 敏感词已部分输出到前端 | 前端回退最后一个不完整 token，或替换为安全文案（如"内容违规已拦截"） |
| 已输出完整敏感词 | 前端移除/打码替换，并发安全提示 |

#### ④ 上下文清理

| 清理对象 | 说明 |
| --- | --- |
| 历史消息 | 不把含敏感内容的轮次写入会话历史，避免后续轮次"回忆"出敏感内容 |
| 缓存 | 命中截断的响应不进语义缓存，避免污染 |
| 日志 | 敏感内容脱敏后再落日志，避免二次泄露 |

### 4. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 缓冲区上限 | 跨 chunk 缓冲区设上限，防恶意超长未匹配 |
| 词库更新热加载 | 敏感词库可热更新，不重启服务 |
| 检测与生成解耦 | 检测跑在流式管道的独立阶段，不阻塞正常 token（或仅微延迟） |
| token 计费 | 截断部分已生成 token 仍计费，统计见 [[8.流式返回中Token消耗的精准统计方法逐段+汇总及计费适配]] |
| 兜底 | 检测组件故障时，安全优先——可选择停流或放行（按业务定） |

### 5. 一句话总结

流式内容安全要"实时截断"：用 **DFA/AC 自动机在字符流上增量匹配（跨 chunk 缓冲续接）→ 命中即停流（中断上游推理+截断下游）→ 已输出部分清理替换 → 上下文清理（不污染历史/缓存/日志）**，四步联动；停流机制与用户主动停止生成同源（见 [[3.用户停止生成时LLM推理终止、资源释放的实现及资源泄露防范]]）。
