## 流式返回中 Token 消耗的精准统计方法：逐段+汇总及计费适配

流式输出下 token 是逐 chunk 产生的，而完整的 usage（prompt/completion/total）通常只在流结束时才由上游返回。要既支持"实时展示已消耗 token"又保证"最终计费精准"，需逐段估算 + 末尾汇总双管齐下。

### 1. 流式 token 统计的难点

| 难点 | 说明 |
| --- | --- |
| 逐 chunk 增量 | token 随 chunk 到达，需实时累计 |
| 最终 usage 滞后 | prompt/total tokens 通常在 stream 末尾才返回 |
| chunk 边界≠token 边界 | 一个 chunk 可能含半个 token（按字符/字节流），本地估算需用 tokenizer |
| 多模型差异 | 不同模型 usage 字段格式、tokenizer 不同 |
| 截断/中断 | 用户停止或敏感词截断时，已生成部分仍需计费 |

### 2. 逐段统计（实时累计）

在流式过程中实时累计已输出 token，供前端展示"已生成 N tokens"：

| 方法 | 说明 |
| --- | --- |
| 本地 tokenizer 估算 | 每 chunk 用对应 tokenizer（如 tiktoken 估 GPT、各模型自带 tokenizer）累计估算 |
| 粗估 | 字符数 ÷ 系数（中文≈1.5 字/token，英文≈4 字符/token）快速估算 |
| 用途 | 实时展示、阈值控制（超 token 上限停流） |

> 本地估算是"近似值"，最终以上游返回的 usage 为准。

### 3. 汇总（精准总量）

上游 LLM 在 stream 结束时返回最终 usage，这是精准值：

| 字段 | 含义 |
| --- | --- |
| prompt_tokens | 输入（含历史上下文+本轮问题）token 数 |
| completion_tokens | 输出（生成内容）token 数 |
| total_tokens | prompt + completion |
| cached_tokens（如有） | 命中缓存的 prompt token（计费折扣） |

```text
data: {"seq":1,"text":"你"}
data: {"seq":2,"text":"好"}
...
data: {"seq":10,"text":"世界"}
data: {"usage":{"prompt_tokens":120,"completion_tokens":10,"total_tokens":130}}  ← 末尾 usage
data: [DONE]
```

```python
# 伪代码：解析流式末尾 usage
total_prompt = total_completion = 0
for chunk in stream:
    if "usage" in chunk:           # 末尾帧带 usage
        total_prompt = chunk["usage"]["prompt_tokens"]
        total_completion = chunk["usage"]["completion_tokens"]
        break
    yield chunk["text"]            # 正常 token 透传
final_total = total_prompt + total_completion   # 计费依据
```

### 4. 本地估算兜底

当上游不返回 usage（部分模型/自部署服务）时，用本地 tokenizer 兜底：

| 兜底场景 | 做法 |
| --- | --- |
| 上游无 usage 字段 | 全程本地 tokenizer 估算 prompt + completion |
| 上游 usage 不准 | 对账时以本地估算修正或人工核对 |
| 流中断未到末尾 | 用本地估算的已生成部分作为计费依据 |

### 5. 计费适配

| 计费场景 | 处理 |
| --- | --- |
| 按 token 计费 | 以末尾 usage 的 total_tokens 为准，乘单价 |
| 实时计费/预扣 | 流式中按本地估算预扣，结束后按 usage 结算差额 |
| 缓存命中折扣 | cached_tokens 部分按折扣价或不计费 |
| 多模型不同价 | 按模型分别配置 prompt/completion 单价 |
| 截断/中断计费 | 已生成 completion_tokens 仍计费（见 [[7.流式输出中内容安全实时截断的实现方法敏感词检测、停流、上下文清理]]） |
| 账单对账 | 落库每次请求的 usage + 单价 + 金额，定期与上游账单对账 |

### 6. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 以 usage 为准 | 本地估算仅用于实时展示，计费/对账以上游 usage 为准 |
| usage 落库 | 每次请求的 usage 持久化，支撑计费与分析 |
| tokenizer 一致 | 本地估算用的 tokenizer 必须与模型匹配，否则偏差大 |
| 并发统计 | 高并发下用原子计数/异步累加，避免统计竞争 |
| 估算修正 | 定期用 usage 校正本地估算系数 |

### 7. 一句话总结

流式 token 统计 = **逐段用本地 tokenizer 实时估算（供展示/预扣）+ 末尾解析上游 usage 汇总（供精准计费）+ 无 usage 时本地兜底**，计费以 usage 为准、估算为辅，截断部分照常计费（见 [[7.流式输出中内容安全实时截断的实现方法敏感词检测、停流、上下文清理]]）。
