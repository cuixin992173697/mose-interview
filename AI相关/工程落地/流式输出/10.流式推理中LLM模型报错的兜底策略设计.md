## 流式推理中 LLM 模型报错的兜底策略设计

> 流式推理不是"调用一次拿一个结果"，而是长连接持续输出——中途任何一跳报错都影响体验。本篇讲报错场景与兜底策略，重点是"流式中途报错"的专项处理。

### 1. 流式推理的报错场景

| 场景 | 典型 HTTP | 特点 |
| --- | --- | --- |
| 限流 | 429 | 并发/配额超限，可重试 |
| 超时 | 网关 504 / 推理超时 | 首 token 慢或整体超时 |
| 模型内部错误 | 5xx | 上游服务异常，可重试或降级 |
| 上下文超限 | 400 | 输入 token 超窗口，需截断/压缩 |
| 内容过滤拒绝 | 400(policy) | 触发安全策略，不可重试 |
| 流式中途断流 | 连接中断 / 模型中途出错 | 已输出部分内容，最棘手 |

> 前 5 类是非流式也有的"请求级"报错；第 6 类"流式中途断流"是流式专属，需要专项兜底。

### 2. 通用兜底策略

| 策略 | 做法 | 适用 |
| --- | --- | --- |
| 重试 | 指数退避 + 抖动，限次重试 | 429/5xx/超时等瞬时错误 |
| 降级 | 换备用模型/备用通道/备用机房 | 上游持续异常 |
| 部分结果保留 | 已生成内容不丢 + 错误标记 | 流式中途报错 |
| 友好提示 | 给用户可读的错误说明 + 重试入口 | 所有错误 |
| 熔断 | 连续失败达阈值触发熔断，快速失败 | 防止雪崩 |
| 缓存命中 | 相似请求命中语义缓存 | 热点问题 |

### 3. 流式中途报错专项（核心）

流式已输出部分内容时中途报错，直接整段丢弃体验最差。专项处理：

| 处理点 | 做法 |
| --- | --- |
| 保留已输出 | 已生成的内容不丢，页面继续显示 |
| 错误标记 | 在已输出内容后追加错误标识（如"⚠️ 生成中断"） |
| 可续打重试 | 提供"继续生成"按钮，从断点续打（见 [[11.流式输出断点续打的实现及页面刷新后的内容恢复方法]]） |
| 不静默失败 | 明确告知用户中断原因，不假装成功 |

```
已输出内容... [生成中断：服务暂时不可用]  [重试继续]
```

### 4. 兜底决策表

| 报错类型 | 首选兜底 | 是否保留部分结果 |
| --- | --- | --- |
| 429 限流 | 退避重试 | 是（已输出保留） |
| 超时 | 重试 + 降级备用模型 | 是 |
| 5xx 内部错误 | 重试 → 降级 | 是 |
| 上下文超限 | 截断/压缩后重试 | 否（需改输入） |
| 内容过滤拒绝 | 友好提示，不重试 | 是（保留已输出） |
| 流式中途断流 | 保留已输出 + 可续打重试 | 是（关键） |

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 区分可重试 vs 不可重试 | 429/5xx/超时可重试；内容过滤、参数错误不可重试 |
| 重试要有上限 | 限次 + 退避，避免无限重试拖垮服务 |
| 降级链预设 | 主模型→备用模型→规则兜底，提前配置 |
| 用户停止生成也要释放资源 | 见 [[3.用户停止生成时LLM推理终止、资源释放的实现及资源泄露防范]] |
| 错误可观测 | 流式报错要埋点统计失败率/类型，见 [[12.跨服务流式透传的日志埋点设计及全链路追踪实现]] |
| 幂等重试 | 续打重试要带断点标识，防重复输出 |

### 6. 一句话总结

流式推理兜底 = **通用策略（重试/降级/熔断/缓存）+ 流式中途报错专项（保留已输出 + 错误标记 + 可续打重试）**；关键是区分可重试与不可重试错误，且流式中途断流绝不静默丢弃已生成内容。资源释放配合 [[3.用户停止生成时LLM推理终止、资源释放的实现及资源泄露防范]]，断点续打配合 [[11.流式输出断点续打的实现及页面刷新后的内容恢复方法]]。
