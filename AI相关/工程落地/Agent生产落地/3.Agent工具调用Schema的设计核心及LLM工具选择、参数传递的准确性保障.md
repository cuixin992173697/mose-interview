## Agent 工具调用 Schema 的设计核心及 LLM 工具选择、参数传递的准确性保障

> 工具是 Agent 的"手脚"，Schema 是工具的"说明书"。Schema 设计得好，LLM 选得准、参数传得对；设计得差，选错工具、参数乱传。工具调用链路见 agent 目录的《19.Tool Calling工具调用的完整链路解析》《13.LLM Agent动态API调用的实现方式》，多 Provider Schema 差异见《38.不同LLM Provider对Tool Schema支持差异的处理及OpenClaw的适配方法》。

### 1. Schema 设计核心

| 要素 | 说明 | 示例 |
| --- | --- | --- |
| name | 简洁、动词开头、唯一 | `search_docs` / `get_order_status` |
| description | 写清"做什么+何时用+何时不用" | "按关键词检索知识库文档；当需要查事实/文档时用，需要实时数据时改用 web_search" |
| parameters | JSON Schema 定义 | type/properties/required |
| required | 标注必填参数 | `["query"]` |
| enum | 枚举约束取值 | `"status": {"enum": ["paid","unpaid"]}` |
| 示例值 | 给参数示例，降低 LLM 猜测 | `"example": {"query": "RAG 原理"}` |
| 返回值说明 | 描述返回结构，帮 LLM 理解结果 | "返回 {title, content, source}" |

### 2. LLM 工具选择准确性

LLM 选错工具，根因多在 description 与工具数量：

| 保障手段 | 说明 |
| --- | --- |
| description 写清边界 | 明确"何时用"+"何时不用"+与相似工具的区别 |
| 工具数量控制 | 工具过多 LLM 选择困难，单次暴露相关子集（路由/检索过滤） |
| 命名规范 | 一致命名前缀（如 `db_*`/`web_*`），帮 LLM 分类 |
| 避免工具重叠 | 功能重叠的工具合并或用参数区分，别让 LLM 二选一纠结 |
| 工具描述随上下文 | 按任务阶段动态注入相关工具，减少干扰 |

### 3. 参数传递准确性保障

| 保障手段 | 说明 |
| --- | --- |
| 强类型 | 用 JSON Schema 限定 type（string/number/boolean/array/object） |
| enum 约束 | 有限取值用 enum，杜绝自由发挥 |
| required 必填校验 | 缺必填直接判失败 |
| 示例值引导 | example 值锚定格式，减少格式错误 |
| function calling 结构化输出 | 用原生 tool_use，比文本解析可靠 |
| 参数校验失败回退 | 校验不过→带错误反馈让 LLM 重新生成参数，而非直接报错 |

### 4. Schema 设计示例

```json
{
  "name": "search_docs",
  "description": "按关键词检索知识库文档。需要查事实/文档/政策时用；需要实时数据(天气/股价)改用 web_search；需要订单状态改用 get_order_status。",
  "parameters": {
    "type": "object",
    "properties": {
      "query": {"type": "string", "description": "检索关键词", "example": "RAG 检索原理"},
      "top_k": {"type": "integer", "description": "返回数量", "default": 5, "minimum": 1, "maximum": 20}
    },
    "required": ["query"]
  }
}
```

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| description 是第一生产力 | 工具选错 80% 是 description 没写清边界 |
| 参数越少越好 | 能默认的别让 LLM 传，减少出错面 |
| 校验在前执行在后 | 参数校验失败别真调工具，回退重生成 |
| 版本管理 | Schema 变更要兼容，避免老 Agent 调用崩 |
| 评测工具选择准确率 | 用标注集测工具选择命中率，持续优化 description |

### 6. 一句话总结

工具 Schema 设计 = **name 简洁 + description 写清边界（何时用/不用）+ parameters 强类型 enum 约束 + required 校验 + 示例值**；工具选择靠 description 与数量控制，参数准确靠 schema 校验 + function calling + 失败回退重生成。脱节规避见 [[2.ReAct框架实际开发中思考与行动脱节的规避及Reason步骤优化]]，依赖与死循环见 [[4.多步工具依赖的管理方法及重复调用、死循环的规避]]。
