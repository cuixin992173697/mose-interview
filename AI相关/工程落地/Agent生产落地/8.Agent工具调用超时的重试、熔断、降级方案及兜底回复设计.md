## Agent 工具调用超时的重试、熔断、降级方案及兜底回复设计

### 1. 超时处理

| 项 | 说明 |
| --- | --- |
| 分级超时阈值 | 不同工具不同阈值（查询类 5s，生成类 30s，长任务 120s） |
| 连接超时 | 建连超时（如 2s），防卡在握手 |
| 读超时 | 响应超时（如 10s），防卡在等待 |
| 总超时 | 整个工具调用上限，超即取消 |

### 2. 重试

| 要点 | 说明 |
| --- | --- |
| 指数退避+抖动 | 第 n 次等待 base*2^n + 随机抖动，避免雪崩 |
| 最大次数 | 如 3 次，超了不再重试 |
| 幂等前提 | 只有幂等操作（GET/查询）可安全重试；非幂等（扣款）需幂等键 |
| 可重试错误 | 网络抖动/超时/5xx 可重试；4xx/参数错误不重试 |

### 3. 熔断

| 项 | 说明 |
| --- | --- |
| 触发条件 | 错误率超阈值（如 50%）/慢调用比例超阈值 |
| 熔断状态 | Open（拒绝请求）→ Half-Open（放少量探测）→ Closed（恢复） |
| 恢复 | 半开探测成功则关闭熔断 |
| 作用 | 防止故障工具被持续调用拖垮整个 Agent |

### 4. 降级

| 方案 | 说明 |
| --- | --- |
| 换备用工具 | 主工具挂了换备用（如主搜索挂换缓存搜索） |
| 简化逻辑 | 跳过非核心步骤，返回基础结果 |
| 缓存结果 | 返回最近缓存（标注"非实时"） |
| 默认值 | 兜底默认返回 |

### 5. 兜底回复

- 友好提示："该功能暂时不可用，请稍后重试"
- 保留部分结果：已完成的步骤结果不丢
- 可重试入口：提供"重试"按钮

### 6. 决策流程

```
工具调用
  ├─ 超时？→ 重试(指数退避, ≤3 次)
  │            ├─ 成功 → 返回
  │            └─ 失败 → 熔断判断
  ├─ 错误率高？→ 熔断 Open → 直接降级
  └─ 降级：备用工具 / 缓存 / 默认 → 兜底回复(保留部分结果 + 可重试)
```

### 7. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 超时分级 | 别所有工具一个超时，按耗时分级 |
| 幂等键 | 非幂等工具重试必须带幂等键防重复副作用 |
| 熔断器独立 | 每个工具独立熔断器，别全局一刀切 |
| 降级可接受 | 降级结果要标注非实时/不完整，别误导用户 |
| 兜底要友好 | 别抛原始错误栈，给人话提示 + 重试入口 |

### 8. 一句话总结

工具调用容错 = **分级超时 → 幂等前提下指数退避重试 → 错误率触发熔断 → 降级（备用/缓存/默认）→ 兜底回复（友好提示+保留部分结果+可重试）**，层层兜底保证 Agent 不因单工具故障而整体崩。模型报错兜底见流式输出目录的《10.流式推理中LLM模型报错的兜底策略设计》，死循环规避见 agent 目录的《17.Agent死循环问题的解决方法》，并发治理见 [[7.高并发场景下Agent任务的排队、限流、优先级调度实现]]。
