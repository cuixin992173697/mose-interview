## Agent 生成 SQL 与代码的沙箱环境、权限隔离设计及注入攻击防范

### 1. 沙箱环境

Agent 生成 SQL/代码并执行，必须在沙箱内隔离，防止逃逸伤及宿主：

| 方案 | 隔离强度 | 说明 |
| --- | --- | --- |
| Docker 容器 | 中 | 进程级隔离，限制资源，需加固防逃逸 |
| WASM | 高 | 轻量安全沙箱，适合代码执行 |
| gVisor / Kata | 高 | 强隔离容器，内核级 |
| 独立 VM | 最高 | 完整隔离，重 |

资源限制：CPU/内存/时间上限、只读文件系统、无网络或白名单网络、超时 kill。

### 2. 权限隔离

| 原则 | 说明 |
| --- | --- |
| 最小权限 | 只给完成任务所需最小权限 |
| 网络隔离 | 沙箱无外网或仅白名单 |
| 禁敏感数据 | 禁止访问密钥/其他用户数据 |
| 超时 kill | 执行超时强制终止 |
| 只读账户 | SQL 用只读账户，禁 DDL/DML |

### 3. 注入攻击防范

| 攻击类型 | 防范手段 |
| --- | --- |
| SQL 注入 | 参数化查询/预编译；表名列名白名单；只读账户；禁多语句；行数限制 |
| 代码注入 | 沙箱执行 + 禁危险 API（os/subprocess/eval）；超时；资源限制 |
| Prompt 注入 | 输入过滤/转义；指令与数据隔离（分隔符）；工具白名单；不把用户输入直接当指令 |

#### SQL 安全执行示例

```python
# 危险：拼接 SQL
sql = f"SELECT * FROM orders WHERE id = {user_input}"  # ❌ 注入风险

# 安全：参数化 + 白名单
ALLOWED_TABLES = {"orders", "products"}
table = user_input_table if user_input_table in ALLOWED_TABLES else None
if table:
    cursor.execute(
        f"SELECT * FROM {table} WHERE id = %s LIMIT 100",  # ✅ 参数化 + 白名单
        (user_id,)
    )
```

#### 代码沙箱执行要点

```python
# 沙箱执行用户生成代码：限制 + 超时 + 无网络
import subprocess
result = subprocess.run(
    ["python", "-c", generated_code],
    timeout=5,              # 超时 kill
    capture_output=True,
    env={"PATH": "/usr/bin"},  # 最小环境变量，禁敏感
    # 网络层禁出网（容器/网络命名空间隔离）
)
```

### 4. 多层防御纵深

| 层 | 措施 |
| --- | --- |
| 网络层 | 沙箱无外网或白名单 |
| 系统层 | 只读 FS、资源限制、超时 kill |
| 账户层 | 只读 DB 账户、最小权限 |
| 代码层 | 禁危险 API、参数化、白名单 |
| Prompt 层 | 指令隔离、输入过滤、工具白名单 |

### 5. 一句话总结

Agent 生成 SQL/代码执行 = **沙箱隔离（Docker/WASM/VM + 资源限制 + 无网络）+ 权限最小化（只读账户/超时 kill）+ 注入防范（SQL 参数化白名单 / 代码禁危险 API / Prompt 指令隔离）**，多层纵深防御杜绝逃逸与注入。工具权限分层见 agent 目录的《37.Agent工具权限控制的设计及OpenClaw的工具策略管道分层》，身份与权限管控见 [[13.Agent用户身份的安全传递及工具调用中的权限管控]]。
