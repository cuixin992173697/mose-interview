## Agent 反思机制 Reflection 的实现及失败学习优化策略

> 反思（Reflection）让 Agent 从执行结果中学习，发现错误、修正策略，是 Plan-Act-Observe-Reflect 环路的"自我进化"环节。Agent 常见功能见 agent 目录的《10.LLM Agent的常见功能介绍》，长期记忆见《12.LLM Agent长期记忆能力的实现方法》。

### 1. 反思机制是什么

反思 = **执行后对结果做自评估，发现错误并修正后续策略**，而非一味向前执行。区别于"执行即结束"，反思让 Agent 具备自我修正能力。

| 对比 | 无反思 Agent | 有反思 Agent |
| --- | --- | --- |
| 执行后 | 直接进下一步 | 先评估结果对不对 |
| 出错时 | 继续错下去 | 发现错误，重规划/换策略 |
| 学习 | 无 | 失败经验沉淀，下次避免 |

### 2. 反思实现方法

| 方法 | 说明 |
| --- | --- |
| 自评估 LLM 评判 | 用 LLM 对"任务目标 vs 执行结果"打分/判断是否达成 |
| 错误归因 | 分析失败原因：工具选错/参数错/规划错/能力不足 |
| 策略调整 | 换工具/换参数/重规划/拆更细子任务 |
| 限制反思次数 | 反思也消耗步数，限制反思轮次防空转 |
| 触发条件 | 结果不确定/失败/低置信/达反思周期时触发，不必每步反思 |

### 3. 反思的两种模式

| 模式 | 说明 |
| --- | --- |
| 即时反思 | 每步执行后立即评估，决定下一步（轻量、高频） |
| 终局反思 | 任务完成后整体复盘，总结经验（重量、低频） |

### 4. 失败学习优化策略（Reflexion）

核心思想：**把失败经验沉淀到长期记忆，下次执行同类任务时回避**。

```
执行失败 → 反思归因 → 生成"经验教训" → 存入长期记忆
                                         ↓
下次同类任务 → 检索相关经验 → 注入上下文 → 改进执行
```

| 策略 | 说明 |
| --- | --- |
| 经验结构化 | 失败场景 + 原因 + 改进建议，存成可检索条目 |
| 长期记忆外置 | 经验存向量库，按任务相似度检索（见 [[6.Agent短长期记忆的存储结构设计及容量与查询速度的平衡]]） |
| 经验注入 | 执行前检索同类历史经验，注入 Prompt 指导 |
| Reflexion 循环 | 反思→经验→改进→再执行，多轮迭代提升 |
| 经验衰减/清理 | 过时经验降权或清理，避免误导 |

### 5. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 别过度反思 | 反思本身消耗 token 与步数，限次数、按需触发 |
| 反思要有依据 | 基于执行结果与目标，禁止空洞反思 |
| 经验要可检索 | 失败经验结构化 + 向量化，下次能召回 |
| 防反思死循环 | 反思后仍失败要熔断终止，别无限反思 |
| 与人工兜底结合 | 多次反思失败转人工，见 [[14.Agent执行过程的可回放、可打断、可人工干预实现]] |

### 6. 一句话总结

反思机制 = **执行后自评估 + 错误归因 + 策略调整（限次数防空转）**；失败学习 = **把失败经验结构化存长期记忆，下次同类任务检索注入改进（Reflexion 循环）**，让 Agent 从"只会执行"进化为"会自我修正与学习"。环路落地见 [[1.Agent执行环路Plan-Act-Observe-Reflect的生产落地及各环节异常处理]]，记忆存储见 [[6.Agent短长期记忆的存储结构设计及容量与查询速度的平衡]]。
