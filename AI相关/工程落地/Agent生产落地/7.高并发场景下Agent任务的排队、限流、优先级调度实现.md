## 高并发场景下 Agent 任务的排队、限流、优先级调度实现

### 1. 高并发挑战

Agent 任务重（LLM 推理 + 多步工具调用），高并发下资源吃紧：

| 挑战 | 说明 |
| --- | --- |
| LLM 推理慢 | 单次几秒到几十秒，占并发槽 |
| 工具调用慢 | 外部 API/DB 调用阻塞 |
| GPU/并发有限 | 推理资源有上限，无法无限扩 |
| 长任务占资源 | 多步 Agent 长时间占连接/内存 |
| 突发流量 | 用户高峰易压垮后端 |

### 2. 排队（削峰填谷）

| 方案 | 说明 |
| --- | --- |
| 任务队列 | Kafka / Redis Queue / RabbitMQ，请求先入队异步处理 |
| 异步化 | 同步转异步，用户拿任务 ID 轮询/回调/SSE 推送结果 |
| 削峰 | 队列缓冲突发，消费端按能力匀速消费 |
| 死信队列 | 失败任务入死信，人工/重试处理 |

### 3. 限流

| 算法 | 说明 | 适用 |
| --- | --- | --- |
| 令牌桶 | 桶放令牌按速率补充，请求消耗令牌；允许突发 | 大多数场景（推荐） |
| 漏桶 | 请求入桶匀速流出；平滑流量 | 严格匀速 |
| QPS 限制 | 每秒请求数上限 | 保护下游 |
| 并发数限制 | 同时执行任务数上限 | 保护推理资源（推荐 Agent 用） |

限流维度：按用户（防单用户刷）、按全局（保护系统）、按 Agent 类型（重任务更低并发）。

### 4. 优先级调度

| 机制 | 说明 |
| --- | --- |
| 优先级队列 | 高优先级任务先消费 |
| VIP/SLA 分级 | 付费用户/关键业务优先 |
| 权重 | 按权重分配并发槽 |
| 抢占 | 高优先级可抢占低优先级资源（谨慎用） |

### 5. 架构图

```
用户请求 → API网关 → 限流(令牌桶/并发数)
                          │
                   任务队列(Kafka/Redis) ← 优先级标记
                          │
                   优先级调度消费 ← VIP/SLA 分级
                          │
                   Agent 执行池(并发槽上限)
                          │
                   LLM 推理 + 工具调用
                          │
                   结果回调 / SSE 推送
```

### 6. 工程实践要点

| 要点 | 说明 |
| --- | --- |
| 异步优先 | 重任务一律异步化，别让用户同步等几十秒 |
| 并发槽隔离 | 不同 Agent 类型独立并发池，避免互相饿死 |
| 公平性 | 同优先级内 FIFO，防止低优先级永久饿死 |
| 背压 | 队列满时拒绝新请求或降级，别无限堆积 |
| 监控 | 队列长度/等待时间/并发利用率告警 |

### 7. 一句话总结

高并发 Agent = **任务队列（Kafka/Redis）削峰 + 限流（令牌桶/并发数）保护 + 优先级调度（VIP/SLA 分级）排队**，把重推理任务异步化、按能力消费。长连接并发治理见流式输出目录的《6.高并发QPS≥1000下SSE长连接的复用、心跳检测、超时释放及OOM优化》，超时与兜底见 [[8.Agent工具调用超时的重试、熔断、降级方案及兜底回复设计]]，重复执行规避见 [[12.多用户触发同一Agent任务的幂等设计及重复执行规避]]。
