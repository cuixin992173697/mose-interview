## Agent 执行环路 Plan-Act-Observe-Reflect 的生产落地及各环节异常处理

> Plan-Act-Observe-Reflect 是 ReAct（Thought-Action-Observation）在生产环境的强化版：把"思考"拆成更结构化的"规划+反思"，把"行动"落到可工程化的工具调用与结果解析。ReAct 循环的完整过程见 agent 目录的《1.ReAct循环的完整过程》《11.Agent智能体的核心工作流程》。

### 1. 四环节生产落地

| 环节 | 职责 | 生产落地要点 |
| --- | --- | --- |
| Plan（规划） | 任务分解、确定下一步行动 | 任务拆成子任务、选工具、定参数；记录规划到执行日志 |
| Act（行动） | 执行工具调用 | 参数校验→权限校验→沙箱执行→超时控制；结果结构化 |
| Observe（观察） | 解析工具结果 | 容错解析（JSON/文本）、提取关键字段、截断超大结果 |
| Reflect（反思） | 评估结果、决定继续/修正/结束 | 判断是否达成、是否需重规划、是否进入下一子任务 |

```
任务输入
  → Plan（拆解 + 选工具）
  → Act（执行工具，含校验/超时/沙箱）
  → Observe（解析结果，容错/截断）
  → Reflect（评估 + 决策：继续/重规划/结束）
  → 循环直至完成或触发兜底
```

> 每个 Agent Runner 运行阶段都对应这个环路，见 agent 目录的《26.OpenClaw的Agent Runner工作原理及运行阶段》。

### 2. 各环节异常处理

| 环节 | 典型异常 | 处理策略 |
| --- | --- | --- |
| Plan | 规划失败/不可行/拆解错误 | 重规划（限定重规划次数）、降级为单步执行、人工兜底 |
| Plan | 规划与能力不匹配（选了不存在的工具） | 工具白名单校验，回退重规划 |
| Act | 工具调用失败/抛错 | 重试（指数退避）、降级备用工具、把错误作为 Observation 反馈 LLM |
| Act | 超时 | 超时熔断，记录失败，反馈超时信息让 LLM 改方案 |
| Act | 参数非法 | schema 校验失败→回退重问 LLM 重新生成参数 |
| Observe | 结果解析失败/格式错 | 容错解析（正则兜底）、降级取原始文本、反馈 LLM 重试 |
| Observe | 结果超大 | 截断/摘要/落库检索（见流式输出目录的《28》同类思路） |
| Reflect | 反思无效/空转/反复纠结 | 限制反思次数、强制进入下一步或终止 |
| Reflect | 误判已完成 | 终止校验：结果与目标比对，不匹配则继续 |

### 3. 生产落地要点

| 要点 | 说明 |
| --- | --- |
| 状态持久化 | 每轮 Plan/Act/Observe/Reflect 持久化，进程崩溃可恢复续跑 |
| 可恢复 | 中断后从最后检查点续，不重头执行已完成步骤 |
| 可观测 | 每环节埋点，全链路追踪（见 [[11.Agent执行过程的可观测性设计及全链路追踪实现]]） |
| 最大步数兜底 | 防死循环，超限强制终止 + 人工兜底 |
| 超时总预算 | 整任务 token/时间预算，超限熔断 |
| 人工干预点 | 高风险环节（危险工具/低置信）可暂停等人工确认（见 [[14.Agent执行过程的可回放、可打断、可人工干预实现]]） |

### 4. 一句话总结

Plan-Act-Observe-Reflect 生产落地 = **四环节各自带异常处理（Plan 重规划、Act 重试降级、Observe 容错解析、Reflect 限次防空转）+ 状态持久化可恢复 + 可观测 + 最大步数兜底**，把 ReAct 循环从"能跑"变成"生产可托付"。反思机制见 [[5.Agent反思机制Reflection的实现及失败学习优化策略]]，依赖与死循环见 [[4.多步工具依赖的管理方法及重复调用、死循环的规避]]。
