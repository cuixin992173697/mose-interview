## LangChain 与 LangGraph 的生产选型及 LangGraph 状态机对复杂业务流程的适配

### 1. LangChain vs LangGraph 选型对比

| 维度 | LangChain | LangGraph |
| --- | --- | --- |
| 核心抽象 | Chain / LCEL 管道 | 状态图（State + Node + Edge） |
| 流程模型 | 线性 / 管道 | 图遍历 + 状态机 |
| 循环 | 弱（需 hack） | 原生支持（边可回环） |
| 条件分支 | 弱 | 原生条件边 |
| 人工节点 | 弱 | interrupt 人工节点 |
| 多 Agent | 弱 | 原生多 Agent 图 |
| 状态持久化 | 弱 | Checkpointer 内置 |
| 中断恢复 | 弱 | 支持断点续跑 |
| 适用 | 简单线性流程 | 复杂流程（循环/分支/人机/多 Agent） |

### 2. 选型逻辑

| 场景 | 选型 |
| --- | --- |
| 简单 RAG 问答 / 摘要 / 翻译 | LangChain（LCEL 足够） |
| 单 Agent 工具循环（ReAct） | LangChain 可，复杂用 LangGraph |
| 含循环/条件分支的业务流程 | LangGraph |
| 人机协同（需人工审批节点） | LangGraph |
| 多 Agent 协作 | LangGraph |
| 需中断/恢复/回放 | LangGraph（Checkpointer） |

一句话：**简单线性用 LangChain，复杂流程用 LangGraph**。LangGraph 是 LangChain 团队为复杂 Agent 流程出的状态机框架，并非取代而是补位。

### 3. LangGraph 状态机对复杂业务流程的适配

| 能力 | 适配的复杂场景 |
| --- | --- |
| State 持久化 | 跨节点共享状态，长流程不丢 |
| Checkpointer | 中断/崩溃后从检查点恢复续跑 |
| interrupt 人工节点 | 执行到某节点暂停等人工审批，再继续 |
| 条件边 | 根据状态动态决定下一节点（if/else 分支） |
| 循环边 | ReAct 式 Thought→Action→Observation 回环 |
| 多 Agent 图 | 多 Agent 协作编排 |

### 4. 代码对比示例

#### LangChain（线性 LCEL）

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

chain = (
    ChatPromptTemplate.from_template("总结：{text}")
    | ChatOpenAI()
    | (lambda x: x.content)
)
result = chain.invoke({"text": "..."})
```

#### LangGraph（状态图 + 条件分支 + 人工节点）

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict

class State(TypedDict):
    query: str
    draft: str
    approved: bool

def generate(state): return {"draft": llm(state["query"])}
def human_review(state): return {"approved": wait_for_human()}  # 人工节点
def route(state): return END if state["approved"] else "generate"  # 条件边

g = StateGraph(State)
g.add_node("generate", generate)
g.add_node("review", human_review)
g.set_entry_point("generate")
g.add_edge("generate", "review")
g.add_conditional_edges("review", route)  # 不通过则回 generate 循环
app = g.compile(checkpointer=memory)      # 持久化 + 可中断恢复
```

### 5. 一句话总结

LangChain 适合简单线性流程（LCEL 管道），LangGraph 适合复杂业务流程（状态图 + 循环/条件分支/人工节点/多 Agent/Checkpointer 中断恢复）；选型看流程是否需要循环、分支、人机协同、中断恢复。组件与架构详见 agent 目录的《2.LangChain的核心组件详解》《3.LangChain的核心架构解析》《15.主流LLM Agent框架及各自特点》，可回放可打断见 [[14.Agent执行过程的可回放、可打断、可人工干预实现]]，框架落地坑见 [[16.开源Agent框架LangChain、AutoGen、MetaGPT的生产落地坑及规避方法]]。
