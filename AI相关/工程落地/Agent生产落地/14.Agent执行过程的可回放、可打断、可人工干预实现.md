## Agent 执行过程的可回放、可打断、可人工干预实现

### 1. 为什么要这三能力

| 能力 | 解决的问题 |
| --- | --- |
| 可回放 | 出错后回放当时步骤定位问题、调试、审计 |
| 可打断 | 用户中止/暂停、超时中断、防止跑飞 |
| 可人工干预 | 危险步骤需人审批、出错需人接管修正 |

### 2. 可回放

| 要素 | 做法 |
| --- | --- |
| 步骤持久化 | 每步 Thought/Action/Observation 落库 |
| 状态快照 Checkpoint | 关键节点保存 Agent 完整状态 |
| 重放 | 按步骤顺序回放，复现执行路径 |
| 用途 | 调试/故障定位/审计/评测 |

### 3. 可打断

| 中断类型 | 实现 |
| --- | --- |
| 用户中止 | 前端取消 → 取消信号传到 Agent 循环 → 停止 |
| 暂停 | 暂停标志，循环检查后挂起 |
| 超时中断 | 单步/总超时，到点抛中断 |
| 中断点 | 在关键步骤前检查中断信号 |

### 4. 可人工干预（Human-in-the-loop）

| 场景 | 做法 |
| --- | --- |
| 审批节点 | 危险工具调用前暂停，等人审批通过再执行 |
| 人工接管 | 出错时人接管修正后继续 |
| 人工修正 | 人修改 Agent 的 Plan/参数后继续 |
| LangGraph interrupt/resume | 用 interrupt 挂起 → 人输入 → resume 继续 |

LangGraph 的状态机 + checkpoint 天然支持 interrupt/resume，是 HITL 的优选，详见 [[10.LangChain与LangGraph的生产选型及LangGraph状态机对复杂业务流程的适配]]。

### 5. 实现基础

三能力共同基础 = 状态持久化 + 检查点 + 恢复点：

```
每步执行 → 持久化步骤 + 存 Checkpoint
  ↓
中断信号？ → 是 → 挂起(保存恢复点) → 等待(resume)
  ↓ 否
继续下一步
```

- Checkpoint 存：当前状态/历史/中间结果/下一步
- resume 从最近 Checkpoint 恢复，不丢上下文

Agent Runner 的执行阶段与异常重试见 agent 目录的《26.OpenClaw的Agent Runner工作原理及运行阶段》；Hook 是实现中断/干预挂载点的理想机制，见 agent 目录的《39.Agent系统中Hook中间件的作用、典型场景及OpenClaw的Hook系统设计》。

### 6. 代码示例（LangGraph HITL）

```python
from langgraph.graph import StateGraph
from langgraph.checkpoint import MemorySaver

def approve_node(state):
    # 危险操作前挂起等审批
    pass

graph = StateGraph(State)
graph.add_node("plan", plan_node)
graph.add_node("approve", approve_node)   # 审批节点
graph.add_node("execute", execute_node)
graph.add_edge("plan", "approve")
graph.add_conditional_edges("approve",
    lambda s: "execute" if s["approved"] else "end")

app = graph.compile(checkpointer=MemorySaver())
# 执行到 approve 自动 interrupt，等人审批后 resume
config = {"configurable": {"thread_id": "t1"}}
app.invoke(input, config)            # 到 approve 挂起
app.invoke(None, config)             # 审批后 resume 继续
```

### 7. 一句话总结

Agent 可回放 = 步骤持久化 + Checkpoint 可重放；可打断 = 中断信号 + 超时 + 暂停挂起；可人工干预 = 审批节点 + 人工接管 + LangGraph interrupt/resume；三者共同基础是状态持久化 + 检查点 + 恢复点，LangGraph 状态机是 HITL 优选（见 [[10.LangChain与LangGraph的生产选型及LangGraph状态机对复杂业务流程的适配]]），可观测性见 [[11.Agent执行过程的可观测性设计及全链路追踪实现]]。
