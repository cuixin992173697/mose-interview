## Agent 与现有后端系统 Java、Go 的对接及接口稳定性、一致性保障

> Agent 服务常以 Python 实现（生态所致），而企业后端多为 Java/Go。二者如何稳定对接、保证接口稳定性与数据一致性，是 Agent 生产落地的关键工程问题。

### 1. 对接背景与挑战

| 维度 | Agent 侧（常 Python） | 后端侧（Java/Go） |
| --- | --- | --- |
| 语言生态 | LLM/Agent 库丰富 | 业务系统、事务、高并发强 |
| 调用模式 | 流式、长耗时、多步 | 同步 RPC、事务型 |
| 一致性 | 最终一致为主 | 强一致/事务 |
| 典型问题 | 长耗时拖垮后端、异步结果难同步、Schema 不一致 |

### 2. 对接方式

| 方式 | 适用 | 说明 |
| --- | --- | --- |
| HTTP/REST | 通用、简单接口 | 易调试，但流式与长连接支持弱 |
| gRPC | 高性能、强类型、内部服务 | Protobuf 契约、双向流支持，内部对接首选 |
| 消息队列（Kafka/RabbitMQ） | 异步长任务、解耦削峰 | Agent 任务异步消费，结果回写，天然解耦 |
| Server-Sent Events / WebSocket | 流式输出回传 | 流式结果实时推回后端或前端 |

> 长耗时 Agent 任务推荐"消息队列投递 + 异步执行 + 结果回调/轮询"，避免 HTTP 同步长连接占用。

### 3. 接口稳定性

| 手段 | 说明 |
| --- | --- |
| 超时 | Agent 侧调用后端设超时；后端调用 Agent 设超时，防长耗时拖垮 |
| 重试 | 幂等接口可重试；非幂等用幂等键，见 [[12.多用户触发同一Agent任务的幂等设计及重复执行规避]] |
| 熔断 | 后端不可用时熔断，Agent 降级，见 [[8.Agent工具调用超时的重试、熔断、降级方案及兜底回复设计]] |
| 降级 | Agent 不可用时后端走规则/缓存兜底回复 |
| 版本兼容 | 接口带版本号（/v1/），新旧版本并行期 |
| Schema 契约 | 用 Protobuf/OpenAPI 定义契约，双方生成代码，防字段漂移 |
| 向后兼容 | 新增字段可选、不删改老字段、用兼容性规则 |

### 4. 一致性保障

Agent 任务异步、多步、可能失败重试，一致性是难点：

| 问题 | 保障手段 |
| --- | --- |
| 异步结果最终一致 | 任务状态机（pending/running/succeeded/failed）+ 结果落库 + 回调通知 |
| 重复执行 | 幂等键（任务 ID）去重，见 [[12.多用户触发同一Agent任务的幂等设计及重复执行规避]] |
| 对账 | 定时对账任务补偿丢失/重复，见 [[18.Agent任务完成率的评估方法及生产中的核心统计指标成功率、错误率等]] |
| 跨服务事务 | 用 Saga/补偿事务：Agent 步骤失败时回滚已执行的副作用 |
| 部分失败 | 工具调用失败可重试/跳过/人工干预，状态机显式记录每步状态 |

### 5. 数据格式与错误码统一

| 项 | 约定 |
| --- | --- |
| 数据格式 | 统一 JSON / Protobuf；时间用 ISO8601+UTC；金额用字符串/分 |
| 错误码 | 统一错误码体系（业务码+HTTP 状态+错误消息+traceId） |
| 错误响应 | `{code, message, traceId, data}` 统一结构，Agent 与后端共用 |
| 国际化 | 错误消息支持多语言，按 Accept-Language 返回 |

### 6. 架构图

```
   前端
    │ HTTP/SSE
   网关(Java/Go)
    │  │ ① 同步轻量请求 → 直接走后端
    │  │ ② Agent 长任务 → 投消息队列
    │  ▼
   消息队列 ──→ Agent 服务(Python)
                    │ gRPC 调后端工具
                    ▼
               后端服务(Java/Go)
                    │
              状态落库 + 结果回调
                    │
               网关 SSE 回推前端
   ── 全链路 traceId 贯穿，见 [[11.Agent执行过程的可观测性设计及全链路追踪实现]] ──
```

### 7. 一句话总结

Agent（Python）与 Java/Go 后端对接，长任务走"消息队列+异步执行+状态机+结果回调"解耦，接口稳定性靠超时/重试/熔断/降级+Schema 契约+版本兼容，一致性靠幂等+对账+Saga 补偿，数据格式与错误码统一；全链路 traceId 贯穿保障可观测。容错细节见 [[8.Agent工具调用超时的重试、熔断、降级方案及兜底回复设计]]，框架选型坑见 [[16.开源Agent框架LangChain、AutoGen、MetaGPT的生产落地坑及规避方法]]。
