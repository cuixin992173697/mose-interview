## 开源 Agent 框架 LangChain、AutoGen、MetaGPT 的生产落地坑及规避方法

> 开源 Agent 框架"跑 demo 很快，上生产很痛"。本篇按框架列常见生产坑与规避方法。框架特点对比见 agent 目录的《15.主流LLM Agent框架及各自特点》。

### 1. 为什么开源框架"能 demo，难生产"

| 阶段 | demo 阶段 | 生产阶段 |
| --- | --- | --- |
| 关注 | 跑通主链路 | 稳定/成本/可观测/容错/安全/可维护 |
| 暴露问题 | 不明显 | 版本漂移、抽象泄漏、成本失控、调试黑盒全面爆发 |

开源框架默认为"灵活与快速验证"设计，生产化需要补齐工程化外壳。

### 2. LangChain 生产坑及规避

| 生产坑 | 表现 | 规避方法 |
| --- | --- | --- |
| 版本变化快、API 频繁破坏 | 升级后 Chain/Agent 写法变了，线上报错 | 锁版本（pin 依赖）、CI 跑回归、不盲目追新 |
| AgentExecutor 废弃 | 旧 Agent 写法被标记废弃 | 迁移到 LangGraph（状态机编排），见 [[10.LangChain与LangGraph的生产选型及LangGraph状态机对复杂业务流程的适配]] |
| 抽象过重 | Runnable/Chain 嵌套深，行为难预测 | 复杂流程直接用 LangGraph 显式状态机，简单流程用 LCEL，别过度嵌套 |
| 调试难、黑盒 | 中间步骤不可见，出错难定位 | 加 Callbacks/Handler 全链路日志，见 [[11.Agent执行过程的可观测性设计及全链路追踪实现]] |
| Prompt 漂移 | 框架内置 Prompt 升级后效果变 | 关键 Prompt 自定义覆盖，不依赖框架默认 Prompt；Prompt 纳入版本管理与评测 |
| 依赖膨胀 | 装全量包体积大、冲突多 | 按需装子包（langchain-core/langchain-community 按用），容器化固定 |

### 3. AutoGen 生产坑及规避

| 生产坑 | 表现 | 规避方法 |
| --- | --- | --- |
| 多 Agent 对话易发散 | 角色互相来回扯，跑题、不收敛 | 限制最大轮次、设终止条件、用 Supervisor 模式集中裁决 |
| 成本高 | 多 Agent 多轮 = 多倍 LLM 调用 | 控制参与 Agent 数、简单步骤用小模型、缓存中间结果 |
| 状态管理弱 | 对话状态散在消息列表，难持久/恢复 | 显式外置状态（数据库/状态机），不依赖框架内存态 |
| 并发与稳定性 | 多 Agent 并发调度易出错 | 生产用 AutoGen 的可调度运行时或自建调度，加超时与重试 |
| 版本与兼容 | v0.2→v0.4 API 大改 | 锁版本，评估迁移成本再升 |

### 4. MetaGPT 生产坑及规避

| 生产坑 | 表现 | 规避方法 |
| --- | --- | --- |
| 场景偏软件工程 | 默认角色/流程围绕"软件开发"，通用业务适配难 | 非软件工程场景谨慎选，按需自定义角色与 SOP |
| 角色固定 | 内置 ProductManager/Architect/Engineer 等角色固定 | 扩展自定义角色与 Action，别硬套默认角色 |
| 中文为主、生态偏国内 | 文档与社区中文为主，国际化协作弱 | 评估团队适配度，关键链路补充英文文档 |
| 定制难 | SOP 流程深耦合框架，改流程成本高 | 把 MetaGPT 当"参考实现"，核心流程自研 + 借鉴其角色协作思想 |

### 5. 通用生产坑（不分框架）

| 通用坑 | 规避 |
| --- | --- |
| LLM 版本锁定 | Provider/模型版本写死配置，变更走评测，不在线上直接切 |
| Prompt 漂移 | Prompt 外置版本管理 + 评测集回归 |
| 成本失控 | token 预算 + 步数上限 + 缓存 + 小模型降级 |
| 可观测差 | 全链路 trace + 每步输入输出落盘 + 指标大盘，见 [[11.Agent执行过程的可观测性设计及全链路追踪实现]] |
| 容错弱 | 工具调用超时/熔断/降级，见 [[8.Agent工具调用超时的重试、熔断、降级方案及兜底回复设计]] |
| 安全风险 | 工具权限管控 + 沙箱 + 注入防范 |
| 死循环 | 最大步数 + 状态去重 + 反思修正 |

### 6. 一句话总结

开源 Agent 框架上生产的核心是"补工程化外壳"：LangChain 锁版本+迁 LangGraph+加可观测、AutoGen 限制轮次+控成本+外置状态、MetaGPT 按场景选+自定义角色；通用坑（版本锁定/Prompt 漂移/成本/可观测/容错/安全）用工程手段统一兜住。与 Java/Go 后端对接的稳定性问题见 [[17.Agent与现有后端系统Java、Go的对接及接口稳定性、一致性保障]]。
