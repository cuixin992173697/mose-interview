## Agent 用户身份的安全传递及工具调用中的权限管控

### 1. 风险

Agent 代用户执行工具（查数据/改数据/发消息），若身份传递失真或权限失控：

| 风险 | 后果 |
| --- | --- |
| 身份伪造 | 冒充他人触发 Agent |
| 身份丢失 | Agent 不知为谁执行，数据权限失效 |
| 越权工具 | 普通用户用了管理员工具 |
| 越权数据 | 看到非自己的数据 |
| 操作无审计 | 出问题无法追溯 |

### 2. 用户身份安全传递

| 环节 | 做法 |
| --- | --- |
| 接入层 | 校验 token/JWT，解析出用户身份(用户 ID/角色/租户) |
| 传递 | 身份上下文随请求透传（HTTP 头/上下文对象），全链路携带 |
| 绑定 | Agent 会话绑定用户身份，执行全程持有 |
| 防伪造 | 身份由网关签发校验，下游不信任客户端自报 |
| 防丢失 | 每次工具调用都带上身份上下文，不靠隐式状态 |

### 3. 工具调用权限管控

| 维度 | 做法 |
| --- | --- |
| RBAC 角色权限 | 用户角色 → 可调工具集白名单 |
| 工具分级 | 只读/可逆/危险，危险需审批 |
| 按身份授权 | 不同身份可用不同工具/参数范围 |
| 数据权限 | 行级控制（只能查自己的订单）、字段级脱敏 |
| 操作审计 | 每次工具调用记录 who/what/when/params/result |

权限校验管道：工具调用前过校验链（身份有效 → 角色有该工具权限 → 数据范围合法 → 危险级审批）。

### 4. 安全传递设计

```
用户请求(token) → 网关校验签发身份上下文(用户ID/角色/租户)
  → Agent 会话绑定身份
  → 每次工具调用携带身份上下文
  → 权限校验管道(身份/角色/数据/审批)
  → 通过则执行，拒绝则越权拦截 + 审计
```

工具权限分层管控详见 agent 目录的《37.Agent工具权限控制的设计及OpenClaw的工具策略管道分层》；多渠道会话隔离见 agent 目录的《36.多渠道下Agent会话隔离粒度的设计及OpenClaw的实现》。

### 5. 代码示例

```python
class IdentityContext:
    user_id: str
    role: str
    tenant_id: str

def call_tool(tool, params, identity: IdentityContext):
    # 1. 角色权限校验
    if tool.name not in ALLOWED_TOOLS[identity.role]:
        audit.log(identity, tool, "denied:role")
        raise PermissionDenied
    # 2. 数据权限（行级）
    params = apply_data_scope(params, identity)  # 注入 user_id 过滤
    # 3. 危险级审批
    if tool.risk == "dangerous" and not identity.has_approval:
        raise ApprovalRequired
    # 4. 审计
    audit.log(identity, tool, params, "allowed")
    return tool.run(params)
```

### 6. 工程要点

| 要点 | 说明 |
| --- | --- |
| 身份由网关背书 | 下游不信客户端自报身份 |
| 全程携带 | 不靠隐式/全局变量，显式传身份上下文 |
| 默认拒绝 | 权限未配置 = 不可用，而非默认开放 |
| 数据权限下沉 | 在工具/SQL 层强制注入用户范围，不靠 Agent 自觉 |
| 审计全留痕 | who/what/when/params/result 可追溯 |

沙箱与注入防范见 [[9.Agent生成SQL与代码的沙箱环境、权限隔离设计及注入攻击防范]]。

### 7. 一句话总结

Agent 身份安全 = 网关校验签发身份上下文 → 随 Agent 执行全程显式透传 → 每次工具调用过权限校验管道（RBAC 角色 + 工具分级 + 数据行级 + 危险审批 + 审计），默认拒绝、数据权限下沉，工具权限分层见 agent 目录《37》《36》。
