## 多用户触发同一 Agent 任务的幂等设计及重复执行规避

### 1. 为什么 Agent 任务要幂等

Agent 工具调用常有副作用（发邮件/写库/扣款/调外部 API），重复执行会重复副作用：

| 重复触发来源 | 后果 |
| --- | --- |
| 多用户同时触发同一任务 | 重复发邮件/重复扣款 |
| 用户重复点击 | 重复执行 |
| 网络重试 | 重复写库 |
| 上游重试/补偿 | 重复操作 |
| Agent 自身重试工具 | 重复副作用 |

### 2. 幂等设计核心

| 手段 | 说明 |
| --- | --- |
| 任务 ID/幂等键 | 客户端生成唯一 request_id，服务端据此去重 |
| 去重表 | 已处理 request_id 入表，重复请求直接返回缓存结果 |
| 结果缓存 | 首次执行结果缓存，重复请求命中返回 |
| 状态机校验 | 任务有状态(待执行/执行中/完成/失败)，重复请求按状态返回 |
| 分布式锁 | 同一幂等键加锁，防并发重复执行 |

> 幂等键设计：用业务语义级（如"用户 X 对订单 Y 执行退款"hash 为 key），而非纯随机 ID，才能真正识别"同一副作用任务"。

### 3. 重复执行规避（前后端配合）

| 层 | 手段 |
| --- | --- |
| 前端 | 按钮防抖/提交后禁用/loading 锁/禁止重复提交 |
| 网关 | request_id 去重 + 限流 |
| 后端 | 幂等键去重表 + 状态机 + 分布式锁 |
| 工具层 | 工具调用本身幂等（如带 operation_id 的扣款接口） |

### 4. 与并发调度配合

高并发下多个相同任务请求到达，先去重再调度：

```
请求到达 → 提取幂等键 → 查去重表
  ├─ 已存在且完成   → 返回缓存结果
  ├─ 已存在且执行中 → 返回"执行中"或等待
  └─ 不存在         → 加锁 → 入去重表(执行中) → 入调度队列 → 执行 → 更新结果 → 释放锁
```

并发调度详见 [[7.高并发场景下Agent任务的排队、限流、优先级调度实现]]。

### 5. 代码示例

```python
def execute_agent_task(request_id, task_spec):
    # 1. 幂等检查
    cached = idempotency_store.get(request_id)
    if cached:
        return cached  # 已执行过，返回缓存
    # 2. 加分布式锁防并发
    lock = acquire_lock(f"agent:{request_id}", ttl=300)
    if not lock:
        return get_existing_result(request_id)  # 别的实例在执行
    try:
        # 3. 状态机校验
        if get_task_state(request_id) == "done":
            return get_result(request_id)
        mark_running(request_id)
        result = agent.run(task_spec)
        mark_done(request_id, result)
        idempotency_store.set(request_id, result, ttl=3600)
        return result
    finally:
        release_lock(lock)
```

### 6. 工程要点

| 要点 | 说明 |
| --- | --- |
| 幂等键语义化 | 用业务语义 hash，而非纯随机 ID，防不同请求撞同一副作用 |
| 去重表 TTL | 设合理过期，避免无限膨胀 |
| 锁与超时 | 分布式锁带 TTL 防死锁 |
| 工具自身幂等 | 优先让下游工具幂等（带 operation_id），双保险 |
| 异常处理 | 执行失败要清理"执行中"状态，允许重试 |

更底层的 Gateway 幂等处理见 agent 目录的《44.Agent系统幂等性的必要性及OpenClaw的Gateway幂等性处理方案》。

### 7. 一句话总结

Agent 任务幂等 = 用幂等键 + 去重表 + 状态机 + 分布式锁，让重复触发（多用户/重试/重点击）不重复执行副作用，配合前端防抖与工具自身幂等双保险，并发场景下先去重再调度（见 [[7.高并发场景下Agent任务的排队、限流、优先级调度实现]]）。
